# THE ENGINE ROOM

## Book 6, Part 3: पूल: एकाच वेळी अनेक कामं

**मागच्या भागाचा शेवट:** GIL "race टाळायला" होता: म्हणजे
अनेक threads एकाच गोष्टीला हात घातले तर गोंधळ. हा भाग तो
गोंधळ (concurrency) आणि तो सांभाळायच्या युक्त्या शिकवतो:
locks, deadlock, GPU vs CPU, आणि distributed चा पाया (Book
5 शी पूल). आणि शेवटी: **चंदूच्या केसचा निकाल** (सगळे संशयित
एकत्र), आणि AI-युगात हे सगळं का उरतं.

## सूत्र (शेवटच्या भागासाठी)

```
प्रत्येक हुशारी ही वेळ आणि जागा (memory) यांची अदलाबदल आहे.
Part 3 चा भर: अनेक कामं एकत्र = वेग विकत, गोंधळ (आणि तो
सांभाळायची मेहनत) विकून.
```

## Part 2 ची उजळणी: 3 प्रश्न (बोलून; उत्तरं खाली)

**1.** वेगवान CPU = वेगवान app का नाही?

> CPU बहुधा आकड्यांची वाट बघतो; cache/memory बघा,
> GHz नाही. (2.1, 2.2)

**2.** RAM-disk फरक आणि धडा?

> ~1000 पट; वारंवारचं जवळ ठेवा (cache), शेजारी-आकडे जलद. (2.2)

**3.** Python AI त कसं (हळू असूनही)?

> वरचा सोपा Python-थर + खालचा वेगवान C/GPU थर. (2.5)

## या भागात काय

Race conditions (यंत्राच्या तळाशी), locks + deadlock, parallel
vs concurrent, GPU vs CPU थेट भिडत, distributed चा पाया,
चंदूच्या केसचा निकाल, AI-युगात CS का उरतं, आणि अंतिम परीक्षा
+ latency/complexity पट्ट्या. Book 6, आणि मालिका, इथे संपते.
