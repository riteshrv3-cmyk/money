# Chapter 2.3 [SPINE]: Process, Thread, आणि एका CPU वर हजार कामं

चंदूचा प्रश्न: एकच CPU, तरी दहा apps एकत्र कसे? उत्तर दोन
कल्पनांत (process, thread) आणि एका सुंदर भ्रमात (आळीपाळी).

**Process: प्रत्येक app चं स्वतंत्र घर.** चालू असलेलं प्रत्येक
app म्हणजे एक **process**: त्याला स्वतःची memory-जागा, स्वतःची
संसाधनं, इतरांपासून **वेगळी** (एक app कोसळलं तरी दुसरं
सुरक्षित: Book 5 चं isolation, इथे OS-पातळीवर). वेगवेगळ्या
कुटुंबांची वेगवेगळी घरं: एकाच्या घरातला गोंधळ दुसऱ्याला लागत
नाही. WhatsApp एक process, गाणी दुसरं, चंदूचं app तिसरं.

**Thread: एका घरातले अनेक हात.** एका process (app) च्या
आत अनेक **threads** असू शकतात: एकाच घरातले अनेक माणसं,
**सामायिक** memory (एकच स्वयंपाकघर) वापरणारे. उदा: चंदूच्या
app मध्ये एक thread गिऱ्हाईकाची विनंती हाताळतो, दुसरा
background मध्ये data जतन करतो: एकाच वेळी. Threads सामायिक
memory वापरतात म्हणून **जलद संवाद** (एकाच घरात), पण
**धोका**: दोघांनी एकाच वेळी एकाच गोष्टीला हात घातला तर गोंधळ
(Book 5 चा race condition, 2.4: इथे परत येणार, Part 3).

**आणि आता तो सुंदर भ्रम: आळीपाळी (एका CPU वर "एकत्र").**
एक CPU एका वेळी खरंच **एकच** सूचना करतो (2.1). मग दहा
apps "एकत्र" कसे? युक्ती: CPU **अति-वेगात आळीपाळी** करतो:
WhatsApp ला काही millisecond, मग चंदूच्या app ला, मग गाण्याला,
मग परत WhatsApp... इतक्या वेगात की **तुम्हाला वाटतं सगळे
एकत्र चालतायत** (प्रत्यक्षात एकावेळी एकच, पण अदलाबदल इतकी
जलद की डोळा फसतो). चित्रपटाची उपमा: पडद्यावर वेगळी-वेगळी
स्थिरचित्रं, पण सेकंदाला 24 वेळा बदलली की "हालचाल" दिसते.
CPU-आळीपाळी तेच: **भ्रम, पण उपयोगी भ्रम.** (खऱ्या multi-core
chips मध्ये अनेक CPU असतात, म्हणून **खरोखर** काही एकत्र:
पण तत्त्व तेच, फक्त काही समांतर.)

**चंदूच्या प्रश्नाचं उत्तर: हो, दुसरं app तुमचं हळू करू शकतं.**
कारण CPU आळीपाळीने वाटलेला: जर दुसरं app भरपूर CPU खात
असेल, तर चंदूच्या app ला कमी वेळ मिळतो, ते हळू. एकाच रांगेत
अनेक गिऱ्हाईक: प्रत्येकाला थोडा-थोडा वेळ, गर्दी वाढली की
प्रत्येकाची वाट लांब. **म्हणून app चा वेग फक्त त्याच्या code
वर नाही, यंत्रावरच्या एकूण गर्दीवरही अवलंबून.**

## इथे लोक काय चुकीचं समजतात

"माझं app एकटंच चालतंय असं समजून बांधतो." यंत्रावर नेहमी
डझनभर processes स्पर्धा करत असतात: तुमचं app त्यातलं एक.
आणि "threads = आपोआप वेगवान" हा गैरसमज: threads जोडले
की सामायिक-memory चे race conditions (Part 3) येतात, आणि
एका CPU वर threads खरं समांतर चालत नाहीत (आळीपाळीच).
Threads शक्तिशाली पण धोकादायक: त्यांची पूर्ण गुंतागुंत Part 3.

## नकाशावर

```
2.1-2.2  CPU | latency-पट्टी
2.3  process (app चं स्वतंत्र घर, isolated) vs thread (घरातले
     अनेक हात, सामायिक memory); एका CPU वर आळीपाळी = "एकत्र"
     चा उपयोगी भ्रम; दुसरं app तुमचं हळू करू शकतं
```

**सूत्रावर:** process/thread दाखवतात की "एकत्र चालणं" हा
आळीपाळीचा भ्रम आहे: एक संसाधन (CPU) अनेकांत वाटलेलं.
आणि वाटप म्हणजे सौदा: प्रत्येकाला थोडं, कुणालाच सगळं नाही.

## स्वतः बघा (5 मिनिटं)

फोनमध्ये "recent apps" उघडा: डझनभर apps "चालू" दिसतात.
खरंच सगळे एकाच क्षणी चालत नाहीत; CPU त्यांच्यात अति-वेगात
आळीपाळी करतो (+ काही खरोखर समांतर, multi-core मुळे). आणि
एखादं जड app (गेम) चालू केलं की बाकी हळू होतात/थांबतात:
कारण ते जास्त CPU खातं. तुम्ही रोज CPU-वाटप अनुभवता.

## विचार करा

चंदूला आळीपाळी कळली, पण नवा प्रश्न: "CPU आळीपाळी करतो,
ठीक. पण **कोण ठरवतं** कुणाला किती वेळ, कधी? माझं महत्त्वाचं
app आणि एखादं किरकोळ background-काम: दोघांना सारखाच वेळ
मिळतो का? कोणीतरी हुशारीने वाटप करत असणार."

> ठरवणारा): एक अदृश्य मुकादम जो कुणाला कधी CPU द्यायचा
> हे क्षणाक्षणाला ठरवतो. त्याची कला: पुढचा chapter.
