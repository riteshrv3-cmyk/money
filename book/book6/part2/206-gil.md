# Chapter 2.6 [DEPTH]: GIL आणि त्याचा 2026 चा (अर्धा) मृत्यू [ताजा]

चंदूचा प्रश्न: Python एका वेळी एकच thread? 2026 मध्ये बदललं?
हा chapter एका गाजलेल्या मर्यादेचा, आणि तिच्या चालू-असलेल्या
मृत्यूचा (ताजा, Aug 2026). [DEPTH]: थोडं तांत्रिक, पण 2026
चा जिवंत मुद्दा.

**GIL म्हणजे काय.** Python (मुख्य आवृत्ती) मध्ये एक "मोठं
कुलूप" आहे: **GIL** (Global Interpreter Lock). नियम: **एका
वेळी फक्त एकच thread** Python-code चालवू शकतो (कुलूप
ज्याच्याकडे तोच). म्हणजे तुमच्याकडे 8-core CPU असला (8 खरे
समांतर हात), तरी Python-code साठी **एकच हात** वापरला जातो,
बाकी 7 रिकामे! एका मोठ्या स्वयंपाकघरात 8 आचारी, पण नियम
"एका वेळी एकच शिजवू शकतो": 7 बसून. Threads जोडूनही Python-
गणित समांतर होत नाही (आळीपाळीच, 2.3): हीच GIL ची मर्यादा.

**GIL का ठेवला (कारण समजा, नाहीतर तो मूर्खपणा वाटेल):**
GIL ने Python **सोपं आणि सुरक्षित** ठेवलं: एका-वेळी-एकच
म्हणजे race conditions (Book 5, 2.4) चा धोका कमी, आणि
Python चं आतलं memory-व्यवस्थापन सोपं. म्हणजे GIL = **सुरक्षा
+ साधेपणा विकत, multi-core समांतरता विकून** (सूत्र पुन्हा!).
दोन दशकं हा सौदा बहुतेकांना परवडला (कारण बहुतेक apps ला
पूर्ण multi-core लागत नव्हतं, आणि जड काम C-थराला (2.5) जायचं
जे GIL सोडतं). पण AI-युगात, जिथे प्रचंड समांतर गणित लागतं,
GIL अडथळा ठरू लागला.

**2026 चा (अर्धा) मृत्यू: free-threaded Python (ताजी स्थिति).**
अनेक वर्षांच्या कामानंतर, Python ने GIL **काढायचा** निर्णय
घेतला (PEP 703). टप्पे (तपासलेले): Python 3.13 (Oct 2024)
ने GIL-शिवाय आवृत्ती **प्रयोगिक** म्हणून दिली; Python 3.14
(Oct 2025) ने ती **अधिकृतपणे समर्थित** केली: पण **वेगळी
आवृत्ती** म्हणून (डिफॉल्ट नाही). म्हणजे Aug 2026 पर्यंत: GIL-
शिवाय Python **उपलब्ध आणि अधिकृत**, पण अजून **डिफॉल्ट
नाही**; बहुतेक जग अजून GIL-वालं Python वापरतं, आणि GIL-
शिवाय आवृत्तीत एकट्या-thread चं काम ~5-10% हळू (एक किंमत).
म्हणून "अर्धा मृत्यू": दार उघडलं, पण सगळे अजून आतच गेलेले
नाहीत. **पुढच्या काही वर्षांत हे बदलत जाईल**: तुम्ही या
संक्रमणाच्या मध्यावर आहात.

**चंदूसाठी (आणि तुमच्यासाठी) धडा:** (1) आजही, Python मध्ये
खरं समांतर गणित हवं तर बहुधा **अनेक processes** (2.3: वेगळी
घरं, वेगळे GIL) वापरतात, threads नाही: ही जुनी युक्ती अजून
चालते. (2) किंवा जड काम C/GPU-थराला सोपवा (2.5: तो GIL
सोडतो). (3) आणि नवं free-threaded Python येतंय हे लक्षात
ठेवा: पुढे threads खरं समांतर होतील. **एक भाषा-वैशिष्ट्य
(GIL) कसं जन्मलं (सुरक्षा-सौदा), का अडथळा झालं (AI-समांतरता),
आणि कसं बदलतंय (free-threading): हे बघणं म्हणजे tech
जिवंत, बदलणारं आहे हे समजणं.** कुठलाही "नियम" कायमचा
नाही; प्रत्येक सौदा काळानुसार पुन्हा तपासला जातो.

## इथे लोक काय चुकीचं समजतात

"GIL म्हणजे Python मूर्खपणे बांधलं." GIL एक **जाणीवपूर्वक
सौदा** होता (सुरक्षा+साधेपणा), मूर्खपणा नाही: दोन दशकं त्याने
Python सोपं-सुरक्षित ठेवलं. आणि उलट (2026 चा नवा गैरसमज):
"GIL गेला, आता Python सगळीकडे समांतर!" अजून नाही: free-
threaded आवृत्ती उपलब्ध पण डिफॉल्ट नाही, आणि एकट्या-thread
ला थोडी हळू. संक्रमण चालू आहे, पूर्ण नाही. "बदल जाहीर झाला"
आणि "बदल सर्वत्र पोहोचला" यांत वर्षं असतात: tech मध्ये नेहमी.

## नकाशावर

```
2.1-2.5  CPU | latency | process/thread | OS | Python
2.6  GIL = एका वेळी एकच Python-thread (सुरक्षा+साधेपणा विकत,
     multi-core समांतरता विकून); 2026: free-threaded Python
     अधिकृत पण डिफॉल्ट नाही (अर्धा मृत्यू); समांतरतेला अनेक
     processes/C-थर
```

**सूत्रावर:** GIL हा सूत्राचं जिवंत उदाहरण: सुरक्षा-साधेपणा
विकत घ्यायला समांतरता विकली; आणि जेव्हा समांतरतेची किंमत
(AI-युग) वाढली, तेव्हा सौदा पुन्हा तपासला जातोय. कुठलाही
सौदा कायमचा बरोबर नसतो: काळ बदलला की तोही बदलतो.
