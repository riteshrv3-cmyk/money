# Chapter 2.5 [SPINE]: तुझं Code ते यंत्राचे 0/1: Python हळू का

चंदूचा प्रश्न: Python code आणि CPU चे 0/1 यांच्यात काय, आणि
Python हळू का? हा chapter तुमच्या रोजच्या code ला यंत्राच्या
तळाशी जोडतो, आणि एक व्यावहारिक सत्य उघडतो.

**दोन जगांमधली दरी.** तुम्ही लिहिता: `total = price + tax`
(माणसाला वाचता येणारं). CPU समजतो: फक्त 0/1 च्या ठरलेल्या
सूचना (2.1). मध्ये **भाषांतर** लागतं: तुमच्या code चं CPU-च्या-
0/1 मध्ये. आणि हे भाषांतर **कधी** होतं यावर दोन जगं:

**वाट 1: Compiler (आधीच भाषांतर): C, Rust, Go.** compiler
तुमचं **पूर्ण** code आधीच, एकदाच, CPU-च्या-0/1 मध्ये भाषांतरित
करतो (एक तयार file). मग ती file थेट CPU वर धावते: **वेगवान**
(भाषांतर आधीच झालंय). पुस्तक आधीच पूर्ण अनुवादित करून
छापण्यासारखं: वाचकाला पटकन. तोटा: बदल केला की पुन्हा पूर्ण
भाषांतर (compile), आणि लिहिणं थोडं कडक.

**वाट 2: Interpreter (चालता-चालता भाषांतर): Python.** interpreter
तुमचं code **ओळ-ओळ, चालतानाच** भाषांतरित करतो. दुभाष्याची
उपमा: भाषण चालू असताना, वाक्य-वाक्य अनुवाद. फायदा: लिहिणं-
बदलणं **सोपं, लवचिक** (आधी compile नको, लगेच चालवा).
तोटा: **हळू**: कारण प्रत्येक ओळ **प्रत्येक वेळी** भाषांतरित
(आणि loop मध्ये तीच ओळ हजार वेळा = हजार वेळा भाषांतर!).
म्हणून Python हे C पेक्षा शुद्ध-गणितात ~10-100 पट हळू असू
शकतं.

**मग Python इतकं लोकप्रिय का (जर हळू)?** इथे Book 5 चा
सौदा परत: **Python माणसाचा वेळ वाचवतं, यंत्राचा खर्चतं.**
लिहायला सोपं-जलद, शिकायला सोपं, कमी code: म्हणजे **माणूस
वेगवान** (जो महाग आहे), यंत्र हळू (जे स्वस्त होत चाललंय). आणि
गुपित: **खरं जड गणित Python स्वतः करत नाही**: ते खाली C-
मध्ये-लिहिलेल्या वेगवान library ला (NumPy, आणि AI मधलं सगळं!)
सोपवतं. Python फक्त "मुकादम" (काय करायचं ठरवणारा, सोपा),
खरं काम खालचा वेगवान C-थर करतो. **म्हणून AI Python मध्ये
लिहिलं जातं पण हळू नसतं**: वरचा सोपा थर Python, खालचा
वेगवान थर C/GPU. दोन्ही जगांचं उत्तम.

**चंदूसाठी थेट धडा:** "Python हळू" म्हणून घाबरू नका: बहुतेक
apps ला Python चा वेग पुरतो (आणि माणसाचा वेळ वाचतो).
पण जिथे **खरंच** जड गणित (लाखो आकडे कुरतडणं) तिथे ते
वेगवान library ला (जे आत C आहे) सोपवा, स्वतः Python-loop
मध्ये करू नका. **"सोपं लिहा (Python), जड काम वेगवान थराला
सोपवा"**: हाच 2026 चा व्यावहारिक नियम, आणि Book 4 चं "code
agents लिहितात" युगातही तोच.

## इथे लोक काय चुकीचं समजतात

"Python हळू आहे, म्हणून गंभीर काम त्यात करू नये." चूक:
जगातलं जवळजवळ सगळं AI Python मध्ये लिहिलं जातं! रहस्य:
Python वरचा-सोपा-थर, खालचं जड काम वेगवान C/GPU थराला.
"Python हळू" हे फक्त **शुद्ध Python-loop मध्ये जड गणित**
केल्यास खरं; योग्य वापरात (मुकादम Python + मजूर C-library)
ते वेगवान **आणि** सोपं. उलट गैरसमज: "सगळं C मध्ये लिहा,
वेगवान." C लिहायला-सांभाळायला महाग (माणसाचा वेळ): बहुतेक
कामाला ती किंमत परवडत नाही. वेग हवा तिथे C, सोपेपणा हवा
तिथे Python: सौदा बघा.

## नकाशावर

```
2.1-2.4  CPU | latency | process/thread | OS
2.5  code -> 0/1 भाषांतर: compiler (आधीच, वेगवान: C) vs
     interpreter (चालता-चालता, लवचिक-हळू: Python); Python =
     माणसाचा वेळ वाचवतो; जड काम खालच्या C/GPU थराला सोपवा
```

**सूत्रावर:** compiler-vs-interpreter हा सौदा "माणसाचा वेळ की
यंत्राचा वेळ": Python माणसाचा वाचवतं (यंत्राचा खर्चून), C उलट.
आणि AI ची युक्ती दोन्ही जिंकते: सोपा वरचा थर + वेगवान खालचा.

## स्वतः बघा (5 मिनिटं)

दुभाष्याचा (interpreter) आणि आधीच-अनुवादित-पुस्तकाचा (compiler)
फरक आठवा: थेट भाषणात दुभाष्या लवचिक (कुठलंही वाक्य लगेच),
पण हळू (प्रत्येक वाक्य तिथल्या तिथे); अनुवादित पुस्तक जलद
वाचता येतं पण आधी सगळं अनुवादावं लागलं. Python दुभाष्या,
C अनुवादित-पुस्तक. दोन्हींची जागा वेगळी: तुमच्या गरजेने निवडा.
