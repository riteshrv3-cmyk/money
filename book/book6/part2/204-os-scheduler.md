# Chapter 2.4 [SPINE]: OS: अदृश्य मुकादम आणि Virtual Memory

चंदूचा प्रश्न: वाटप कोण ठरवतं? उत्तर: **operating system (OS)**:
यंत्रावरचा अदृश्य मुकादम. हा chapter OS ची दोन मुख्य जादू
दाखवतो: वेळ-वाटप (scheduler) आणि जागा-भ्रम (virtual memory).

**OS म्हणजे काय.** तुमचं app आणि हार्डवेअर यांच्यामधला
**व्यवस्थापक** (Windows, Android, Linux). Apps थेट हार्डवेअरला
हात लावत नाहीत; ते OS ला "मला CPU हवा", "हा data disk वर
लिही" म्हणून **विनंती** करतात, आणि OS ठरवतो कोणाला काय-
कधी. मोठ्या हॉटेलचा manager: गिऱ्हाईक (apps) थेट स्वयंपाकघरात
(hardware) जात नाहीत; manager सगळं वाटतो, रांगा सांभाळतो,
भांडणं टाळतो.

**जादू 1: Scheduler (वेळ-वाटप).** शेकडो threads CPU मागतात;
scheduler क्षणाक्षणाला ठरवतो कुणाला द्यायचं. नियम गुंतागुंतीचे,
पण तत्त्व: (1) **महत्त्वाला आधी** (तुमचा स्पर्श हाताळणारं thread
background-कामापेक्षा आधी: म्हणून फोन "प्रतिसादशील" वाटतो);
(2) **कुणी उपाशी राहू नये** (प्रत्येकाला थोडा-थोडा वेळ, नाहीतर
एखादं app कायमचं अडकेल); (3) **वाट बघणाऱ्याला बाजूला ठेवा**
(जर एखादं app disk-data ची वाट बघतंय (2.2: दिवस!), तर
त्याला CPU देऊन उपयोग नाही: दुसऱ्याला द्या, हे परत आलं की
बघू). हा शेवटचा नियम महत्त्वाचा: **OS वाट-बघणाऱ्यांना बाजूला
ठेवून CPU व्यस्त ठेवतो**: म्हणून एक app disk ची वाट बघत
असताना तुमचं दुसरं काम थांबत नाही.

**जादू 2: Virtual Memory (जागेचा उपयोगी भ्रम).** प्रत्येक app
ला वाटतं त्याच्याकडे **अख्खी, स्वतःची, अखंड** memory आहे:
पण हा भ्रम आहे. प्रत्यक्षात OS खऱ्या RAM चे तुकडे वेगवेगळ्या
apps ना वाटतो, आणि प्रत्येकाला "तुझ्याकडे सगळं आहे" असं
भासवतो (virtual = आभासी). फायदे: (1) apps एकमेकांच्या memory
ला हात लावू शकत नाहीत (सुरक्षा, isolation); (2) RAM कमी
पडली तर OS कमी-वापरलेले तुकडे **disk वर** ढकलतो (swap)
आणि "अजून जागा आहे" भासवतो. पण इथे सापळा: जर app disk-
वर-ढकललेली memory सारखी मागू लागलं, तर प्रत्येक मागणीला
disk-फेरी (2.2: ~दिवस!): app भयंकर हळू (याला "thrashing"
म्हणतात). **RAM संपली की app disk-वेगाने रांगतं:** चंदूच्या
app च्या अधूनमधून-हळूपणाचा एक संभाव्य संशयित.

**चंदूच्या केसला हातभार:** आता चंदूला दिसतं की त्याच्या app
चा वेग तीन गोष्टींवर: (1) त्याचं algorithm (Part 1), (2) आकडे
जवळ की दूर (2.2 cache), आणि (3) OS कडून किती CPU-वेळ
आणि RAM मिळतो (गर्दी, virtual memory). तिन्ही तपासल्याशिवाय
"app हळू का" चं पूर्ण उत्तर नाही. गुप्तहेराची नजर आता पूर्ण
यंत्रावर.

## इथे लोक काय चुकीचं समजतात

"माझ्या app कडे अख्खी memory आहे." भ्रम: OS ने भासवलेला.
प्रत्यक्षात RAM वाटलेली, आणि संपली तर disk वर ढकलली जाते
(हळू). "माझं app नीट चालतंय पण अधूनमधून अडतं" चं कारण
अनेकदा हेच: RAM कमी, swap सुरू, disk-वेग. आणि दुसरा:
"OS म्हणजे फक्त desktop चं चित्र (icons)." ते फक्त वरचं तोंड;
खरा OS हा अदृश्य मुकादम आहे जो प्रत्येक क्षणी CPU-memory-
disk वाटतो. तो न दिसणं म्हणजे तो चांगला काम करतोय.

## नकाशावर

```
2.1-2.3  CPU | latency | process/thread
2.4  OS = अदृश्य मुकादम; scheduler (महत्त्वाला आधी, वाट-
     बघणाऱ्याला बाजूला); virtual memory (प्रत्येकाला "सगळं"
     चा भ्रम; RAM संपली -> swap -> disk-वेगाने रांगणं)
```

**सूत्रावर:** OS दाखवतो की "सगळ्यांना सगळं" हा भ्रम रचनेने
सांभाळला जातो: वेळ आणि जागा दोन्ही वाटलेली, प्रत्येकाला
"पूर्ण" भासवत. आणि भ्रम तुटतो (RAM संपली) तेव्हा सूत्राची
किंमत दिसते: दूरची (disk) जागा वापरावी लागते, हळू.

## स्वतः बघा (5 मिनिटं)

फोन/computer मध्ये खूप apps उघडा: एका क्षणी तो हळू होतो
(RAM संपली, swap सुरू). काही बंद करा: पुन्हा जलद. तुम्ही
virtual-memory ची सीमा अनुभवली. आणि task-manager (असेल
तर) उघडून बघा: कुठलं app किती CPU/memory खातंय: OS चा
वाटप-हिशेब तुमच्या डोळ्यांसमोर.
