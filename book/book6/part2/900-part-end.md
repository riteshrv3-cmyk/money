## स्वतःची परीक्षा (4 प्रश्न, बोलून; उत्तरं खाली)

**1.** वेगवान CPU (जास्त GHz) = वेगवान app का नाही?

> CPU बहुधा आकड्यांची वाट बघत बसतो; अडचण "आकडे दूर"
> असेल तर वेगवान CPU फक्त जास्त वेगात वाट बघतो. cache/
> memory बघा. (2.1, 2.2)

**2.** RAM आणि disk मध्ये किती फरक, आणि त्याचा code-धडा?

> ~1000 पट (RAM 100ns, SSD ~दिवस-CPU-दृष्टीने); धडा:
> वारंवारचं जवळ ठेवा (cache); शेजारी-आकडे (array) जलद. (2.2)

**3.** Python "हळू" तरी AI त वापरतात: कसं?

> Python वरचा-सोपा-मुकादम-थर; जड गणित खालच्या वेगवान
> C/GPU थराला (NumPy वगैरे) सोपवलं जातं. सोपेपणा + वेग दोन्ही. (2.5)

**4.** GIL काय, आणि 2026 ची स्थिती?

> एका वेळी एकच Python-thread (सुरक्षा-सौदा). 2026: free-
> threaded Python अधिकृत पण डिफॉल्ट नाही; संक्रमण चालू,
> अर्धा मृत्यू. (2.6)

## पुढच्या भागाची चाहूल

GIL "race टाळायला" होता: म्हणजे अनेक threads एकाच गोष्टीला
हात घातले तर गोंधळ. Part 3: पूल: concurrency चा गोंधळ आणि
तो सांभाळायच्या युक्त्या (locks, deadlock), GPU vs CPU, distributed
चा पाया (Book 5 शी पूल), आणि चंदूच्या केसचा **निकाल.**

## BOOK 6, PART 2 चा MINI-GLOSSARY

```
cache            CPU जवळची जलद memory; वारंवारचं ठेवते (2.2)
compiler         पूर्ण code आधीच 0/1 मध्ये (वेगवान: C) (2.5)
CPU              transistor-स्विचांचा मेंदू; ठोक्यावर एक सूचना (2.1)
GIL              एका वेळी एकच Python-thread चं कुलूप (2.6)
interpreter      code ओळ-ओळ चालता-चालता (लवचिक: Python) (2.5)
latency          एका कृतीला लागणारा वेळ; जवळ<->दूर (2.2)
OS               hardware-app मधला मुकादम-व्यवस्थापक (2.4)
process          app चं स्वतंत्र, isolated घर (2.3)
scheduler        कुणाला कधी CPU द्यायचं ठरवणारा (2.4)
thread           process मधला हात; सामायिक memory (2.3)
transistor       चिमुकला विजेचा स्विच (0/1); CPU चा पाया (2.1)
virtual memory   प्रत्येक app ला "पूर्ण memory" चा भ्रम (2.4)
```
