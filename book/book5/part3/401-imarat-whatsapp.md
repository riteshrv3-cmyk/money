# Chapter 4.1 [SPINE]: इमारत: WhatsApp: 50 माणसं, 90 कोटी लोक

पहिली इमारत, आणि सर्वात थक्क करणारी. 2015 त WhatsApp
**~90 कोटी** (900 million) लोकांना real-time chat देत होतं,
अब्जावधी messages रोज: आणि engineering-टीम **~50 माणसं.**
(2014 त Facebook ने ~$19 अब्जांना विकत घेतलं तेव्हा एकूण
~55 कर्मचारी, ~45 कोटी users: आकडे तपासलेले.) हे कसं?
उत्तर पूर्ण पुस्तकाचं सार आहे.

**रहस्य 1: कट्टर सोपेपणा (feature नकार).** WhatsApp ने जे
**केलं नाही** ते जास्त महत्त्वाचं: जाहिराती नाहीत, games नाहीत,
फालतू features नाहीत, रंगीबेरंगी गुंतागुंत नाही. फक्त: संदेश
पोहोचवा, विश्वासाने, जलद. एक काम, कट्टरपणे. कमी features =
कमी code = कमी bugs = कमी माणसं. Book 4, 9.3 चा "एकट्याचा
कारखाना" इथे 50-लोकांचा: **सोपेपणा हाच सर्वात मोठा scaling-
मंत्र.**

**रहस्य 2: योग्य हत्यार (Erlang).** त्यांनी एक खास भाषा वापरली
(Erlang): जी **लाखो सतत-दुवे** (2.8 चे WebSocket-सारखे)
सांभाळण्यासाठीच दशकांपूर्वी (टेलिफोन-यंत्रणांसाठी) बनली होती.
एका server वर ~20 लाख जोडण्या. योग्य कामाला योग्य हत्यार:
"cool" भाषा नाही, **या** कामाला बनलेली भाषा (2.2 चा "fashion
नको, सौदा बघा" इथे भाषेच्या निवडीत).

**रहस्य 3: नकाशा उलगडून (Part 1-2 चे सौदे).** WhatsApp
मध्ये तुम्हाला दिसेल: (1) messages **कायमचे साठवत नाहीत**
(पोहोचले की server वरून पुसतात): storage स्वस्त, गुंतागुंत
कमी: एक धाडसी सौदा (2.1 चा data-model, टोकाला नेलेला).
(2) real-time साठी सतत-दुवे (2.8). (3) प्रचंड-वेगवान, सैल
लेखनासाठी योग्य database (LSM-कुळ, 2.3). प्रत्येक निर्णय
"या कामाला काय लागतं" वर, "काय भारी दिसतं" वर नाही.

**समान धागा (पूर्ण पुस्तकाचा):** WhatsApp ने कुठलीही "जादूई
भारी रचना" वापरली नाही. त्यांनी **एक काम निवडलं, ते कट्टर
सोपेपणाने केलं, योग्य हत्यार वापरलं, आणि प्रत्येक सौदा जाणून
केला.** म्हणून 50 माणसं 90 कोटींना पुरली. हा तुमच्यासाठी
(आणि आरतीसाठी) सर्वात मोठा दिलासा: **मोठेपणाला प्रचंड टीम/
पैसा/गुंतागुंत लागत नाही; सोपेपणा आणि योग्य निवडी लागतात.**
Book 4 चं leverage-सूत्र (9.3) इथे 2015 तच खरं ठरलं होतं.

## महाग चूक

"मोठं app म्हणजे भरपूर features, भरपूर माणसं, भरपूर गुंतागुंत."
WhatsApp हे उलट सिद्ध करतं: **features वाढवणं सोपं, नाकारणं
अवघड**: आणि नाकारण्यातच खरी शिस्त. प्रत्येक जोडलेलं feature =
जास्त code + bugs + माणसं + गुंतागुंत (Book 4, 4.2/4.4 चा
"किती tools" तोच धडा). यशस्वी होण्यासाठी जास्त करावं लागतं
हा भ्रम; बहुधा **कमी, पण उत्तम** करावं लागतं. "काय करू"
पेक्षा "काय करू नको" हा कठीण आणि किमती प्रश्न.

थोड्या माणसांत पेलला. सोपेपणा हा सर्वात कमी लेखलेला
superpower.

## स्वतः बघा (5 मिनिटं)

WhatsApp उघडा आणि मोजा: त्यात किती "features" आहेत?
मुख्य: संदेश, call, status. संपलं जवळपास. आता एखादं गचडलेलं
app आठवा (डझनभर features, गोंधळ). कुठलं तुम्ही रोज वापरता,
कुठलं टिकलं? सोपेपणाची ताकद तुमच्या स्वतःच्या फोनवर दिसते.
