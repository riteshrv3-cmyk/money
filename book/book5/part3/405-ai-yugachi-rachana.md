# Chapter 4.5 [SPINE]: AI-युगाची रचना: नजर हीच leverage

आरतीचा अस्वस्थ प्रश्न: agents code लिहितात, मग हे शिकण्याचा
उपयोग काय? हा chapter त्याचं उत्तर आहे, आणि तो Book 4
शी थेट पूल बांधतो. उत्तर एका ओळीत: **code लिहिणं स्वस्त
झालं; रचना बरोबर आहे का ठरवणारी नजर महाग राहिली: आणि
तीच आता तुमची सर्वात मोठी संपत्ती.**

**काय बदललं, काय नाही.** Book 4 (9.2-9.3) चा leverage-
सरकण्याचा धडा इथे software-रचनेत उतरतो. बदललं: **code
टाइप करणं** (agents करतात, जलद-स्वस्त). **नाही** बदललं:
"कुठली रचना, कुठला सौदा, कुठली database, हे बरोबर आहे का"
हा निर्णय. आठवा (2.10): top engineer ची अर्धी किंमत नवं
बांधण्यात, अर्धी **रचना वाचून सौदे-धोके ओळखण्यात.** आता
बांधणं agent करतो; म्हणून **वाचणारी-ठरवणारी नजर** ही उरलेली,
आणि म्हणून सर्वात मौल्यवान. Code = कच्चा माल (स्वस्त); नजर =
मूल्य (Book 4, 9.1 चा थर 5-6).

**agent-सोबत बांधण्याची नवी शिस्त (Book 4 + Book 5 एकत्र):**

```
1. स्पष्ट करार आधी (Book 4, 4.7 spec-driven): agent ला
   "काय बांधायचं + कुठले सौदे" स्पष्ट सांगा. "किराणा-app
   बांध" नाही; "SQL वापर (पैसे आहेत), monolith ठेव (टीम
   छोटी), हे API-करार" : तुमची Book 5 ची नजर agent ला दिशा.
2. रचना तुम्ही ठरवा, code agent लिहो: database-निवड (2.2),
   monolith/micro (2.6), CAP (1.10): हे निर्णय तुमचे; अंमलबजावणी
   agent ची.
3. नकाशा वाचा (2.10): agent ने बांधलेलं वाचून सौदे-धोके
   तपासा: "इथे cache आहे, 'जुनं कधी' विचारलं का? इथे थेट
   database-हात आहे का (2.5 चा भंग)?"
4. Book 4 ची सगळी शिस्त लागू: evals (test), brakes, review
   (agent चं code ही reviewer ला/तुम्हाला दाखवा), observability.
```

**म्हणजे Book 5 शिकल्याने काय मिळालं:** agent ला **दिशा
देण्याची** आणि त्याचं काम **तपासण्याची** नजर. Agent ला
system-design कळत नाही असं नाही; पण **तुमच्या** परिस्थितीला
कुठला सौदा योग्य (छोटी टीम? पैसे? किती गर्दी?) हे **तुम्ही**
ठरवता: agent अंमलात आणतो. रचना न कळणारा माणूस agent
ला "किराणा-app बांध" म्हणतो आणि agent जे देईल ते घेतो
(बहुधा over-engineered, चुकीचे सौदे); रचना कळणारा माणूस
agent ला नेमकी दिशा देतो आणि त्याचं काम तपासतो. **तोच
फरक थर-4 (wrapper) आणि थर-5-6 (खंदक) मधला** (Book 4,
9.1).

**पूर्ण दोन पुस्तकांचं लग्न:** Book 4 ने "AI कसं वापरून बांधायचं"
दिलं (harness); Book 5 ने "काय बांधायचं, कुठली रचना" दिलं
(blueprint). एकत्र: **तुम्ही agent ला योग्य गोष्ट, योग्य रचनेत,
सुरक्षितपणे बांधायला लावू शकता: आणि त्याचं काम तपासू
शकता.** हीच 2026 ची सर्वात मौल्यवान जोडी: आणि आता ती
तुमच्याकडे आहे.

## महाग चूक

"AI सगळं बांधतं, आता system-design शिकायची गरज नाही."
सर्वात महाग गैरसमज. उलट: **जितकं बांधणं स्वस्त, तितकी
'काय-आणि-कशी बांधायची' ची नजर मौल्यवान.** Agent ला रचना
कळते, पण **तुमच्या** संदर्भातले सौदे (टीम-आकार, पैसा, गर्दी,
data-स्वभाव) तुम्हीच द्यायचे; आणि त्याचं काम **तपासायची**
नजरही तुमचीच. रचना न कळणारा agent-वापरकर्ता म्हणजे
आंधळा माणूस driverless गाडीत: गाडी चालवेल, पण **कुठे
जायचं** माहीत नसेल तर चुकीच्या जागी वेगात पोहोचेल. नजर
हीच steering.

```

     (तुमचे सौदे) + तपासणी (नकाशा वाचा) तुमची; Book 4
     (कसं) + Book 5 (काय) = मौल्यवान जोडी
```

**सूत्रावर:** शेवटचा, सर्वात मोठा सौदा-उलगडा: जेव्हा बांधणं
फुकट होतं, तेव्हा **काय बांधायचं आणि कुठला सौदा** हा निर्णय
सर्व मूल्याचा होतो. तुमची रचना-नजर हीच तुमची न-नकलता-येणारी
संपत्ती.

## स्वतः बघा (5 मिनिटं)

कुठल्याही AI ला "एक किराणा-app ची रचना सुचव" विचारा.
उत्तर वाचा आणि 2.10 ची सहा-प्रश्नांची नजर लावा: त्याने
कुठली database सुचवली, का? Monolith की micro? Cache
कुठे? आणि विचारा: "माझी टीम 2 माणसांची आहे, हे बदलतं
का?" बघा उत्तर कसं बदलतं. तुम्ही agent ला **दिशा देताय
आणि तपासताय**: हीच AI-युगातली तुमची भूमिका, प्रत्यक्ष.
