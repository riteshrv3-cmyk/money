# Chapter 1.2 [SPINE]: पहिली भिंत: Database चा जन्म आणि ACID

आरतीच्या पुसलेल्या-data च्या रात्रीतून पहिली खरी संकल्पना
जन्मते. माहितीला वेगळं, टिकाऊ घर हवं: **database.** पण
database म्हणजे नुसती "मोठी वही" नाही; ती एका करारावर उभी
असते: आणि तो करार समजला की पुढचं अर्धं पुस्तक सोपं होतं.

**Database म्हणजे नक्की काय जास्त देते?** किराणा-दुकानाची
वही आठवा: नुसती यादी. आता बँकेची वही आठवा: तिथे नियम
कडक आहेत: प्रत्येक नोंद पूर्ण किंवा मुळीच नाही; एकाच वेळी
दोन कारकून एकाच खात्याला हात लावले तर गोंधळ होऊ नये;
आणि एकदा नोंदलं की वीज गेली तरी टिकलं पाहिजे. **database
ही अशी शिस्तीची वही आहे.** त्या शिस्तीला चार अक्षरांचं नाव:
**ACID.** हे चार शब्द पाठ करा; हजारो engineers चं ते समान
पाया-ज्ञान आहे:

```
A  Atomicity (अखंडता): व्यवहार पूर्ण किंवा मुळीच नाही.
   रमेशचे पैसे कापले पण ऑर्डर नोंदली नाही: असं अर्धवट
   कधीच नाही. दोन्ही, किंवा काहीच नाही.
C  Consistency (सुसंगती): नियम कधीच मोडत नाहीत. साखर
   -5 किलो शिल्लक असं अशक्य; नियम database राखते.
I  Isolation (एकांत): दोन ऑर्डर एकाच वेळी आल्या तरी
   एकमेकांत मिसळत नाहीत; प्रत्येकीला वाटतं ती एकटीच.
D  Durability (टिकाऊपणा): एकदा "झालं" म्हटलं की वीज
   गेली, यंत्र बंद पडलं तरी नोंद राहते.
```

आरतीला हे चारही हवे आहेत. साखरेची शिल्लक, रमेशचे पैसे,
दुकानाचा हिशेब: इथे "अर्धवट" किंवा "मिसळलेलं" म्हणजे धंदा
बुडाला. म्हणून ती एक खरी database वापरते (PostgreSQL:
जगात 2026 त developers मध्ये सर्वात लोकप्रिय, Stack Overflow
च्या पाहणीत सलग पहिली): नुसती file नाही.

**पण इथे सूत्र लपलंय: ACID ची किंमत.** ही शिस्त फुकट नाही:
प्रत्येक "झालं" म्हणण्याआधी database ला खात्री करावी लागते
(खरंच लिहिलं? टिकलं?), एकांत राखायला कुलपं लावावी लागतात.
म्हणजे ACID = **खात्री विकत, वेग विकून.** बँकेची वही
किराणा-वहीपेक्षा **हळू** असते: कारण ती जास्त **खात्रीशीर**
असते. हा सौदा आत्ता (पैसे, शिल्लक) फायद्याचा; पण पुढे
आरतीला काही माहिती अशी भेटेल जिथे कडक खात्रीपेक्षा वेग
महत्त्वाचा (कोण-किती-वेळा-app-उघडलं सारखी): तिथे हाच सौदा
उलटवावा लागेल (Part 2 चा SQL-vs-NoSQL वाद याच फाट्यावर
उभा).

**खरी जगातली भीषण आठवण (postmortem-चव):** database
किती नाजूक, हे 2017 त **GitLab** ला महाग कळलं. एका
engineer ने रात्री, replication-चा गोंधळ सोडवताना, **चुकीच्या**
server वरची database-directory पुसली: ~300 GB. आणि मग
कळलं की त्यांच्या **पाच** backup-पद्धतींपैकी एकही धड चालत
नव्हती (backup-files काही bytes च्या, दुसरी रिकामी). शेवटी
~6 तास जुन्या एका snapshot वरून वाचवलं; ~6 तासांचा data
(हजारो projects, नोंदी) कायमचा गेला: आणि हे सगळं त्यांनी
**थेट YouTube वर live** दुरुस्त केलं. धडा दुहेरी: database
हे धंद्याचं हृदय, **आणि** "backup आहे" म्हणणं वेगळं, "backup
तपासलेला आहे" म्हणणं वेगळं (Book 4, 4.5 ची तीच शिकवण,
इथे रक्ताने). न तपासलेला backup म्हणजे नसलेला backup.

## महाग चूक

"माहिती Excel/file मध्येच ठेवू, database कशाला?" छोट्या,
न-वाढणाऱ्या, एकट्याच्या यादीला file ठीक. पण जिथे **पैसे,
शिल्लक, किंवा एकाच वेळी अनेक लोक** माहिती बदलतात: तिथे
file म्हणजे आरतीची पुसली-गेली रात्र आणि त्याहून वाईट: दोन
लोकांनी एकाच वेळी लिहिलं तर **गुपचूप** चुकीचा आकडा (isolation
नाही). ACID ची गरज "मोठेपणा" वर नाही, **माहितीच्या स्वभावा**वर
ठरते: पैसा-शिल्लक-नोंद = ACID हवीच.

## नकाशावर

```
1.1  एक यंत्र, तीन कामं; एकच अपयश-बिंदू
1.2  database = शिस्तीची वही (ACID: अखंड-सुसंगत-एकांत-
     टिकाऊ); खात्री विकत, वेग विकून
```

**सूत्रावर:** ACID हा पहिला मोठा जाणीवपूर्वक सौदा: वेग देऊन
खात्री घेतली. Top engineer ला विचारा "ACID हवी का?" तो
"कशासाठी?" विचारेल: पैशाला हो, like-count ला कदाचित नाही.
सौदा दिसणं = नजर.

## स्वतः बघा (5 मिनिटं)

तुमच्या फोनमधल्या दोन गोष्टींचा विचार करा: bank-app मधली
शिल्लक, आणि कुठल्याही app मधली "views/likes" ची संख्या.
कुठली **अचूक** असलीच पाहिजे (एक रुपयाही चुकून चालणार
नाही), आणि कुठली "साधारण बरोबर" चालते? ही रेषा म्हणजे
ACID कुठे हवी याची रेषा: तुम्ही ती रोज नकळत अनुभवता.

## विचार करा

आरतीचं app वाढलं: 10 वरून 500 ऑर्डर रोज. आणि अचानक
app **हळू** झालं: दुकानाची यादी उघडायला 8-10 सेकंद. Database
तीच, नियम तेच, मग हळू का? आरती गोंधळली: "माहिती तर आहेच
आत, मग शोधायला एवढा वेळ का?"

> कारण database माहिती **कशी शोधते** यावर वेग ठरतो, आणि
> डिफॉल्ट पद्धत म्हणजे "पूर्ण वही पहिल्या पानापासून चाळणं":
> 500 नोंदींना ठीक, 5 लाखांना संकट. वही भराभर उघडायला
> एक जुनी कारकुनी युक्ती लागते: अनुक्रमणिका. पुढची भिंत:
> index.
