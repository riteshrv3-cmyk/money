# THE BLUEPRINT

## Book 5, Part 1: प्रवास: एक User ते कोटी

**हे पुस्तक कुणासाठी:** Book 1 (The Machine) ने "internet चालतं
कसं" सांगितलं. हे पुस्तक पुढचं सांगतं: **टिकणारं, कोटी-लोकांचं
software बांधतात कसं, आणि जगातल्या उत्तम teams काम कशा
करतात.** का महत्त्वाचं? कारण तुमचं code आता agents लिहितील
(Book 4 ने दाखवलं); पण **कोणतं** बांधायचं, कुठली रचना निवडायची:
हा निर्णय अजून तुमचा. आणि तोच खरा फरक: top talent ची ओळख
code टाइप करण्याच्या वेगात नाही, **रचनेच्या नजरेत** आहे.

## या पुस्तकाचं एकमेव सूत्र

```
मोठेपणा फुकट नसतो.
प्रत्येक रचना-निर्णय म्हणजे काहीतरी विकून काहीतरी विकत घेणं.
Trade-off न दिसणं हीच खरी चूक.
```

उलगडून: software मध्ये "सगळ्यात चांगली" रचना नसते; फक्त
"या परिस्थितीला योग्य" रचना असते. वेग हवा तर जागा (किंवा
पैसा) विका; खात्री हवी तर वेग विका. जो engineer प्रत्येक
निर्णयामागचा **सौदा** बघतो तो top; जो "हे भारी tech आहे
म्हणून वापरू" म्हणतो तो नवखा. प्रत्येक chapter शेवटी हे सूत्र
परत भेटेल.

## आरतीचं किराणा-app: या पुस्तकाचं चालतं उदाहरण

**आरती.** वय 26. पुण्याजवळच्या तालुक्यातली. तिने एक साधं
app बनवलं: गावातल्या किराणा-दुकानांना घरपोच ऑर्डर. सुरुवात:
एक दुकान, एक गाव, दिवसाला 10 ऑर्डर, एका जुन्या laptop वर
चालणारं. Part 1 मध्ये आपण तिच्यासोबत प्रवास करू: 10 ऑर्डर
ते **कोटी** ऑर्डर. आणि हा प्रवास **भिंतींचा** आहे: प्रत्येक
टप्प्यावर एक नवी भिंत आदळते (app हळू झालं, database बुडाली,
दिवाळीला crash झालं), आणि प्रत्येक भिंत एक नवी संकल्पना
शिकवते. आरतीच्या जागी स्वतःला ठेवा: तिचा प्रत्येक पेच तुमचा
आहे.

## Book 1 ची उजळणी: 4 प्रश्न (बोलून; उत्तरं खाली)

**1.** Server म्हणजे काय? (Book 1)

> दुसऱ्यांच्या विनंत्या ऐकून उत्तर देणारा, सतत चालू असलेला
> computer.

**2.** Request-response एका ओळीत?

> तुमचा computer विनंती पाठवतो, server उत्तर परत पाठवतो;
> internet म्हणजे या देवाणघेवाणीचं जाळं.

**3.** Database का लागते?

> माहिती **टिकवायला** आणि पुन्हा शोधायला: वीज गेली तरी
> राहणारी, रचलेली साठवण.

**4.** Latency म्हणजे?

> विनंती आणि उत्तर यांच्यातला वेळ: अंतर जितकं जास्त,
> latency तितकी जास्त.

चौघे पक्के? मग आरतीच्या पहिल्या server पासून सुरू करू.
