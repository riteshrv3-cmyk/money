# Chapter 3.3 [DEPTH]: भाषांतरकाराचे दोन प्रकार

(DEPTH chapter. वगळू शकता; परत आलात की "compiled vs interpreted"
वाली प्रत्येक tech चर्चा उघडेल.)

एक पुस्तक मराठीत आहे, तुम्हाला ते English वाचकांपर्यंत पोहोचवायचं
आहे. दोन रस्ते आहेत, दोन्ही तुम्ही स्वतः विचार करू शकता:

**पहिला: पूर्ण पुस्तकाचं भाषांतर आधी करून घ्या.** वेळ लागेल, पण
त्यानंतर प्रत्येक English वाचक सरळ वाचेल, पूर्ण वेगाने. आणि
भाषांतरकार पूर्ण पुस्तक बघतो, म्हणून चुका आधीच सापडतील, छापण्याआधी.

**दुसरा: वाचकाशेजारी एक दुभाषी बसवा.** सुरुवात लगेच होईल: एक ओळ
ऐका, एक ओळ बोला. पण प्रत्येक वाचनाला भाषांतर पुन्हा होईल, म्हणून
वेग कमी. आणि चूक तेव्हाच सापडेल जेव्हा ती ओळ येईल; पुस्तकाच्या
मध्यात अडकू शकता.

Code चेही हेच दोन रस्ते आहेत:

**Compiler** = पूर्ण भाषांतर आधी. Code एकदा machine code मध्ये
बदलला, आता ती file सरळ CPU वर धावते. वेगवान. Games, browsers,
operating systems असे बनतात (भाषा: C, C++, Rust). तयार file चं
नाव **binary** किंवा **executable**: .exe वाली file हीच आहे,
भाषांतर झालेली recipe.

**Interpreter** = शेजारी बसलेला दुभाषी. लिहा आणि लगेच चालवा, बदला
आणि पुन्हा चालवा. आराम आहे, पण चालताना प्रत्येक ओळीचं भाषांतर
होतं, म्हणून हळू (10-100 पट पर्यंत). Python असं आहे.

मग सौदा साफ आहे: **compiler = मेहनत आधी, वेग नंतर. Interpreter =
आराम आधी, वेगाची किंमत नंतर.** स्वयंपाकाची उपमा: लग्नाच्या
पंगतीसाठी सगळी तयारी आदल्या दिवशी करून ठेवता (चिरून, वाटून,
मोजून), मग वाढताना विजेचा वेग. घरच्या रोजच्या जेवणात चालता-चालता
ठरवता, आज काय बनवायचं. दोन्ही बरोबर; प्रसंग वेगळे.

कुठला बरोबर? चुकीचा प्रश्न. **कुठल्या कामासाठी**, हा प्रश्न विचारा.
Game ला वेग हवा: compiler. रोज बदलणारं छोटं काम: interpreter.
(जगात मधले रस्तेही आहेत; Java आणि JavaScript अर्धं आधी, अर्धं
चालता-चालता भाषांतर करतात. पण मूळ कल्पना याच दोन.)

Android phone वर कधी update नंतर लिहून येतं "Optimising apps 1 of
132..." ते हेच आहे: phone आपल्या CPU साठी apps चं भाषांतर आधीच
करून ठेवतोय, म्हणजे नंतर प्रत्येक app वेगाने उघडेल. तुम्ही
compiler ला काम करताना बघितलं आहे; फक्त नाव माहीत नव्हतं.

## इथे लोक काय चुकीचं समजतात

"Python हळू आहे, मग AI सारखी जड कामं Python मध्ये का होतात?" चाल
अशी आहे: Python फक्त **steering** आहे. AI चा खरा जड हिशोब
(numbers चा गुणाकार, billions वेळा) compiled code मध्ये लिहिलेला
आहे (C/C++ च्या libraries); Python फक्त त्याला बोलावतो. हळू
भाषेतून वेगवान engine चालवलं जातंय. Abstraction पुन्हा: आराम वर,
वेग खाली, दोन्ही एकत्र.

## MAP वर

रुपयाचा रस्ता: server वर प्रत्येक second च्या CPU चं भाडं लागतं
(Part 5 मध्ये पूर्ण हिशोब). हळू code = जास्त seconds = मोठं bill.
म्हणून companies मोठ्या झाल्या की आपले सगळ्यात जास्त चालणारे भाग
compiled भाषांमध्ये **पुन्हा** लिहितात, फक्त bill घटवण्यासाठी.
Founder साठी धडा: सुरुवातीला आरामवाली भाषा (वेगाआधी जिवंत राहणं
गरजेचं), scale वर वेगवाली. चुकीच्या वेळी चुकीची निवड, दोन्ही
बाजूंनी महाग.

## स्वतः बघा (5 मिनिटं)

Laptop वर एक .exe file शोधा (कुठल्याही app च्या folder मध्ये) आणि
एक .txt file. .txt उघडा: माणसाला वाचता येतं. .exe ला Notepad मध्ये
उघडायचा प्रयत्न करा: विचित्र अक्षरांचा कचरा दिसेल, कारण ते machine
code आहे. दोन दुनियांचा फरक स्वतःच्या डोळ्यांनी: एक माणसासाठी
लिहिलेली, एक CPU साठी.
