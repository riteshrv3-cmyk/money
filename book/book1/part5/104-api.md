# Chapter 7.4 [SPINE]: दोन programs आपसात बोलतात कसे

Zomato ला delivery वाल्याचा रस्ता नकाशावर दाखवायचा आहे. नकाशा
बनवणं म्हणजे उपग्रह, गाड्या, जगाचं survey: decades चं काम. Zomato
ते करणार? अर्थात नाही: **Google Maps कडून मागणार.** पण थांबा:
मागणार **कसं**? Google च्या office ला फोन? माणसासाठी Google ने
screen बनवली आहे; पण इथे माणूस नाही, Zomato चा **program** दुसऱ्या
company च्या **program** शी बोलणार आहे.

Part 3 मधून उत्तराचा सांगाडा तुमच्याकडे आहेच: दोन machines बोलतात
तेव्हा **आधीच ठरलेले नियम** लागतात (protocol). आता तीच कल्पना एक
मजला वर न्या: दोन **programs** बोलतात तेव्हा ठरलेले **प्रश्न आणि
उत्तरांचे साचे** लागतात:

"असा प्रश्न विचारा: 'रस्ता दे: इथून-तिथे.' उत्तर असं येईल:
वळणांची यादी, अंतर, वेळ. चुकीचा पत्ता दिलात तर असा नकार येईल."

अशा ठरलेल्या प्रश्नोत्तर-साच्यांच्या यादीचं नाव **API**. हॉटेलचं
**menu card** हीच कल्पना आहे: हे-हे मागता येतं (यादी), असं मागायचं
(क्रमांक सांगा), हे मिळेल (ताट), आणि जे menu त नाही ते मागता येत
नाही: kitchen त घुसायची परवानगी नाही, गरजही नाही. API म्हणजे
program चं menu card: **आतलं न दाखवता, ठरलेल्या सेवा देणारा
दरवाजा.** (Chapter 0.4 चं abstraction, त्याच्या सगळ्यात व्यापारी
रूपात.)

तुम्ही रोज दहा APIs मधून जाता, न कळत: app मध्ये "Login with
Google" (तुमच्या app ने Google चा API वापरला), weather app (हवामान
खात्याचा API), प्रत्येक UPI app (NPCI चा API: Part 3 मध्ये protocol
म्हणून भेटला; apps साठी तो API च आहे), payment चं Razorpay-पान
(दुकानाने पैसे घेण्याचं पूर्ण kitchen भाड्याने घेतलं: फक्त API
जोडला).

आणि इथे एक करार-धर्म आहे: API हा **शब्द दिलेला** असतो. हजार apps
तुमच्या API वर बांधलेली आहेत; तुम्ही साचा बदललात (प्रश्नाचं रूप,
उत्तराचं रूप), तर ती हजार apps **एका क्षणात** तुटतात. म्हणून
जुना साचा चालू ठेवून नवा शेजारी उघडतात (versioning: menu बदललं
तरी जुन्या ग्राहकांची थाळी बंद करत नाहीत, आधी सांगून मगच).

## इथे लोक काय चुकीचं समजतात

"API म्हणजे engineers चा कुठलातरी बारीक technical शब्द." नाही: API
हा **धंद्याचा दरवाजा** आहे. API देणं म्हणजे जाहीर करणं: "माझ्या
दुकानावर तुम्ही **तुमची** दुकानं बांधा." आणि API **वापरणं** म्हणजे
दुसऱ्याच्या जमिनीवर भिंत बांधणं: सोय प्रचंड, पण जमीनमालक भाडं
वाढवू शकतो. हे खरोखर घडलं: Google Maps ने 2018 मध्ये API चे भाव
अनेक पटींनी वाढवले; रातोरात हजारो apps चं महिन्याचं bill उडालं,
काही धंदे बदलावे लागले. दुसऱ्याच्या API वर उभा असलेला business
हा **भाडेकरू** आहे; भाडेकरूने करार वाचावा.

## MAP वर

रुपयाचा रस्ता: "API विकणं" ही स्वतः एक अर्थव्यवस्था आहे. Razorpay/
Stripe म्हणजे "पैसे घेण्याचं kitchen, API ने भाड्याने": प्रत्येक
व्यवहारावर हिस्सा. Twilio: SMS चं kitchen. Google Maps: नकाशाचं.
आणि आता AI: OpenAI/Claude चा API म्हणजे "विचार करण्याचं kitchen,
भाड्याने" (Book 2). तुमच्या 4-level नकाशावर बघा: API हे Level 3
च्या आतल्या दुकानांचं **वाणिज्य-रूप** आहे: जो एक कठीण गोष्ट सोपा
दरवाजा लावून विकतो, तो हजारो धंद्यांचा पुरवठादार होतो: लोणी सगळे
बनवत नाहीत; डेअरीकडून घेतात.

## स्वतः बघा (5 मिनिटं)

तुमच्या कुठल्याही app मध्ये हे शोधा: "Login with Google" चं बटण,
हवामानाचा तुकडा, नकाशाचा तुकडा, payment चं पान जे क्षणभर वेगळं
दिसतं (Razorpay/PayU चा रंग). प्रत्येक तुकडा म्हणजे **दुसऱ्या**
company चं kitchen, API ने जोडलेलं. एक app मोजा: आत किती
companies चे APIs दिसतात? पाच-सात सहज निघतील. आजचं software
म्हणजे स्वतःचं थोडं + APIs ची जोडणी.
