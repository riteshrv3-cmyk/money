# PART 4 चा शेवट: नकाशा आणि पुढचं पाऊल

## जे तुमच्याकडे आता आहे

```
DATABASE       data चा एकमेव दरबान: वेगळा, कायम चालणारा
               program; file नाही, server आहे
INDEX          लावलेली यादी + खुणा; 10 million मधून ~23
               पावलांत; किंमत: लिहिणं हळू, जागा जास्त
QUERY / SQL    database ला विचारलेला प्रश्न / tables ची भाषा
आकार           खण (table), पिशवी (document), खुंटी
               (key-value); आकार कामावरून, fashion वरून नाही
TRANSACTION    "सगळं किंवा काहीच नाही" चा गठ्ठा; अर्धवट
               अवस्था अस्तित्वातच नाही (rollback)
LOCK / RACE    मोजकी वस्तू + अनेक हात = कुंडी; नाहीतर शर्यत
               आणि दोन तिकिटं एक खुर्ची
QUEUE / ASYNC  आत्ता नोंदवा, नंतर करा; waiter ची चिठ्ठी;
               पडलेली system = साठलेली रांग, हरवलेलं काही नाही
CACHE          महाग उत्तर जवळ ठेवणं; किंमत: शिळेपणा;
               दाखवणं शिळं चालतं, बदलणं ताजंच लागतं
BACKUP vs      काळ-प्रत (चुकीपासून वाचवते) vs जिवंत प्रत
REPLICATION    (machine मरण्यापासून; पण चूकही copy करते)
3-2-1          3 प्रती, 2 प्रकारच्या जागा, 1 दुसऱ्या गावात;
               आणि: न तपासलेला backup = backup नाहीच
```

## एक परीक्षा, स्वतःसाठी

पुस्तक न उघडता, बोलून उत्तरं द्या:

1. Excel आणि database मध्ये खरा फरक काय? (नुसतं "मोठा" चालणार
   नाही; तीन तुटी सांगा.)
2. 10 million नोंदींमधून शोध 23 पावलांत कसा होतो?
3. पैसे पाठवताना "वजा झाले पण जमा नाही झाले" ही अवस्था का
   अस्तित्वात येऊ शकत नाही?
4. Backup असूनही company का बुडू शकते? (दोन कारणं.)

अडलात तर: 1 -> 6.1, 2 -> 6.2, 3 -> 6.4, 4 -> 6.7.

## Part 5 मध्ये काय आहे

आता तुमच्याकडे पूर्ण machine आहे: recipe चालते (Part 1-2), जग
जोडलेलं आहे (Part 3), आठवण पक्की आहे (Part 4). शेवटचा प्रश्न
उरला, आणि तो थेट पैशाचा आहे: **हे सगळं लाखो लोकांसाठी, एकाच
वेळेस, परवडणाऱ्या खर्चात कसं चालवायचं?** Cloud म्हणजे नक्की काय
आणि त्याचं bill कसं वाचायचं, traffic अचानक दहापट झाला तर काय,
जगभर वेगवान कसं राहायचं (CDN), आणि शेवटी: एक खरं product उघडून
त्यात या पूर्ण पुस्तकाचा नकाशा बघणं. Part 5: जगाला SERVE करणं.
शेवटचा आणि सगळ्यात मोठा part.
