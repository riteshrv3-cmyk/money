# Chapter 6.5 [DEPTH]: कामाला रांगेत लावणं

(DEPTH chapter. लहान आहे, आणि यानंतर "हे काम आत्ता, ते नंतर" ही
design ची नजर मिळते: ती founder ची नजर आहे.)

Zomato वर order पडली. आता किती कामं करायची आहेत मोजा: पैसे घ्या,
order नोंदवा, restaurant ला कळवा, delivery वाल्याला शोधा, तुम्हाला
SMS पाठवा, email पाठवा, loyalty points द्या, हिशोबाच्या वहीत नोंद
करा. आठ कामं.

सोपं design: सगळी आठ कामं **आत्ता** करा, मग user ला "order झाली"
दाखवा. काय बिघडेल? User थांबलेला आहे: आठ कामं x प्रत्येकाचा वेळ =
फिरणारं चक्र, आणि Chapter 2.3 ची आठवण: उशीर = गेलेला ग्राहक. आणि
वाईट: SMS पाठवणारी system **पडली** असेल तर? आठपैकी एक काम अडलं
म्हणून पूर्ण order अडली? SMS साठी धंदा थांबवायचा?

आता हॉटेलचा waiter बघा; त्याला हे design आधीच येतं. तो तुमची
order घेतो, kitchen च्या खिडकीत **चिठ्ठी लावतो**, आणि लगेच पुढच्या
table कडे जातो. तो स्वयंपाक होईपर्यंत उभा राहत नाही. चिठ्ठ्या
रांगेत लागतात; cooks आपल्या वेगाने त्या उचलतात. Waiter चं काम:
मागणी **नोंदवणं**. Kitchen चं काम: ती **पूर्ण करणं**. दोघांचे वेग
वेगळे, आणि म्हणूनच दोघांना जोडणारी **रांग** मध्ये आहे.

Software मध्ये या रांगेचं नाव **queue**, आणि या पद्धतीचं नाव
**async** (आत्ता नोंदवा, नंतर करा). Order च्या आठ कामांना आता दोन
रंगांत वाटा:

**आत्ताच झालीच पाहिजेत:** पैसे घेणं आणि order नोंदवणं (हे मागच्या
chapter चा transaction-गठ्ठा). हे झालं की user ला हिरवी खूण:
"Order झाली!" वेळ: 1-2 seconds.

**नंतर चालतील:** SMS, email, points, हिशोब. यांच्या चिठ्ठ्या
रांगेत टाकल्या. वेगळे कामगार-programs (workers) त्या सावकाश
उचलतात. SMS system पडली? चिठ्ठ्या रांगेत **साठून राहतात**; system
उठली की निघतात. User ला पत्ताही नाही; त्याची order कधीच अडली नाही.

ही रचना तुमच्या रोजच्या अनुभवात उघड दिसते: WhatsApp वर message
पाठवताना **घड्याळ-icon** दिसतं (तुमच्या phone च्या रांगेत आहे), मग
एक tick (server च्या रांगेत पोहोचला), मग दोन (मित्राला मिळाला).
"पाठवलं" म्हणजे "पोहोचलं" नाही; "रांगेत नोंदवलं." आणि म्हणूनच
network नसतानाही तुम्ही message "पाठवू" शकता: रांग वाट बघते.
Diwali च्या मध्यरात्री सगळ्यांचे greetings उशिरा पोहोचतात ते
म्हणूनच: रांगा भरलेल्या; पण **हरवत** कोणीच नाही.

## इथे लोक काय चुकीचं समजतात

"चांगलं system म्हणजे सगळं realtime." उलटं आहे: चांगलं system
म्हणजे **नेमकं** काय realtime हवं हे माहीत असलेलं. सगळंच आत्ता
करायचं तर सगळ्यांची ताकद सगळ्या क्षणी लागते: खर्च टोकाचा, आणि एक
भाग पडला की सगळं पडतं. सरकारी office जेव्हा "अर्ज घेतला, पावती
घ्या, निकाल टपालाने येईल" म्हणतं, तेव्हा ते (नकळत) उत्तम queue
design आहे: घेणं वेगवान, करणं सावकाश. चीड येते ती रांग **किती
लांब** आहे याची; रांग **असण्याची** नाही.

## MAP वर

रुपयाचा रस्ता: रांगा चालवणं हा स्वतः infra-धंदा आहे (Kafka,
RabbitMQ, cloud च्या queue-सेवा). पण तुमच्यासाठी मोठी गोष्ट खर्चाची
आहे: "आत्ताच" ची ताकद **सगळ्यात महाग** असते; "नंतर चालेल" ची
स्वस्त, कारण ती सावकाश, रात्री, स्वस्त machines वर चालवता येते.
म्हणून product design करताना प्रत्येक feature ला विचारा: हे user
समोर उभं राहून व्हायला हवं, की चिठ्ठी लावून? या एका प्रश्नाने
server चं bill दुप्पट-अर्धं होतं. (Part 5 मध्ये हा हिशोब पूर्ण
भेटेल.)

## स्वतः बघा (5 मिनिटं)

Phone airplane mode वर टाका आणि कोणाला तरी WhatsApp message लिहा.
घड्याळ-icon दिसेल: तुमची चिठ्ठी रांगेत आहे, वाट बघते आहे. आता
airplane mode काढा: tick, मग दोन ticks, आपोआप. तुम्ही आत्ता एक
queue पूर्ण चक्र चालताना बघितली: नोंदवलं, थांबलं, जमलं तेव्हा
झालं, हरवलं काहीच नाही.

## विचार करा

1. (derivation) Cinema ticket booking system design करताय. ही
कामं दोन रंगांत वाटा: seat अडवणं, पैसे घेणं, ticket चा QR बनवणं,
SMS पाठवणं, "आवडेल असे shows" सुचवणं. कुठलं आत्ता, कुठलं रांगेत?
आणि एक काम **मुद्दाम** अवघड आहे: QR कुठे टाकाल?

> **उत्तर:** Seat अडवणं + पैसे: आत्ताच, एका transaction-गठ्ठ्यात
> (Chapter 6.4: मोजकी वस्तू + अनेक हात). SMS आणि सुचवणं: रांगेत,
> उशीर चालतो. QR मधली गोम: user ला ticket **लगेच** दिसायला हवं
> (theatre ला निघालाय!), म्हणजे "नंतर चालेल" म्हणता येत नाही; पण
> QR बनवणं म्हणजे फक्त एक चित्र काढणं, त्यात मोजकं काही अडवायचं
> नाही, म्हणून transaction मध्ये कोंबूही नये. उत्तर: transaction
> पूर्ण होताच, रांगेच्या **सगळ्यात पुढच्या** टोकाला, आणि screen
> वर "ticket तयार होतंय..." ची दोन seconds. धडा: "आत्ता vs नंतर"
> हे दोनच रंग नाहीत; "किती नंतर चालेल" ही एक **मोजपट्टी** आहे,
> आणि design म्हणजे प्रत्येक कामाला तिच्यावर योग्य जागी ठेवणं.
