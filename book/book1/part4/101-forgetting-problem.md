# Chapter 6.1 [SPINE]: विसरण्याची problem

Part 2 चं एक सत्य आठवा (Chapter 3.6): process मेली की तिची state
जाते. जे वाचवायचं ते storage मध्ये लिहावं लागतं. मग सोपं वाटतं:
file मध्ये लिहून टाका. संपलं?

दुकानाच्या वहीने सुरुवात करू, कारण file म्हणजे तेच: एक वही.
छोट्या दुकानाला वही पुरते. आता दुकान वाढतंय. बघा वही कुठे कुठे
तुटते:

**नोंदी crores झाल्या.** "पाटील यांची उधारी किती?" वही पान-पान
चाळावी लागते. 10 million नोंदींची file म्हणजे तेच: उत्तरासाठी
सगळं वाचणं.

**लिहिणारे अनेक झाले.** गल्ल्यावर तुम्ही, मागे भाऊ, online भाचा:
तिघे **एकाच** वहीत एकाच वेळेस लिहू लागले तर? नोंदी एकमेकांवर
चढतील, काही हरवतील. Files सोबत नेमकं हेच होतं: दोन programs नी
एकाच वेळेस लिहिलं की भेळ.

**प्रश्न अवघड झाले.** "या महिन्यात 500 पेक्षा जास्त उधारी असलेले,
गावाबाहेरचे ग्राहक कोण?" वहीत उत्तर **आहे**, पण विखुरलेलं. File
पण असंच: data आहे, उत्तर काढायचं म्हणजे स्वतः recipe लिहा.

**अर्धवट लिहिताना वीज गेली.** नोंद अर्धी लिहिली गेली: "पाटील,
500 जमा..." आणि पुढचं गायब. आता वहीवर विश्वास कसा ठेवायचा?

चारही अडचणी एकत्र बघा, आणि design स्वतः सुचतं: वही **प्रत्येकाच्या
हातात देणंच** चूक आहे. एक वेगळा, कायम चालणारा program हवा, ज्याचं
**एकच** काम आहे: data ठेवणं. सगळे programs त्याला **विनंती**
करतील ("ही नोंद ठेव," "हे शोधून दे"); वहीला हात फक्त तोच लावेल.
तो रांग लावेल, अर्धवट नोंदी होऊच देणार नाही, शोध वेगवान ठेवेल.

या program चं नाव **database**. आणि लक्ष द्या: database म्हणजे
file नाही; तो एक **server** आहे (Part 3 ची भाषा: देणारी machine),
जो दिवसरात्र चालू असतो आणि data चा एकमेव दरबान असतो. सोसायटीचं
office आठवा: कागदपत्रं सदस्यांच्या घरी नाही, office मध्ये असतात;
पाहिजे ते secretary कडे **मागावं** लागतं, आणि नोंदी तोच करतो.
नियम जाचक वाटतात, पण 500 सदस्यांची सोसायटी त्यांच्याशिवाय
कोसळेल.

तुमच्या भोवतीचं जग आता या नजरेने बघा: bank चं प्रत्येक खातं एका
database मध्ये आहे. Zomato ची प्रत्येक order, WhatsApp चा प्रत्येक
group, IRCTC चं प्रत्येक ticket. जगातला जवळजवळ प्रत्येक business
शेवटी एका database भोवती बांधलेला आहे, जसं जुनं गाव विहिरीभोवती.

## इथे लोक काय चुकीचं समजतात

"Excel आहे ना, तोच आमचा database." छोट्या कामाला खरंच पुरतो, आणि
तिथे तो उत्तम आहे. पण वरच्या चार तुटी आठवा: Excel ची file एकाच
वेळेस अनेकांनी लिहिली की भेळ होते, 1 million ओळींवर तो धापा टाकतो,
आणि अर्धवट लिहिणं त्याला कळत नाही. हजारो businesses "Excel वर
चाललंय ना" म्हणत वाढले आणि एका दिवशी orders हरवायला लागल्या. Excel
वही आहे; database दरबान आहे. दुकान केवढं आहे यावर निवड ठरते; पण
फरक **माहीत** असणं founder चं काम आहे.

## MAP वर

Database हा Level 3 च्या आतला एक अख्खा देश आहे: Oracle या एका
company ने databases विकून decades राज्य केलं (आजही ~50 billion
dollars ची company). मग open source आलं (Chapter 3.7): Postgres,
MySQL फुकट झाले, आणि आता cloud companies तेच भाड्याने देतात (Part
5). आणि एक खोल गोष्ट: business विकला जातो तेव्हा खरेदीदार काय
विकत घेतो? Building नाही, code ही नाही: **database** विकत घेतो:
ग्राहक कोण, काय घेतात, किती देतात. Data हीच मालमत्ता, बाकी सगळं
आवरण.

## स्वतः बघा (5 मिनिटं)

तुमच्या bank च्या app मध्ये statement उघडा आणि filter लावा: फक्त
"debit", फक्त "या महिन्यातले". अर्ध्या second मध्ये उत्तर आलं.
आता कल्पना करा हेच काम एका कागदी वहीत करायचं: पान-पान, खूण करत.
तुम्ही आत्ता database ला काम करताना बघितलंत: crores नोंदींमधून,
अटी लावून, क्षणात. पुढचा chapter सांगेल हे **कसं** शक्य आहे.

## विचार करा

1. (derivation) भाजीवाल्याला वही पुरते; bank ला database लागतो.
मधली रेषा नेमकी कुठे आहे? तीन प्रश्न बनवा, जे कुठल्याही business
ला विचारून "वही की database" ठरवता येईल.

> **उत्तर:** (1) **लिहिणारे किती?** एक माणूस: वही चालते. एकाच
> वेळेस अनेक (दुकानं, apps, branches): database. (2) **नोंदी
> किती?** हजारांत: काहीही चालेल. Millions मध्ये: शोधासाठी database.
> (3) **चुकीची किंमत काय?** भाजीची एक नोंद चुकली: 20 रुपये गेले.
> Bank ची एक नोंद चुकली: विश्वास गेला, license गेलं. जिथे चुकीची
> किंमत मोठी, तिथे दरबान लागतो. लक्षात घ्या: तिन्ही प्रश्न
> technology चे नाहीत, **business** चे आहेत. Tech ची निवड नेहमी
> business च्या प्रश्नांनी सुरू होते; हत्यारांनी नाही.
