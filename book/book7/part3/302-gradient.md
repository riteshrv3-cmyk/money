# Chapter 3.2 [SPINE]: Gradient: धुक्यातला डोंगर उतरणं

थेंबूचा प्रश्न: लाखो weights चे उतार एकत्र कसे? उत्तर Part 1
शी जोडतं: सगळ्या weights चे derivatives मिळून एक **बाण**
(vector) होतो, आणि त्याचं नाव **gradient.** हा विभागाचा
मध्यवर्ती शब्द आहे.

**Gradient म्हणजे काय.** एका weight चा derivative = त्या एका
दिशेतला उतार (3.1). पण अनेक weights म्हणजे अनेक दिशा
(थेंबूला 2: आर्द्रता-अक्ष, ढग-अक्ष). प्रत्येक अक्षाचा वेगळा उतार
काढा, त्यांची यादी बनवा: **तोच gradient बाण.** आणि त्याचा
सुंदर गुणधर्म: **gradient बाण नेहमी सर्वात तीव्र चढाच्या दिशेला
दाखवतो.** म्हणजे "इथून सर्वात वेगात **वर** (loss वाढेल) कुठे?"
मग loss कमी करायला? **gradient च्या बरोबर उलट** जा: सर्वात
तीव्र **उताराची** दिशा. याला **gradient descent** (उतार-उतरण)
म्हणतात: पूर्ण यंत्र-शिक्षणाचं इंजिन.

**धुक्यातल्या डोंगराची पूर्ण उपमा (Book 2, 2.6 आता नेमकी).**
तुम्ही धुक्यात डोंगरावर, तळ शोधायचाय (कमीत कमी loss).
पूर्ण नकाशा दिसत नाही. काय करता? (1) पायाखाली चाचपून
बघता: **कुठली दिशा सर्वात तीव्र खाली** (gradient चं उलट).
(2) त्या दिशेला **एक पाऊल** (छोटं, कारण धुकं). (3) नव्या
जागी पुन्हा चाचपा, पुन्हा पाऊल. हळूहळू तळाकडे. हेच gradient
descent: **उतार बघ -> उलट दिशेला पाऊल -> पुन्हा**, हजारो-
लाखो वेळा. यंत्र "शिकतं" म्हणजे नक्की हेच करतं: loss-डोंगरावर
weights-चेंडू धुक्यात, पावलापावलाने तळाकडे.

**थेंबूवर आकड्यांनी (दोन weights).** थेंबूचा loss दोन weights
w1, w2 वर. एका जागी gradient काढला, म्हणा तो बाण (+4,
-2) निघाला. अर्थ: "w1 वाढवला तर loss जोरात वाढेल (+4);
w2 वाढवला तर loss घटेल (-2)." loss कमी करायला **उलट**
जा: w1 **कमी** करा, w2 **वाढवा**, आणि प्रमाणात (4 चा उतार
मोठा म्हणून w1 जास्त हलवा). एक पाऊल:

```
gradient = (+4, -2)   (सर्वात तीव्र चढाची दिशा)
उलट दिशा = (-4, +2)   (सर्वात तीव्र उताराची: इकडे जा)
w1: 5 -> 5 - (थोडं)x4  (कमी करा, जास्त)
w2: 3 -> 3 + (थोडं)x2  (वाढवा, कमी)
```

नवे weights loss किंचित कमी करतात. पुन्हा gradient, पुन्हा
पाऊल. **हेच शिकणं, फक्त 2 ऐवजी अब्जावधी weights आणि
ट्रिलियन पावलं.**

**आणि इथे GPU का लागतो ते नेमकं दिसतं (Book 2 चा कारखाना):**
अब्जावधी weights चा gradient एका पावलात काढणं म्हणजे अब्जावधी
derivatives, अब्जावधी गुणा-बेरीज (Part 1 चे dot products,
matrices). आणि हे ट्रिलियन पावलं. म्हणून हजारो GPU, महिनोन्महिने
(Book 4, 1.1 चं training-bill: आता कळलं कशाचं). "training"
म्हणजे: प्रचंड gradient descent, धुक्यातल्या अवाढव्य डोंगरावर.

## इथे लोक काय चुकीचं समजतात

"Gradient descent यंत्राला 'सर्वोत्तम उत्तर' शोधून देतो." नाही:
तो फक्त **जवळचा खोलगट भाग** शोधतो (local minimum), जगातला
सर्वात खोल नाही. धुक्यात तुम्ही एका दरीत उतराल, पण शेजारी
अजून खोल दरी असू शकते: तुम्हाला दिसत नाही. आश्चर्य हे की
अब्जावधी-मितींच्या डोंगरावर हे बहुधा **पुरेसं चांगलं** निघतं (का,
ते 3.6 चं गूढ). पण "सर्वोत्तम सापडतं" ही चूक: gradient descent
"चांगलं-पुरेसं" शोधतो, "परिपूर्ण" नाही.

## नकाशावर

```
3.1  derivative = एका दिशेतला उतार
3.2  gradient = सगळ्या weights चे उतार एकत्र (बाण); सर्वात
     तीव्र चढाची दिशा -> उलट जा (gradient descent); धुक्यात
     पावलापावलाने तळाकडे = शिकणं
```

**सूत्रावर:** gradient हा चष्मा "अब्जावधी weights एकत्र कसे
सुधारायचे" या अशक्य वाटणाऱ्या प्रश्नाला एका बाणात आणतो:
सर्वात तीव्र उताराची दिशा. जे मोजता येतं (gradient) त्या दिशेने
सगळे weights एकदम सुधारतात: हेच शिकण्याचं इंजिन.

## स्वतः बघा (5 मिनिटं)

डोळे मिटून, एका उतारावर उभं असल्याची कल्पना करा. पायाखाली
जाणवतं: डावा पाय थोडा खाली, उजवा थोडा वर -> म्हणजे उतार
डावीकडे-खाली. तुम्ही सहज डावीकडे पाऊल टाकाल (तळाकडे).
तुमचा पाय हा gradient-sensor आहे; तुमचं पाऊल gradient
descent. यंत्र हेच करतं, फक्त अब्जावधी "पायांनी" (weights)
एकाच वेळी.
