# विभाग 1: दिशांचं जग

AI च्या तळाशी एकच गणिती कल्पना आहे, आणि ती आश्चर्यकारक
साधी आहे: **आकड्यांची यादी म्हणजे एक दिशा.** थेंबूची आर्द्रता
आणि ढग: दोन आकडे: म्हणजे एक बाण. शब्दाचा अर्थ: शेकडो
आकडे: म्हणजे शेकडो-मितींतला बाण. आणि यंत्राचं सगळं काम
म्हणजे या बाणांना **फिरवणं, ताणणं, जुळवणं.** हा विभाग तो
पाया घालतो: vector (दिशा) आणि matrix (दिशा फिरवणारं यंत्र).
**हे तुमच्या शिक्षणात कुठे येईल:** embedding, attention, हे
सगळे शब्द इथून जन्मतात; हा विभाग समजला की पुढचं सगळं
"आकडे फिरवणं" इतकं सोपं होतं.

# Chapter 1.1 [SPINE]: Vector: आकड्यांची यादी म्हणजे दिशा

थेंबूकडे आज दोन आकडे आहेत: आर्द्रता **0.8** (0 म्हणजे कोरडं,
1 म्हणजे पूर्ण दमट), आणि ढग **0.6** (0 म्हणजे निरभ्र, 1 म्हणजे
पूर्ण भरलेलं). या दोन आकड्यांची यादी: **(0.8, 0.6)**: हाच एक
**vector.** आणि गणिताची पहिली जादू: ही यादी म्हणजे नुसते
दोन आकडे नाहीत, ती एक **जागा** आहे, एक **दिशा** आहे.

**कागदावर बघा (मनातल्या मनात).** एक कागद घ्या. डावी-उजवी
रेषा = आर्द्रता, खाली-वर रेषा = ढग. आता (0.8, 0.6) म्हणजे:
उजवीकडे 0.8, वर 0.6: तिथे एक टिंब. मध्यबिंदूपासून त्या
टिंबापर्यंत **बाण** काढा: तो बाण म्हणजे थेंबूचा आजचा "हवामान-
vector." आजची पूर्ण हवा एका बाणात. उद्या हवा बदलली (0.3,
0.9: कोरडं पण ढगाळ) तर बाण वेगळ्या दिशेला. **प्रत्येक
परिस्थिती = एक बाण; बदल = बाण फिरणं.**

**दोन गोष्टी बाण सांगतो: दिशा आणि लांबी.** दिशा = कुठल्या
बाजूला झुकलंय (आर्द्रतेकडे की ढगांकडे). लांबी = किती "जोरात"
(दोन्ही आकडे मोठे तर लांब बाण). ही दोन्ही पुढे कामाला येतील:
दिशा म्हणजे **अर्थ** (कशासारखं), लांबी म्हणजे **तीव्रता.**

**आणि आता खरी जादू: यादी कितीही लांब असू शकते.** थेंबूकडे
2 आकडे, म्हणून 2-मितींचा (कागदावर काढता येणारा) बाण. पण
कल्पना करा 3 आकडे (आर्द्रता, ढग, तापमान): आता बाण
**खोलीत** (3D, खोलीतल्या दिशेसारखा). आणि AI मध्ये? एका
शब्दाचा अर्थ **शेकडो किंवा हजारो** आकड्यांनी दाखवला जातो:
म्हणजे शेकडो-मितींतला बाण. तो आपल्याला **काढता येत नाही**
(आपले डोळे 3 मितींपुरते), पण गणित त्याला बाणासारखंच हाताळतं:
दिशा, लांबी, फिरवणं: सगळं तेच, फक्त जास्त आकडे. **हीच AI ची
पहिली गुरुकिल्ली:** शब्द, चित्र, आवाज: सगळं आकड्यांच्या याद्यांत,
म्हणजे बाणांत, म्हणजे दिशांत बदलतं. (Book 2 चं embedding:
आता कळलं ते नक्की काय: शब्दाला दिलेला बाण.)

**थेंबूचं पहिलं पाऊल:** थेंबू आजची हवा (0.8, 0.6) या एका
बाणात बघतो. पुढच्या chapters मध्ये तो या बाणाला **तपासेल**
(पावसाच्या दिशेशी किती जुळतो?), **फिरवेल** (यंत्रातून जाताना),
आणि त्यातून अंदाज काढेल. सगळी सुरुवात या एका कल्पनेतून:
यादी = दिशा.

## इथे लोक काय चुकीचं समजतात

"Vector म्हणजे भौतिकशास्त्रातला बाण (वेग, बल)." तिथे सुरुवात
झाली, पण AI मध्ये vector म्हणजे **कुठलीही आकड्यांची यादी**:
तिला "दिशा" मानायचं ही गणिती सोय आहे, भौतिक बाण नाही.
थेंबूचा (0.8, 0.6) हा हवेचा वेग नाही; तो फक्त "आर्द्रता-अक्षावर
0.8, ढग-अक्षावर 0.6" ही जागा आहे. आणि दुसरा गैरसमज:
"शेकडो मिती म्हणजे काहीतरी अतिमानवी." नाही: 2 आकड्यांचं
जे गणित, तेच 700 आकड्यांचं: फक्त आपल्याला डोळ्यांनी दिसत
नाही, गणिताला दिसतं. मिती वाढणं म्हणजे यादी लांब होणं,
जादू होणं नाही.

## नकाशावर

(ही यादी दर chapter ला एक ओळ वाढेल.)

```
1.1  vector = आकड्यांची यादी = दिशा (बाण); दिशा=अर्थ,
     लांबी=तीव्रता; शब्द/चित्र/आवाज सगळं बाणांत
```

**सूत्रावर:** vector हा पहिला चष्मा: तो लावला की "शब्दाचा
अर्थ यंत्राला कसा कळतो" हे गूढ नाहीसं होतं: अर्थ = दिशा,
आणि दिशा = आकड्यांची यादी. न दिसणारं (अर्थ) आकड्यांत
दिसायला लागलं.

(0.9, 0.1), (0.1, 0.9), (0.8, 0.7). प्रत्येकाला मध्यापासून

## विचार करा

# Chapter 1.2 [SPINE]: Dot Product: जवळिकीचं माप

थेंबूला दोन बाणांची जवळीक एका आकड्यात हवीय. गणिताचं उत्तर
एका साध्या कृतीत आहे, आणि ती कृती AI मध्ये **सर्वात जास्त
वेळा** घडते: म्हणून ती हातानेच करून बघू.

**कृती: जोडीजोडीने गुणा, मग बेरीज.** दोन बाण:
आज = (0.8, 0.6), आदर्श-पावसाळी = (0.9, 0.7). Dot product:

```
पहिले आकडे गुणा:   0.8 x 0.9 = 0.72
दुसरे आकडे गुणा:   0.6 x 0.7 = 0.42
बेरीज:            0.72 + 0.42 = 1.14
```

झालं. दोन बाणांचा dot product = **1.14.** एका आकड्यात दोन
बाणांची "जुळणी." मनातल्या मनात झालं ना? यंत्रात हेच अब्जावधी
वेळा घडतं: फक्त 2 ऐवजी शेकडो आकडे, पण कृती तीच: जोडीने
गुणा, बेरीज.

**हा आकडा काय सांगतो: तीन प्रसंग बघा.** थेंबूची आजची हवा
(0.8, 0.6) तीन वेगळ्या "आदर्शां"शी ताडू:

```
पावसाळी आदर्श (0.9, 0.7): 0.8x0.9 + 0.6x0.7 = 0.72+0.42 = 1.14  (मोठा!)
कोरडा आदर्श   (0.1, 0.2): 0.8x0.1 + 0.6x0.2 = 0.08+0.12 = 0.20  (छोटा)
उलटा         (-0.9,-0.7): 0.8x-0.9+0.6x-0.7 = -0.72-0.42 = -1.14 (उणे!)
```

नियम स्पष्ट दिसतो: **बाण एकाच दिशेला (सारखे) -> dot मोठा
सकारात्मक; लंब (असंबंधित) -> शून्याजवळ; उलट्या दिशेला
(विरुद्ध) -> उणे.** म्हणजे dot product हे **जवळिकीचं थर्मामीटर**
आहे: एका आकड्यात "हे दोन बाण किती एकमेकांसारखे." थेंबूला
आता कळलं: आजची हवा पावसाळी-आदर्शाशी खूप जुळते (1.14),
कोरड्याशी नाही (0.20): म्हणजे आज पाऊस शक्य.

**आणि इथे AI ची दुसरी गुरुकिल्ली:** Book 2 मध्ये attention
म्हणजे "मागणी-पाटी जुळणी" (query-key match) होतं. ते नक्की
काय? **प्रत्येक शब्दाचा query-बाण दुसऱ्या शब्दांच्या key-बाणांशी
dot product.** मोठा dot = "हे दोन शब्द एकमेकांशी संबंधित,
लक्ष दे"; छोटा = "दुर्लक्ष कर." Attention चं हृदय म्हणजे लाखो
dot products: जवळिकीची लाखो मापं. आणि embedding-शोध
(RAG, Book 4): "या प्रश्नाशी जवळचे कागद" म्हणजे सर्वात मोठा
dot product असलेले. **एक साधी कृती: जोडीने गुणा, बेरीज: AI
च्या अर्ध्या कामाचा पाया.**

## इथे लोक काय चुकीचं समजतात

"Dot product म्हणजे किचकट गणित." आत्ता तुम्ही ते मनातल्या
मनात केलंत: दोन गुणाकार, एक बेरीज. किचकट काहीच नाही;
फक्त AI मध्ये आकडे शेकडो आणि कृती अब्जावधी वेळा, म्हणून
GPU लागतो (Book 2 चा कारखाना: तो हेच अब्जावधी गुणा-बेरीज
करतो!). दुसरा गैरसमज: "जवळीक म्हणजे नेहमी चांगलं." नाही:
dot फक्त **मोजतो**; तो जवळ हवा की दूर हे कामावर ठरतं
(query ला उत्तर जवळचं हवं, पण दोन वेगळ्या गोष्टी वेगळ्याच
हव्यात). Dot हे थर्मामीटर आहे, ताप चांगला की वाईट हे तुम्ही
ठरवता.

## नकाशावर

```
1.1  vector = यादी = दिशा (बाण)
1.2  dot product = जोडीने गुणा+बेरीज = जवळिकीचं माप;
     सारखे->मोठा, लंब->शून्य, उलटे->उणे; attention चं हृदय
```

**सूत्रावर:** dot product हा चष्मा "यंत्राला दोन शब्द संबंधित
आहेत हे कसं कळतं" हे गूढ फोडतो: एका गुणा-बेरजेने. Attention
ची जादू आता अंकगणित आहे: न दिसणारं (संबंध) आकड्यात दिसलं.

## स्वतः बघा (5 मिनिटं)

तीन जोड्या हाताने करा: (1,0)·(0,1) = 1x0+0x1 = 0 (लंब,
असंबंधित); (1,1)·(1,1) = 1+1 = 2 (तंतोतंत सारखे, मोठा);
(1,1)·(1,-1) = 1-1 = 0 (लंब!). शेवटचा गंमतीचा: (1,1) आणि
(1,-1) उलटे वाटतात पण dot शून्य = लंब = असंबंधित. आकडा
तुमच्या डोळ्याच्या अंदाजापेक्षा नेमका असतो: हीच गणिताची ताकद.

## विचार करा

थेंबूचं यंत्र आता आर्द्रता आणि ढग यांना **वेगवेगळं महत्त्व**
द्यायला शिकलंय: "पावसासाठी ढग आर्द्रतेपेक्षा जास्त महत्त्वाचे."
म्हणजे त्याला दोन आकडे नुसते जुळवायचे नाहीत, तर **एका
आकड्याचं दुसऱ्यात, महत्त्वानुसार, रूपांतर** करायचंय: (आर्द्रता,
ढग) -> (पाऊस-गुण). "एका दिशेचं दुसऱ्या दिशेत, ठरलेल्या
नियमाने रूपांतर: हे कसं मांडायचं?"

> दिशा फिरवणारं, ताणणारं, रूपांतर करणारं एक यंत्र गणितात
> आहे: आणि तेच AI च्या प्रत्येक थराचं हृदय आहे. त्याचं नाव
> matrix: पुढचा chapter.

# Chapter 1.3 [SPINE]: Matrix: रूपांतराचं यंत्र

थेंबूला (आर्द्रता, ढग) चं (पाऊस-गुण) मध्ये, महत्त्वानुसार, रूपांतर
करायचंय. गणिताचं हत्यार म्हणजे **matrix**: आणि matrix हे
"आकड्यांचा चौकोन" नसून एक **रूपांतर-यंत्र** आहे: बाण आत
टाका, फिरवलेला-ताणलेला बाण बाहेर.

**आधी सोपं: एका आकड्याचं रूपांतर.** थेंबूला वाटतं ढग
आर्द्रतेपेक्षा दुप्पट महत्त्वाचे. तो एक "वजन-यादी" बनवतो:
आर्द्रतेला 1, ढगांना 2. आजची हवा (0.8, 0.6). पाऊस-गुण =

```
0.8 x 1  +  0.6 x 2  =  0.8 + 1.2  =  2.0
```

हे ओळखीचं आहे: हा dot product च आहे (1.2)! वजन-यादी
(1, 2) आणि हवा (0.8, 0.6) यांचा dot = पाऊस-गुण 2.0. म्हणजे
**एका बाणाचं एका आकड्यात रूपांतर = एक dot product.**

**आता matrix: अनेक रूपांतरं एकत्र.** समजा थेंबूला दोन गुण
हवेत: "पाऊस-गुण" आणि "गारवा-गुण." प्रत्येकाची वेगळी वजन-
यादी:

```
पाऊस-गुण  = वजनं (1, 2):   0.8x1 + 0.6x2 = 2.0
गारवा-गुण = वजनं (3, -1):  0.8x3 + 0.6x-1 = 2.4 - 0.6 = 1.8
```

या **दोन वजन-याद्या एकत्र रचल्या** की matrix होतो:

```
        आर्द्रता  ढग
पाऊस  [   1      2  ]
गारवा [   3     -1  ]
```

आणि "हवा-बाण matrix मधून घालवणं" म्हणजे: **प्रत्येक ओळीचा
हवेशी dot product.** आत (0.8, 0.6) टाकलं, बाहेर (2.0, 1.8)
आलं. एक 2-आकड्यांचा बाण दुसऱ्या 2-आकड्यांच्या बाणात
**रूपांतरित.** Matrix = अनेक dot products एका खोक्यात =
एक रूपांतर-यंत्र.

**हीच AI च्या प्रत्येक थराची कृती.** Book 2 चा transformer-मजला
(3.8) आठवा: प्रत्येक थर म्हणजे एक (किंवा अनेक) matrix, जो
येणारा बाण (शब्दाचा अर्थ) घेऊन त्याला नव्या बाणात रूपांतरित
करतो. "यंत्र विचार करतं" म्हणजे प्रत्यक्षात: **बाण -> matrix ->
नवा बाण -> पुढचा matrix -> नवा बाण...** शेकडो वेळा. GPT
मध्ये हे matrices अवाढव्य (शेकडो x शेकडो आकडे) आणि शेकडो
थर, पण **कृती तीच जी थेंबूची**: ओळीचा dot, नवा आकडा. यंत्राचं
"वजन" (Book 2, 2.4: weights) म्हणजे नक्की हेच: या matrices
मधले आकडे. अब्जावधी weights = अब्जावधी matrix-आकडे. **शिकणं
म्हणजे हे matrix-आकडे बरोबर जुळवणं** (Part 3 चा विषय).

## इथे लोक काय चुकीचं समजतात

"Matrix म्हणजे आकड्यांचा नुसता चौकोन/table." घातक अर्धसत्य.
Matrix हे **क्रियापद** आहे, नाम नाही: तो एक **कृती** आहे: "हा
बाण घे आणि असा फिरव-ताण." Excel-सारखा स्थिर table बघितलात
तर matrix कधीच "जाणवणार" नाही; "रूपांतर-यंत्र" म्हणून बघितलात
की AI ची अख्खी रचना उलगडते. दुसरा गैरसमज: "matrix गुणाकार
म्हणजे भयंकर किचकट नियम." नियम एकच, तुम्ही आत्ता केलात:
**ओळीचा येणाऱ्या बाणाशी dot product.** बाकी सगळं याचीच
पुनरावृत्ती.

## नकाशावर

```
1.1  vector = यादी = दिशा     1.2  dot = जवळिकीचं माप
1.3  matrix = रूपांतर-यंत्र (अनेक dot एकत्र); बाण आत ->
     फिरवलेला बाण बाहेर; AI चे weights = matrix-आकडे
```

**सूत्रावर:** matrix हा चष्मा "यंत्राचा थर म्हणजे नक्की काय"
हे दाखवतो: एक रूपांतर, बाणाचं बाणात. "यंत्र विचार करतं" ही
कविता; "बाण matrix मधून जातो" हे गणित. न दिसणारं (विचार)
आकड्यांच्या फिरवणुकीत दिसलं.

## स्वतः बघा (5 मिनिटं)

हा matrix हाताने चालवा: वजनं ओळ-1 (2, 0), ओळ-2 (0, 2),
बाण (3, 5). प्रत्येक ओळीचा dot: 2x3+0x5 = 6; 0x3+2x5 =
10. बाहेर (6, 10): मूळ बाण **दुप्पट** झाला! हा matrix "सगळं
दुप्पट कर" हे रूपांतर करतो. आता ओळी (0,1),(1,0) घ्या, बाण
(3,5): बाहेर (5,3): आकडे **उलटे**! Matrix आकडे बदलून वेगवेगळी
रूपांतरं: फिरवणं, ताणणं, अदलाबदल. खेळून बघा.

## विचार करा

थेंबूचं यंत्र आता एक matrix आहे: हवा आत, गुण बाहेर. पण
खरं यंत्र एका matrix चं नसतं; ते **अनेक matrices एकामागून
एक** असतं (Book 2 चे शेकडो थर). थेंबूला प्रश्न पडला: "मी
हवा पहिल्या matrix मधून घातली, नवा बाण आला; तो दुसऱ्या
matrix मधून घातला... हे अनेक रूपांतरं एकामागून एक: याला
काही एकत्रित अर्थ आहे का? की नुसती साखळी?"

> साखळीला सुंदर अर्थ आहे: अनेक रूपांतरं मिळून **एकच मोठं
> रूपांतर** होतं, आणि तेच AI च्या खोलीचं (depth) रहस्य आहे.
> रूपांतरांची साखळी: पुढचा chapter.

# Chapter 1.4 [DEPTH]: रूपांतरांची साखळी आणि खोली

थेंबूचा प्रश्न: अनेक matrices एकामागून एक: याला एकत्रित अर्थ
आहे का? उत्तर सुंदर आहे, आणि ते AI च्या "खोली" (depth: शेकडो
थर) चं रहस्य उघडतं. [DEPTH]: थोडं खोलात, पण थेंबूसोबत सोपं.

**साखळी म्हणजे काय.** थेंबूची हवा (0.8, 0.6) पहिल्या matrix
A मधून जाते -> नवा बाण; तो दुसऱ्या matrix B मधून -> आणखी
नवा बाण. दोन रूपांतरं, एकामागून एक. गंमत: A नंतर B लावणं
= एकच नवा matrix C लावण्यासारखं (C म्हणजे "आधी A मग B").
म्हणजे **अनेक रूपांतरांची साखळी = एकच (गुंतागुंतीचं) रूपांतर.**
स्वयंपाकाची उपमा: भाजी चिरा -> तळा -> मसाला घाला: तीन
कृती, पण मिळून "एक पदार्थ बनवणं" ही एकच मोठी कृती.

**मग शेकडो थर कशाला, एकच मोठा matrix का नाही?** इथे खरी
गोम आहे, आणि ती समजली की deep learning मधलं "deep" कळतं.
जर मध्ये **काहीच** घडलं नाही (नुसते matrices), तर खरंच शेकडो
थर = एकच matrix (वाया). पण AI मध्ये **प्रत्येक matrix नंतर
एक छोटी वाकडी कृती** घडते: याला "activation" म्हणतात, आणि
ती साखळीला **सरळ रेषेपेक्षा जास्त** बनवते.

**वाकडी कृती का लागते (सर्वात महत्त्वाचा मुद्दा).** matrix फक्त
**सरळ** रूपांतरं करतो: ताणणं, फिरवणं (म्हणून त्याला "linear"
म्हणतात: रेषीय). पण जग सरळ नाही: "आर्द्रता 0.9 च्या **पुढे**
गेली तरच पाऊस" असले **उंबरठे**, **वळणं** matrix ला जमत
नाहीत. म्हणून प्रत्येक थरानंतर एक साधी वाकडी कृती: उदा
"उणे आकडे शून्य कर, धन तसेच ठेव" (याला ReLU म्हणतात:
सर्वात सामान्य). ही छोटी वाकडी कृती नसेल तर शंभर थर = एक
थर (नुसती सरळ साखळी); ती असेल तर शंभर थर **खरोखर**
शंभर पट गुंतागुंतीचं वळणदार रूपांतर शिकू शकतात. **खोली =
सरळ रूपांतरं + वाकड्या कृती, आलटून-पालटून, शंभर वेळा:
म्हणून यंत्र गुंतागुंतीचे नमुने पकडतं.**

**थेंबूवर:** थेंबूचा एक matrix "आर्द्रता + 2xढग" इतकंच सरळ
काढू शकतो. पण "ढग भरपूर **आणि** आर्द्रता उंबरठ्यापुढे तरच
जोरदार पाऊस" हा वाकडा नियम एका matrix ला जमत नाही: दोन
थर + मधली वाकडी कृती लागते. म्हणून खरं यंत्र = अनेक थेंबू-
matrices + वाकड्या कृती: आणि तेच ChatGPT, फक्त अब्जावधी पट.

## इथे लोक काय चुकीचं समजतात

"जास्त थर = आपोआप जास्त हुशार." अर्धसत्य: थर जास्त **आणि**
मधल्या वाकड्या कृती **आणि** नीट शिकवणी (Part 3) असेल तरच.
नुसते matrices रचले (वाकड्या कृतीशिवाय) तर शंभर थर = एक
थर: वाया. आणि उलट: वाकडी कृती हे "यंत्राची जादू" नाही; ती
"उणे शून्य कर" इतकी साधी असू शकते: जादू **खोली आणि
शिकवणीत** आहे, कुठल्या एका कृतीत नाही.

## नकाशावर

```
1.1-1.3  vector | dot | matrix
1.4  साखळी: अनेक रूपांतरं = एक मोठं रूपांतर; पण मधली
     वाकडी कृती (activation) नसेल तर शंभर थर = एक थर;
     खोली = सरळ+वाकडं आलटून-पालटून
```

**सूत्रावर:** हा चष्मा "deep learning मधलं deep का महत्त्वाचं"
हे दाखवतो: खोली म्हणजे रूपांतरं + वाकडी वळणं, वारंवार. न
दिसणारं (यंत्राची गुंतागुंत पकडायची क्षमता) आकड्यांच्या साखळीत
दिसलं.

## स्वतः बघा (5 मिनिटं)

एक वाकडी कृती हाताने: ReLU = "उणे असेल तर 0, धन असेल
तर तसंच." आकडे (3, -2, 5, -1) वर लावा: (3, 0, 5, 0). बघा:
वाईट (उणे) बातम्या गाळल्या, चांगल्या ठेवल्या. आता कल्पना
करा हे प्रत्येक थरानंतर: यंत्र हळूहळू "काय ठेवायचं, काय
गाळायचं" शिकतं. इतक्या साध्या कृतीतून गुंतागुंत जन्मते: हेच
आश्चर्य.

## विचार करा

विभाग 1 संपत आलाय. थेंबूला दिशा (vector), जवळीक (dot),
रूपांतर (matrix), खोली (साखळी) कळलं. पण एक गोष्ट खटकतेय:
"AI मध्ये म्हणतात एका शब्दाचा अर्थ **शेकडो** आकड्यांनी दाखवतात.
दोन आकडे मला कागदावर दिसतात; पण 700 आकडे? इतकी 'जागा'
कशाला? आणि इतक्या मितींत काही विचित्र घडतं का?"

> शेकडो मितींत खरंच विचित्र, आणि उपयोगी, गोष्टी घडतात:
> तिथे जवळ-दूर चा अर्थ बदलतो, आणि म्हणूनच अर्थ साठवता
> येतो. उच्च-मितींचं जग: विभागाचा शेवटचा chapter.

# Chapter 1.5 [SPINE]: हजार मितींचं जग

थेंबूचा प्रश्न: 700 आकडे कशाला, आणि तिथे काय घडतं? हा
chapter उच्च-मितींच्या (high-dimensional) जगाची सफर आहे:
आणि तिथे एक शाप आणि एक वरदान दोन्ही आहेत.

**आधी वरदान: जागा प्रचंड असते.** 2 मितींत (कागद) जागा
मर्यादित: जवळपासच्या गोष्टी गर्दी करतात. पण मिती वाढल्या
की **जागा स्फोटक वाढते.** कल्पना करा: 1 मितीत (रेषा) 10
जागा; 2 मितींत (चौरस) 10x10 = 100; 3 मितींत (घन) 1000;
700 मितींत? 10 च्या 700 घातांक: विश्वातल्या अणूंपेक्षा
अगणित पट जास्त. म्हणून AI ला **प्रत्येक शब्दाला स्वतःची
वेगळी दिशा** द्यायला भरपूर जागा मिळते: लाखो शब्द, प्रत्येकाचा
वेगळा बाण, तरी गर्दी नाही. **अर्थ साठवायला जागा हवी, आणि
मिती ती देतात.** म्हणून embedding शेकडो-मितींचं: दोन मितींत
अख्ख्या भाषेचे अर्थ मावणारच नाहीत.

**आणि सूक्ष्म जादू: दिशांना अर्थ चिकटतात.** उच्च-मितींत असं
घडतं की **वेगवेगळ्या दिशा वेगवेगळे अर्थ** धरतात: एक दिशा
"लिंग" (राजा-राणी), एक "संख्या" (एक-अनेक), एक "काळ" (आज-
काल). म्हणून Book 2 चं गाजलेलं उदाहरण शक्य होतं: **राजा -
पुरुष + स्त्री = राणी** (बाणांची वजाबाकी-बेरीज!). कारण "लिंग-
दिशेत" राजा-वरून-राणीकडे सरकणं म्हणजे तेच जे पुरुष-वरून-
स्त्रीकडे. अर्थाचं अंकगणित: फक्त भरपूर मिती असतील तरच शक्य,
कारण प्रत्येक अर्थ-छटेला स्वतःची दिशा हवी. (हे किती खरं, किती
अतिशयोक्ती: 1.6 त बघू.)

**आता शाप: आपली अंतर्ज्ञान फसते (curse of dimensionality).**
उच्च-मितींत विचित्र गोष्टी घडतात ज्या आपल्या 3-मिती-सराव्या
मेंदूला अशक्य वाटतात: (1) **सगळं सगळ्यापासून दूर होतं:**
इतकी जागा की कुठलेही दोन बाण बहुधा लांबच; "जवळचा शेजारी"
शोधणं अवघड. (2) **जवळपास सगळे बाण जवळजवळ लंब होतात:**
यादृच्छिक दोन बाणांचा dot बहुधा शून्याजवळ. म्हणजे आपलं
"जवळ-दूर" चं भान इथे चालत नाही: गणितावर विसंबावं लागतं,
डोळ्यांवर नाही. म्हणूनच हे पुस्तक: **उच्च-मितींत डोळे आंधळे,
गणित हाच एकमेव चष्मा.**

**थेंबूवर आणि पुढे:** थेंबूचे 2 आकडे कागदावर दिसतात; GPT चे
शेकडो-हजारो आकडे दिसत नाहीत, पण **गणित तेच**: dot product
जवळीक मोजतो (1.2), matrix रूपांतर करतो (1.3): 2 मितींत जे,
तेच 700 मध्ये. फरक एवढाच की 700 मध्ये **जागा भरपूर** (अर्थ
मावतात) पण **डोळे निरुपयोगी** (गणितावर भरवसा). हीच विभाग
1 ची सर्वात मोठी कमाई: **AI च्या मितींना घाबरू नका; त्या
फक्त लांब याद्या आहेत, आणि त्यांचं गणित थेंबूइतकं सोपं आहे:
फक्त डोळ्यांऐवजी आकड्यांवर विश्वास ठेवा.**

## इथे लोक काय चुकीचं समजतात

"शेकडो मिती म्हणजे काहीतरी गूढ, अतिमानवी परिमाण." नाही:
मिती म्हणजे फक्त **यादीतल्या आकड्यांची संख्या.** 700 मिती =
700 आकड्यांची यादी. "चौथी मिती म्हणजे वेळ/जादू" ही विज्ञान-
कथेतली कल्पना इथे लागू नाही; इथे मिती = रकाना, बस. दुसरा
गैरसमज: "उच्च-मितींत आपली भूमिती चालते." उलट: चालत नाही,
म्हणूनच सावध. डोळ्यांचा अंदाज ("हे जवळ दिसतंय") उच्च-मितींत
फसतो; तिथे फक्त dot product सारखी मापं खरी.

## नकाशावर

```
1.1-1.4  vector | dot | matrix | साखळी
1.5  उच्च मिती: जागा स्फोटक (अर्थ मावतात, दिशांना अर्थ);
     पण डोळे फसतात (curse) -> गणितावर भरवसा; मिती =
     यादीची लांबी, गूढ नाही
```

**सूत्रावर:** हा चष्मा सर्वात मोलाचा: उच्च-मितींत **डोळे आंधळे
होतात, गणित हाच एकमेव दृष्टिदाता.** AI समजायला गणित
"पर्याय" नाही, "एकमेव खिडकी" आहे: कारण तिथलं जग बघता
येत नाही, फक्त मोजता येतं.

# Chapter 1.6 [SPINE]: राजा-राणी अंकगणित खरं का [दोन्ही बाजू]

थेंबूचा प्रामाणिकपणाचा प्रश्न: "राजा - पुरुष + स्त्री = राणी"
हे खरंच चालतं का? हा chapter एका गाजलेल्या निकालाचं प्रामाणिक
शव-विच्छेदन आहे: आणि तो स्वतःच "AI-दावे कसे तपासायचे"
याचा धडा आहे.

**दावा काय होता.** 2013 च्या सुमारास (word2vec नावाच्या
कामातून) जगाला धक्का बसला: शब्दांचे बाण (embeddings) असे
निघाले की **अर्थाचं अंकगणित** चालायचं. बाण-भाषेत: राजाचा
बाण घ्या, पुरुषाचा वजा करा, स्त्रीचा जोडा: निकाल राणीच्या
बाणाच्या **खूप जवळ.** तसंच "पॅरिस - फ्रान्स + इटली = रोम"
(राजधान्या), "चालणे - चालला + धावला = धावणे" (काळ). जणू
यंत्राने अर्थाच्या "दिशा" (लिंग-दिशा, देश-दिशा) आपोआप शोधल्या
(1.5). हे खरं आहे: आणि सुंदर आहे.

**पण आता प्रामाणिक दुसरी बाजू (contested):**

```
समर्थक बाजू:  उदाहरणं खरी आहेत; अर्थाला दिशा असते ही
             कल्पना खरी आहे; embeddings मध्ये रचना आहे.
टीकाकार बाजू: प्रत्यक्षात हे इतकं स्वच्छ नाही:
             - निकाल बहुधा "जवळ" येतो, "बरोबर" नाही
               (राणी दुसरी-तिसरी जवळची, पहिली नाही).
             - अभ्यासात दिसलं: उत्तर काढताना "मूळ तीन शब्द
               वगळा" असा नियम लपवलेला असतो; तो काढला तर
               अनेकदा उत्तर मूळ शब्दच येतं (फसवणूक नाही,
               पण जादू कमी).
             - काही नाती छान चालतात (लिंग, राजधानी), बरीच
               अजिबात चालत नाहीत.
निकाल:       अर्थाला-दिशा ही कल्पना खरी आणि मौल्यवान; पण
             "स्वच्छ अंकगणित" ही अतिशयोक्ती. उदाहरण खरं,
             सार्वत्रिक नियम नाही.
```

**यातून खरा धडा (या पुस्तकाचा गाभा):** एक सुंदर, गाजलेलं
AI-उदाहरण घ्या आणि विचारा: "हे **किती वेळा, किती स्वच्छ**
चालतं? की एक चमकदार केस उचलून सगळीकडे लावलीये?" राजा-
राणी हे खरं उदाहरण, पण त्याभोवती जी "यंत्राला अर्थ **कळतो**"
ची कविता रचली गेली ती अतिशयोक्त. गणिताचा चष्मा (हे पुस्तक)
नेमका इथे उपयोगी: तो तुम्हाला "किती जवळ, किती वेळा, कुठला
नियम लपवलाय" हे **मोजायला** लावतो: कवितेवर भुलू देत नाही.
Book 2/4 चं तेच सूत्र: "यावर किती विश्वास, आणि का": इथे
गणिताच्या रूपात.

**आणि हे leverage आहे (Book 4 शी पूल):** जो माणूस "राजा-
राणी भारी!" वर थांबतो तो ग्राहक; जो "हे किती स्वच्छ चालतं,
मूळ दावा काय, तपासलं कोणी" विचारतो तो papers वाचणारा,
आणि तोच top 0.00001 कडे जातो. **AI-गणित शिकण्याचा खरा
फायदा नवं बांधणं नाही; दावे तपासता येणं आहे.** कारण AI-जगात
कवितेचा (आणि विक्रीचा) पूर आहे, आणि गणित हाच एकमेव
गाळणी-चष्मा.

## इथे लोक काय चुकीचं समजतात

"गाजलेलं उदाहरण = सिद्ध झालेला सार्वत्रिक नियम." AI मध्ये
सर्वात महाग गैरसमज: एक चमकदार केस (राजा-राणी, किंवा
कुठलंही viral demo) घेऊन "यंत्र हे नेहमी करतं" मानणं. प्रत्यक्षात
demo हे **निवडलेलं सर्वोत्तम** असतं (Book 4, 5.1 चा "demo
= सोपा ढीग"). प्रामाणिक प्रश्न नेहमी: "सरासरी किती वेळा,
किती स्वच्छ, आणि अपयशं कुठे?" हा प्रश्न विचारणं म्हणजे
गणिताचा चष्मा लावणं.

## नकाशावर

```
1.1-1.5  vector | dot | matrix | साखळी | उच्च मिती
1.6  राजा-राणी: अर्थाला-दिशा खरी, पण "स्वच्छ अंकगणित"
     अतिशयोक्ती; धडा = गाजलेला दावा मोजून तपासा (गणित =
     गाळणी-चष्मा); हेच papers-वाचनाचं leverage
```

**सूत्रावर:** इथे सूत्र पूर्ण वर्तुळ पूर्ण करतं: गणित हा चष्मा
फक्त "AI कसं चालतं" दाखवत नाही; तो "AI-दावे किती खरे"
हेही **मोजायला** लावतो. जे मोजता येतं ते तपासता येतं: आणि
जे तपासता येतं तेच खरं.

## स्वतः बघा (5 मिनिटं)

पुढच्या वेळी कुठलंही "AI ने हे भन्नाट केलं!" चं उदाहरण बघाल
तेव्हा तीन प्रश्न विचारा: (1) हे किती **वेळा** चालतं (एक demo
की हजार वेळा)? (2) "जवळ" की "बरोबर" (जवळपास की नेमकं)?
(3) अपयशं कुठे लपवलीयेत? हे तीन प्रश्न म्हणजे गणिताचा चष्मा,
सूत्रांशिवाय: आणि तेच तुम्हाला भुलणाऱ्या गर्दीतून वेगळं काढतील.

## विचार करा

विभाग 1 खरोखर संपला: दिशांचं जग हातात. थेंबूला बाण, जवळीक,
रूपांतर, खोली, मिती, आणि दावे-तपासणी कळली. पण थेंबूचं मूळ
काम अजून अपुरं: "मी आजची हवा बघून एक 'पाऊस-गुण' काढला
(2.0). पण पाऊस **पडेल की नाही** हे हो/नाही नाही ना: 'किती
शक्यता' असतं. 70% शक्यता म्हणजे काय, आणि गुण-2.0 चं
शक्यतेत रूपांतर कसं?"

# Chapter 2.1 [SPINE]: Probability: विश्वासाचं माप

थेंबूला "पाऊस पडेल" हे हो/नाही न सांगता "70% शक्यता" सांगायचंय.
पण "70%" म्हणजे नक्की काय? इथे probability चा खरा, खोल अर्थ
आहे, आणि तो दोन प्रकारे बघता येतो.

**अर्थ 1: वारंवारता (frequency).** "पाऊस 70% शक्यता" म्हणजे:
"अशी हवा असलेले 100 दिवस घेतले, तर त्यातल्या ~70 दिवशी
पाऊस पडला." भूतकाळातल्या मोजणीतून. फासाची उपमा: फासा
टाकल्यावर 6 येण्याची शक्यता 1/6, म्हणजे "पुष्कळ वेळा टाकलं
तर ~सहावा हिस्सा वेळा 6." हे मोजता-तपासता येतं.

**अर्थ 2: विश्वासाची मात्रा (belief).** पण "उद्या पाऊस" हा तर
एकच दिवस, 100 वेळा घडणार नाही. मग 70% म्हणजे? **"मला
किती खात्री आहे" ची मात्रा:** 0 = अजिबात नाही, 1 = पूर्ण खात्री,
0.7 = बऱ्यापैकी खात्री पण पूर्ण नाही. Probability हे **विश्वासाचं
थर्मामीटर** आहे: 0 ते 1 च्या पट्टीवर. आणि AI साठी हाच अर्थ
मुख्य: यंत्र "पुढचा शब्द 'पाऊस' असण्याची probability 0.7" म्हणतं
म्हणजे "मला 0.7 इतकी खात्री."

**तीन लोखंडी नियम (probability चे, पाठ करा):**

```
1. प्रत्येक शक्यता 0 आणि 1 च्या दरम्यान (कधीच उणे नाही,
   कधीच 1 पेक्षा जास्त नाही).
2. सगळ्या शक्यतांची बेरीज = 1 (काहीतरी घडणारच).
   पाऊस 0.7 -> पाऊस-नाही 0.3; बेरीज 1.
3. probability 0 म्हणजे अशक्य, 1 म्हणजे निश्चित; मध्ये
   सगळी अनिश्चितता.
```

नियम 2 महत्त्वाचा: थेंबूचं यंत्र "पाऊस, ढगाळ, कोरडं" या तीन
शक्यतांना उदा 0.6, 0.3, 0.1 देईल: बेरीज **नेहमी 1.** यंत्र
शक्यता "वाटतं", एकूण 1 चा केक तीन तुकड्यांत.

**आणि इथे Book 2 चं मोठं सत्य नव्या प्रकाशात:** ChatGPT चं
"पुढचा token" म्हणजे नक्की काय? शब्दकोशातल्या **प्रत्येक**
शब्दाला एक probability (बेरीज 1): "the" ला 0.3, "cat" ला
0.05, "पाऊस" ला 0.001... हजारो शब्द, हजारो शक्यता, बेरीज
1. यंत्र एका शब्दाची **खात्री** देत नाही; अख्ख्या शब्दकोशावर
**विश्वास वाटून** देतं. हेच LLM चं गणिती हृदय: आणि म्हणूनच
ते कधीच "नक्की" नसतं, नेहमी "किती शक्यता" असतं. Book 2
चं "यंत्र फासे टाकतं" आता नेमकं दिसतं: शब्दकोशावरच्या
probability-यादीतून एक निवडणं.

## इथे लोक काय चुकीचं समजतात

"70% म्हणजे यंत्राला बऱ्यापैकी माहीत आहे." धोकादायक. Probability
हे यंत्राच्या **आत्मविश्वासाचं** माप आहे, **बरोबरपणाचं** नाही.
यंत्र 0.99 खात्रीने **साफ चुकीचं** सांगू शकतं (Book 2, 5.1:
hallucination = ठाम-खोटं). "किती खात्री" आणि "किती बरोबर"
या दोन वेगळ्या गोष्टी; त्या जुळतात का हे तपासणं म्हणजे
calibration (2.6 च्या पुढे, आणि Book 2, 1.4). आत्मविश्वास =
बरोबरपणा हे गृहीत धरणं म्हणजे ठाम-चुकीच्या यंत्रावर विश्वास
ठेवणं.

# Chapter 2.2 [SPINE]: Distribution: शक्यतांचा डोंगर

थेंबूचा प्रश्न: शक्यतांच्या यादीला आकार असतो का? हो: आणि
त्या आकाराचं नाव **distribution** (वाटणी). तो आकार यंत्राचं
मन उघडून दाखवतो: खात्री की गोंधळ.

**Distribution म्हणजे काय.** सगळ्या शक्यतांची यादी, एकत्र
बघितलेली: एक "आकार." थेंबूची तीन-शक्यतांची यादी दोन वेगळ्या
दिवशी बघा:

```
दिवस A (खात्रीचा):   पाऊस 0.9, ढगाळ 0.08, कोरडं 0.02
दिवस B (गोंधळाचा):   पाऊस 0.4, ढगाळ 0.35, कोरडं 0.25
```

दोन्हींची बेरीज 1 (नियम पाळला). पण **आकार** वेगळा: A मध्ये
एक **तीव्र शिखर** (पाऊस-वर सगळं वजन): यंत्र ठाम. B मध्ये
**सपाट, पसरलेला** डोंगर (तिन्हींत वाटलेलं): यंत्र गोंधळलेलं.
तेच यंत्र, दोन दिवस, दोन मनःस्थिती: आणि distribution चा
आकार ती मनःस्थिती **दाखवतो.** शिखर तीव्र = खात्री; डोंगर
सपाट = अनिश्चितता.

**दोन टोकं (लक्षात ठेवा):** (1) **सर्वात तीव्र:** एका शक्यतेला
1, बाकी सगळ्यांना 0: पूर्ण खात्री, शून्य अनिश्चितता ("नक्की
पाऊस"). (2) **सर्वात सपाट:** सगळ्यांना **सारखीच** शक्यता
(तीन असतील तर प्रत्येकी 0.33): पूर्ण गोंधळ, कमाल अनिश्चितता
("काहीच अंदाज नाही, सगळं सारखं"). खऱ्या यंत्राचं distribution
या दोन टोकांच्या मध्ये कुठेतरी: आणि **किती तीव्र की सपाट**
हेच त्याचा आत्मविश्वास सांगतं.

**हे AI मध्ये कुठे दिसतं:** LLM चं प्रत्येक token हे शब्दकोशावरचं
distribution (2.1). पुढचा शब्द "स्पष्ट" असेल ("भारताची राजधानी
___" -> "दिल्ली" ला 0.95: तीव्र शिखर) तर distribution तीव्र;
"अनेक शक्य" असेल ("मला आवडतं ___" -> हजारो शब्द थोडी-थोडी
शक्यता: सपाट) तर distribution पसरलेलं. आणि इथे एक व्यावहारिक
सोनं: **distribution चा आकार बघून यंत्र किती "खात्रीशीर" आहे
हे कळतं.** सपाट distribution म्हणजे यंत्र गोंधळलंय: तिथे त्याच्या
उत्तरावर कमी भरवसा (hallucination चा धोका जास्त). तीव्र शिखर
म्हणजे यंत्र ठाम (पण ठाम-चुकीचंही असू शकतं: 2.1 चा इशारा).

## इथे लोक काय चुकीचं समजतात

"यंत्र एक उत्तर देतं." नाही: यंत्र **पूर्ण distribution** काढतं
(हजारो शक्यता), मग त्यातून एक निवडतं (2.6 चा softmax/
temperature). तुम्हाला फक्त निवडलेलं दिसतं, पण मागे अख्खा
डोंगर असतो. आणि तो डोंगर **फेकून** दिला जातो हे दुखणं:
कारण त्या डोंगरात "यंत्र किती गोंधळलेलं होतं" ही अमूल्य माहिती
असते, जी अंतिम उत्तरात दिसत नाही. म्हणून calibration-अभ्यास
(Book 2, 1.4) या डोंगराकडे बघतो, उत्तराकडे नाही.

## नकाशावर

```
2.1  probability = विश्वासाचं माप; बेरीज=1
2.2  distribution = शक्यतांचा आकार; तीव्र शिखर=खात्री,
     सपाट=गोंधळ; यंत्राचं मन उघडतं
```

**सूत्रावर:** distribution हा चष्मा यंत्राचा आत्मविश्वास **दृश्य**
करतो: "यंत्र गोंधळलंय" ही भावना "सपाट distribution" या मोजता-
येणाऱ्या आकारात. मोजता आलं, म्हणून वापरता आलं (कमी-खात्रीच्या
उत्तरांना जास्त तपासा).

## स्वतः बघा (5 मिनिटं)

दोन प्रश्न कल्पना करा: "2+2 = ?" (उत्तर distribution: "4" ला
~1.0, बाकी ~0: तीव्र शिखर) आणि "एक चांगलं नाव सुचव" (उत्तर:
हजारो नावांना थोडी-थोडी शक्यता: सपाट). पहिल्यावर यंत्र ठाम,
दुसऱ्यावर मुक्त. तुम्ही AI ला हे दोन प्रश्न विचारून बघा: पहिल्याचं
उत्तर नेहमी तेच, दुसऱ्याचं दर वेळी वेगळं: distribution चा आकार
वर्तनात दिसतो.

## विचार करा

थेंबूचं यंत्र कालपासून शिकतंय, आणि आज सकाळी त्याने अंदाज
लावला: "पाऊस 0.6." पण दुपारी अचानक **नवा पुरावा** आला:
आकाशात काळे ढग दाटले. थेंबूला वाटलं: "आता माझा अंदाज
बदलायला हवा: 0.6 वरून वर. पण **किती** वर? नव्या पुराव्याने
जुनं मत नक्की किती हलवायचं: याचा काही नियम आहे का, की
मनाने ठरवायचं?"

> नव्या पुराव्याने जुनं मत **किती** हलवायचं याचा एक अचूक,
> सुंदर नियम आहे: आणि तो जगातल्या सर्व विज्ञान, वैद्यक,
> आणि यंत्र-शिक्षणाचा पाया आहे. त्याचं नाव Bayes: पुढचा
> chapter, आणि तो या विभागातला सर्वात शक्तिशाली.

# Chapter 2.3 [SPINE]: Bayes: पुराव्याने मत हलवणं

थेंबूचा प्रश्न: नव्या पुराव्याने जुनं मत **किती** हलवायचं? याचं
उत्तर विज्ञानातल्या सर्वात शक्तिशाली कल्पनांपैकी एक आहे. आणि
ती समजायला एक धक्कादायक वैद्यकीय उदाहरण घेऊ: जे बहुतेक
लोक (आणि डॉक्टरही) चुकतात.

**धक्कादायक doctor-test.** एक आजार 1000 माणसांत 1 ला असतो
(दुर्मिळ). त्याची चाचणी 99% "अचूक" आहे. तुमची चाचणी
**positive** आली. तुम्हाला आजार असण्याची खरी शक्यता किती?
बहुतेक म्हणतात "99%." **चुकीचं.** खरं उत्तर ~9% आहे. का, ते
आकडे मोजून बघू (हेच Bayes):

```
1000 माणसं घ्या.
आजारी: 1 (दुर्मिळता). निरोगी: 999.
- आजारी 1: चाचणी 99% बरोबर -> ~1 positive (खरा).
- निरोगी 999: चाचणी 99% बरोबर म्हणजे 1% चुकीची ->
  999 x 0.01 = ~10 जणांना चुकून positive (खोटे).
एकूण positive: 1 खरा + 10 खोटे = 11.
यातले खरे आजारी: 1 पैकी 11 = ~9%.
```

म्हणजे positive येऊनही आजार असण्याची शक्यता फक्त ~9%!
कारण आजार इतका **दुर्मिळ** होता की चाचणीच्या "छोट्या चुका"
(999 पैकी 10) खऱ्या केसपेक्षा जास्त झाल्या. **मूळ दुर्मिळता
(1 in 1000) चा विसर पडला की सगळं चुकतं.**

**Bayes चा गाभा एका वाक्यात:** **नवं मत = जुनं मत (मूळ
शक्यता) + नवा पुरावा, दोन्ही मिळून.** पुरावा जुन्या मताला
पूर्ण उलथवत नाही; तो त्याला **हलवतो**, आणि किती हलवायचं
हे जुनी शक्यता किती होती यावर ठरतं. जुनं मत "आजार दुर्मिळ"
(1/1000) होतं; एका positive ने ते 9% पर्यंत वर नेलं (90 पट
वाढ!), पण 99% पर्यंत नाही (कारण दुर्मिळता प्रचंड होती). दुसरी
positive चाचणी आली तर आता जुनं मत 9% (पहिल्यापेक्षा जास्त),
म्हणून ती अजून वर नेईल. **पुरावा साचत जातो, मत टप्प्याटप्प्याने
सरकतं.**

**थेंबूवर:** थेंबूचं जुनं मत "पाऊस 0.6." नवा पुरावा "काळे ढग"
(जे पावसाच्या दिवशी अनेकदा दिसतात, कोरड्या दिवशी क्वचित).
Bayes म्हणतो: 0.6 वर ढगांचा पुरावा जोडून नवं मत काढ:
म्हणा 0.85. किती वर? ढग पावसाशी किती जोडलेले यावर. मनाने
नाही, **गणिताने.** आणि हेच यंत्र-शिक्षणाचं हृदय: प्रत्येक नवं
उदाहरण म्हणजे पुरावा, जो यंत्राचं "मत" (weights) थोडं हलवतो
(Part 3 चा gradient descent हा Bayes चा चुलतभाऊ).

**हे सर्वत्र आहे:** spam-गाळणी ("हा शब्द spam मध्ये किती वेळा
येतो" वरून email चं मत), वैद्यकीय निदान, न्यायालयातले पुरावे,
आणि AI चा अख्खा अंदाज-खेळ. **Bayes = तर्कशुद्ध मत-बदलाचं
गणित:** आणि जो हे शिकतो तो बातम्या, आकडे, दावे: सगळं
जास्त शहाणपणाने वाचतो.

## इथे लोक काय चुकीचं समजतात

"चाचणी 99% अचूक, positive आलं, म्हणजे 99% आजार." जगातली
सर्वात सामान्य आकडे-चूक (base rate neglect: मूळ-दुर्मिळतेचा
विसर). लोक चाचणीच्या अचूकतेकडे बघतात, आजाराच्या **दुर्मिळतेकडे**
नाही. Bayes शिकवतो: **दुर्मिळ गोष्टीचा पुरावा नेहमी संशयाने
बघा**: कारण दुर्मिळतेमुळे "खोटे positive" खऱ्यांपेक्षा जास्त
असू शकतात. हीच चूक AI मध्येही: "यंत्र 99% खात्रीने म्हणालं"
पण ती गोष्ट मुळात दुर्मिळ/अशक्य असेल तर खात्रीलाही संशयाने
बघा.

## नकाशावर

```
2.1  probability = विश्वासाचं माप   2.2  distribution = आकार
2.3  Bayes: नवं मत = जुनं मत + पुरावा; दुर्मिळतेचा विसर =
     मोठी चूक (doctor-test 9%); पुरावा हलवतो, उलथवत नाही
```

**सूत्रावर:** Bayes हा चष्मा "मत कसं बदलावं" ला **गणित**
देतो: भावनेने नाही, पुराव्याच्या वजनाने. आणि यंत्राचं शिकणं
हेच: पुरावा-पुरावा, मत सरकत जाणं. तर्कशुद्धता म्हणजे Bayes
जगणं.

## स्वतः बघा (5 मिनिटं)

एक बातमी आठवा: "X चाचणीत 95% अचूक!" आता विचारा: ज्या
गोष्टीची चाचणी आहे ती किती **दुर्मिळ** आहे? दुर्मिळ असेल
तर 95% अचूकतेतही बहुतेक positive **खोटे** असू शकतात (doctor-
test). ही एक नजर तुम्हाला आरोग्य-जाहिराती, सर्वेक्षणं, आणि
AI-दावे: सगळं जास्त शहाणपणाने वाचायला लावेल.

## विचार करा

थेंबूला आता एक वेगळाच प्रश्न पडला: "मी शक्यता मोजायला
शिकलो, मत बदलायलाही. पण एक गंमत: जेव्हा माझं distribution
सपाट असतं (सगळं सारखं, गोंधळ), तेव्हा मला 'किती गोंधळ आहे'
हे **एका आकड्यात** सांगता येईल का? 'खात्री' आणि 'गोंधळ'
यांच्यातलं अंतर मोजायचं एक माप?"

> हो, आणि ते माप AI मधलं सर्वात खोल, सर्वात सुंदर आहे:
> **entropy**: आश्चर्याचं/गोंधळाचं माप. आणि तेच Book 2 च्या
> loss चं मूळ आहे. पुढचा chapter.

# Chapter 2.4 [SPINE]: Entropy: आश्चर्याचं माप

थेंबूला "गोंधळ" एका आकड्यात हवाय. गणिताचं उत्तर एका सुंदर
कल्पनेत आहे: **entropy**: आश्चर्याचं माप. आणि ते समजायला
एक खेळ खेळू: विसाव्या प्रश्नांचा.

**20 प्रश्नांचा खेळ (entropy चा आत्मा).** मी एक गोष्ट मनात
धरतो, तुम्ही हो/नाही प्रश्न विचारून ओळखा. जर मी "आठवड्याचा
वार" धरला (7 शक्यता), तर तुम्हाला ~3 प्रश्न लागतात (हुशारीने:
"पहिल्या सहामांत?" वगैरे, अर्धं-अर्धं कापत). जर मी "वर्षातला
दिवस" धरला (365 शक्यता), तर ~9 प्रश्न. **जितक्या जास्त, तितकी
अनिश्चितता जास्त, तितके जास्त प्रश्न.** Entropy म्हणजे नेमकं
हेच: **"ही अनिश्चितता संपवायला सरासरी किती हो/नाही प्रश्न
लागतील"**: गोंधळाचं मोजमाप, प्रश्नांच्या भाषेत.

**थेंबूवर, दोन दिवस:**

```
दिवस A (खात्री): पाऊस 0.9, ढगाळ 0.08, कोरडं 0.02
  -> जवळजवळ नक्की पाऊस; ओळखायला ~शून्य प्रश्न;
     entropy कमी (~0.5).
दिवस B (गोंधळ): पाऊस 0.4, ढगाळ 0.35, कोरडं 0.25
  -> काहीच स्पष्ट नाही; ओळखायला जास्त प्रश्न;
     entropy जास्त (~1.5).
```

(आकडे "bits" मध्ये; नेमकी मोजणी सोडा: **दिशा** पकडा.) तीव्र
distribution (2.2) = कमी entropy = कमी आश्चर्य = ठाम. सपाट
distribution = जास्त entropy = जास्त आश्चर्य = गोंधळ. **entropy
हा distribution च्या "सपाटपणा"चा एक आकडा.**

**"आश्चर्य" का म्हणतो.** जी गोष्ट **नक्की** घडणार (probability
1) ती घडली तर आश्चर्य **शून्य** ("अर्थातच"). जी **दुर्मिळ**
(probability कमी) ती घडली तर आश्चर्य **मोठं** ("अरे, हे कसं!").
Entropy = सरासरी आश्चर्य. खात्रीच्या यंत्राला जग "अपेक्षित"
(कमी आश्चर्य); गोंधळलेल्या यंत्राला जग सतत "धक्कादायक" (जास्त
आश्चर्य). आणि इथे AI चं खोल सत्य: **यंत्र शिकतं म्हणजे जगाचं
आश्चर्य कमी करत जातं**: सुरुवातीला सगळं धक्कादायक (काहीच
अंदाज नाही, प्रचंड entropy); शिकल्यावर "पुढचा शब्द असाच
असणार" (कमी आश्चर्य, कमी entropy). **शिकणं = आश्चर्य कमी
करणं.**

**हे compression शीही जोडलेलं (गंमत):** कमी entropy = कमी
आश्चर्य = अंदाज सोपा = **कमी जागेत साठवता येतं** (zip files
याच तत्त्वावर). आणि म्हणूनच काही संशोधक म्हणतात "समजणं
म्हणजे compression": जितकं चांगलं समजलं, तितकं कमी आश्चर्य,
तितकं आवळता येतं. LLM हे एका अर्थाने इंटरनेटचं आवळलेलं
रूप: कमी entropy मध्ये बसवलेलं जग.

## इथे लोक काय चुकीचं समजतात

"Entropy म्हणजे भौतिकशास्त्रातली अस्ताव्यस्तता (गरम-थंड)."
तिथूनच शब्द आला, पण माहिती-जगात entropy = **अनिश्चितता/
आश्चर्य**, तापमान नाही. आणि दुसरा गैरसमज: "कमी entropy =
चांगलं." नेहमी नाही: यंत्र चुकीच्या गोष्टीवर कमी-entropy (ठाम-
खोटं) असू शकतं (2.1 चा hallucination). Entropy फक्त "किती
ठाम" मोजतं, "किती बरोबर" नाही. ठाम-आणि-चूक ही सर्वात
धोकादायक जोडी.

## नकाशावर

```
2.1-2.3  probability | distribution | Bayes
2.4  entropy = आश्चर्याचं/गोंधळाचं माप (किती हो/नाही प्रश्न
     लागतील); तीव्र=कमी, सपाट=जास्त; शिकणं = आश्चर्य कमी करणं
```

**सूत्रावर:** entropy हा चष्मा "गोंधळ" या अस्पष्ट गोष्टीला
**एका आकड्यात** आणतो. आणि तो आकडा शिकण्याची दिशा दाखवतो:
आश्चर्य कमी करत जा. जे मोजता येतं (आश्चर्य) ते सुधारता येतं
(कमी करत जाणं): सूत्र प्रत्यक्षात.

## स्वतः बघा (5 मिनिटं)

20-प्रश्नांचा खेळ खेळा (कुणासोबत, किंवा मनात): एकदा "आठवड्याचा
वार" (7 शक्यता), एकदा "जगातलं कुठलंही शहर" (हजारो). दुसऱ्याला
किती जास्त प्रश्न लागतात बघा. तो फरक = entropy चा फरक.
आणि लक्षात घ्या: प्रत्येक चांगला प्रश्न अनिश्चितता **अर्धी** करतो
(अर्धं-अर्धं कापणं: Book 6 चा binary search इथे भेटेल): हुशार
प्रश्न = जास्त entropy-कपात प्रति प्रश्न.

(पाऊस पडला) यांच्यातलं अंतर एका आकड्यात कसं मोजायचं?
आणि त्याचा entropy शी संबंध आहे का?"

> आहे, आणि खोल आहे: Book 2 चं loss म्हणजे प्रत्यक्षात
> **cross-entropy**: entropy चंच जुळं भावंडं, जे "यंत्राचा
> अंदाज खऱ्यापासून किती दूर" मोजतं. loss चं खरं रूप: पुढचा
> chapter.

# Chapter 2.5 [SPINE]: Cross-Entropy: Loss चं खरं रूप

थेंबूचा प्रश्न: "चूक (loss)" नक्की काय? Book 2 ने loss ला
"चुकीचं माप" म्हटलं (2.5); आता त्याचं खरं गणिती रूप उघडू:
आणि ते entropy चंच जुळं भावंडं आहे: **cross-entropy.** हे
समजलं की यंत्राच्या शिकवणीचं हृदय दिसतं.

**कल्पना: खऱ्याला तू किती probability दिलीस?** थेंबूने अंदाज
लावला (distribution): पाऊस 0.6, ढगाळ 0.3, कोरडं 0.1. मग
प्रत्यक्षात **पाऊस पडला.** आता चूक कशी मोजायची? सोपं तत्त्व:
**जे खरं घडलं, त्याला यंत्राने किती probability दिली होती?**
पाऊस पडला, यंत्राने पावसाला 0.6 दिलं होतं: बऱ्यापैकी, पण
पूर्ण नाही. जर यंत्राने 0.95 दिलं असतं तर उत्तम (कमी चूक);
0.1 दिलं असतं तर वाईट (मोठी चूक: खऱ्या गोष्टीला यंत्र म्हणत
होतं "अशक्य").

**Cross-entropy loss (गाभा, सूत्राशिवाय):** **खऱ्या घटनेला
यंत्राने दिलेली probability जितकी जास्त, तितकी चूक कमी.**
आणि नातं उलटं-आणि-तीव्र आहे:

```
यंत्राने खऱ्याला दिलं  ->  loss (चूक)
0.9 (छान)              ->  लहान (~0.1)
0.6 (ठीक)              ->  मध्यम (~0.5)
0.1 (वाईट)             ->  मोठा (~2.3)
0.01 (भयंकर)           ->  प्रचंड (~4.6)
```

लक्षात घ्या: probability जसजशी शून्याकडे, तसतशी loss **स्फोटक**
वाढते. का? कारण **"खऱ्या गोष्टीला अशक्य म्हणणं" ही सर्वात
मोठी चूक.** यंत्र 0.9 खात्रीने चुकीचं बोललं (आणि खरं वेगळं
निघालं) तर loss प्रचंड: शिक्षा मोठी. हेच यंत्राला "ठाम-चूक"
पासून परावृत्त करतं (किंवा करायला हवं: hallucination अजून
का उरतं हे Book 2, 5.1). Loss = खऱ्याला दिलेल्या खात्रीची
उलटी शिक्षा.

**Entropy शी नातं (सुंदर):** entropy होतं "यंत्राच्या स्वतःच्या
अंदाजातलं सरासरी आश्चर्य" (2.4). Cross-entropy आहे "खऱ्या
जगाशी ताडून यंत्राला किती आश्चर्य." जर यंत्राचा अंदाज खऱ्याशी
तंतोतंत जुळला तर cross-entropy = entropy (कमीत कमी). जितका
अंदाज खऱ्यापासून दूर, तितकी cross-entropy entropy पेक्षा जास्त:
आणि तो **जास्तीचा भाग म्हणजे यंत्राची चूक.** म्हणून training
म्हणजे: cross-entropy कमी करत नेणं = यंत्राचा अंदाज खऱ्या
जगाच्या जवळ नेणं = आश्चर्य कमी करणं (2.4 चा "शिकणं =
आश्चर्य कमी करणं" आता नेमकं).

**हेच LLM चं संपूर्ण training (Book 2 उघडलं):** अब्जावधी
वाक्यांत, प्रत्येक शब्दाला यंत्र अंदाज लावतं (पुढचा शब्द काय),
खरा शब्द बघतं, आणि **खऱ्या शब्दाला यंत्राने किती probability
दिली** यावरून cross-entropy loss. मग ती कमी करायला weights
थोडे हलवतात (Part 3). ट्रिलियन वेळा. "यंत्र इंटरनेट वाचून
शिकलं" म्हणजे: ट्रिलियन शब्दांवर cross-entropy कमी करत,
आपला अंदाज खऱ्या मजकुराच्या जवळ नेत गेलं. Book 2 चं
"अंदाज-चूक-सुधार" चक्र आता गणितात: चूक = cross-entropy.

## इथे लोक काय चुकीचं समजतात

"Loss म्हणजे यंत्राने किती उत्तरं चुकवली (टक्केवारी)." नाही:
loss हे "किती चुकवली" नाही, "**किती खात्रीने** चुकवली/बरोबर
केली" मोजतं. यंत्र बरोबर उत्तर देऊनही (जर कमी खात्रीने दिलं
तर) थोडी loss घेतं; आणि चुकीचं उत्तर ठाम खात्रीने दिलं तर
प्रचंड loss. म्हणून loss हे उत्तरांच्या **खात्रीचं** माप आहे,
नुसत्या बरोबर-चूक चं नाही. हेच यंत्राला "नुसतं बरोबर" नाही
तर "योग्य आत्मविश्वासाने बरोबर" व्हायला शिकवतं (आदर्शात;
प्रत्यक्षात calibration अपुरं: Book 2, 1.4).

## नकाशावर

```
2.1-2.4  probability | distribution | Bayes | entropy
2.5  cross-entropy = loss चं खरं रूप; खऱ्याला दिलेली
     probability जास्त -> loss कमी; अशक्य-म्हणणं = स्फोटक
     शिक्षा; training = cross-entropy कमी करणं
```

**सूत्रावर:** cross-entropy हा चष्मा "यंत्र शिकतं म्हणजे काय"
हे पूर्ण उघडतो: खऱ्या जगाशी आपला अंदाज ताडून, अंतर (loss)
मोजून, ते कमी करणं. जे मोजता येतं (loss) तेच सुधारता येतं
(कमी करत): सूत्र यंत्र-शिक्षणाच्या केंद्रस्थानी.

## स्वतः बघा (5 मिनिटं)

एक स्वतःची परीक्षा कल्पना करा जिथे तुम्ही प्रत्येक उत्तराला
"किती खात्री" (%) लिहायची. आता cross-entropy चा नियम: बरोबर
उत्तराला 90% खात्री दिली आणि बरोबर निघालं -> छान (कमी
शिक्षा); पण चुकीच्या उत्तराला 90% खात्री दिली -> मोठी शिक्षा.
हा नियम तुम्हाला "खात्री तेवढीच दाखवा जेवढी खरी आहे" शिकवतो:
अति-आत्मविश्वासाला शिक्षा. यंत्रालाही तेच शिकवायचा प्रयत्न,
cross-entropy ने.

काढतं (Part 1: matrix मधून, उदा 2.0, ढगाळ 1.8, कोरडं 0.5).
पण हे 'गुण' कुठलेही आकडे असू शकतात (मोठे, उणे). त्यांचं
0-1 च्या, बेरीज-1 च्या **probability** मध्ये रूपांतर कसं? आणि
मी 'किती धीट अंदाज लावायचा' (नेहमी सर्वात शक्य, की कधी
जोखीम) हे कसं ठरवायचं?"

> गुणांचं probability मध्ये रूपांतर करणारं एक सुंदर यंत्र आहे:
> softmax; आणि "किती धीट" ठरवणारी एक कळ: temperature
> (Book 2 ची तीच!). विभागाचा शेवटचा chapter, दोन्ही एकत्र.

# Chapter 2.6 [SPINE]: Softmax आणि Temperature

थेंबूचे दोन प्रश्न: कुठलेही गुण probability मध्ये कसे बदलायचे,
आणि "किती धीट" कसं ठरवायचं. दोन्हींची उत्तरं एका सुंदर
यंत्रात आणि एका कळीत आहेत: **softmax** आणि **temperature.**
हे विभाग 2 आणि Part 1 ला जोडतात.

**Softmax: गुणांचं probability मध्ये रूपांतर.** थेंबूचे गुण: पाऊस
2.0, ढगाळ 1.8, कोरडं 0.5. हे 0-1, बेरीज-1 मध्ये कसे आणायचे?
Softmax ची तीन पावलं (हाताने, ढोबळ):

```
1. प्रत्येक गुणाचा "स्फोट" (exponential: मोठा गुण जास्त
   मोठा होतो, फरक ठळक होतात):
   पाऊस 2.0 -> ~7.4;  ढगाळ 1.8 -> ~6.0;  कोरडं 0.5 -> ~1.6
2. बेरीज: 7.4 + 6.0 + 1.6 = 15.0
3. प्रत्येकाचा हिस्सा (भागा):
   पाऊस 7.4/15 = 0.49;  ढगाळ 6.0/15 = 0.40;  कोरडं 1.6/15 = 0.11
```

झालं: गुण (2.0, 1.8, 0.5) -> probability (0.49, 0.40, 0.11),
बेरीज 1. **Softmax = कुठलेही आकडे घेऊन probability-वाटणी
बनवणारं यंत्र.** आणि पायरी-1 चा "स्फोट" महत्त्वाचा: तो मोठ्या
गुणाला **अप्रमाणात** जास्त probability देतो (फरक ठळक करतो):
म्हणून "soft-max": सर्वात मोठ्याला झुकतं, पण बाकीलाही थोडं
(पूर्ण max नाही, soft). हेच LLM च्या शेवटच्या पायरीत: शब्दकोशाच्या
गुणांचं (logits) probability मध्ये रूपांतर, प्रत्येक token ला.

**Temperature: "किती धीट" ची कळ (Book 2 ची तीच).** आता
जादूची कळ. softmax च्या आधी सगळे गुण एका आकड्याने **भागा**:
त्याचं नाव temperature (T).

```
T कमी (उदा 0.5): गुण मोठे होतात -> स्फोट तीव्र -> सर्वात
  मोठ्याला अजून जास्त वजन -> distribution तीव्र (2.2) ->
  यंत्र "ठाम", नेहमी सर्वात शक्य निवडतं. (कंटाळवाणं पण सुरक्षित.)
T जास्त (उदा 1.5): गुण लहान होतात -> स्फोट मंद -> सगळे
  जवळ येतात -> distribution सपाट -> यंत्र "धीट/जुगारी",
  कमी-शक्य पर्यायही निवडतं. (सर्जनशील पण जोखमीचं.)
T = 1: मूळ, जसंच्या तसं.
```

म्हणजे temperature ही **entropy ची कळ** (2.4): कमी T = कमी
entropy (ठाम); जास्त T = जास्त entropy (गोंधळ/सर्जनशीलता).
Book 2 मध्ये "temperature = निवडीच्या फाशांची मात्रा" म्हटलं
होतं; आता नेमकं दिसतं: ती softmax च्या तीव्रतेची कळ, म्हणजे
distribution च्या आकाराची कळ.

**सगळं जोडून (विभाग 2 चा कळस): एका token चा पूर्ण प्रवास.**

```
1. matrix-थर (Part 1): शब्दाचा बाण -> गुण-यादी (logits),
   शब्दकोशातल्या प्रत्येक शब्दाला एक गुण.
2. temperature ने भागा: "किती धीट" ठरवा.
3. softmax: गुण -> probability-distribution (बेरीज 1).
4. त्या distribution मधून एक शब्द निवडा (फासे: 2.1).
5. training असेल तर: खऱ्या शब्दाशी ताडून cross-entropy
   loss (2.5) -> weights हलवा (Part 3).
```

Part 1 (बाण, matrix) + Part 2 (probability, softmax, loss):
एकत्र म्हणजे LLM च्या एका पावलाचं **पूर्ण** गणित. थेंबूचं यंत्र
आणि ChatGPT: हाच प्रवास, फक्त आकार वेगळा.

## इथे लोक काय चुकीचं समजतात

"Temperature वाढवली की यंत्र हुशार/सर्जनशील होतं." अर्धसत्य,
धोकादायक. Temperature फक्त "किती कमी-शक्य पर्याय निवडायचे"
ठरवते: जास्त T = जास्त विविधता, **पण जास्त चुका/बरळणंही**
(कमी-शक्य म्हणजे अनेकदा चुकीचं). "सर्जनशीलता" आणि "बरळणं"
दोन्ही जास्त-T चीच फळं: फरक फक्त तुम्हाला कोणतं हवं. तथ्यांच्या
कामाला कमी T (ठाम, अचूक), कल्पक लेखनाला जास्त T (विविध).
कळ हुशारीची नाही, **जोखमीची** आहे.

## नकाशावर

```
2.1-2.5  probability | distribution | Bayes | entropy | cross-entropy
2.6  softmax = गुण -> probability (स्फोट+भागा); temperature =
     धीटपणाची/entropy ची कळ (कमी=ठाम, जास्त=जुगारी);
     पूर्ण token-प्रवास: बाण->गुण->softmax->निवड->loss
```

**सूत्रावर:** softmax+temperature हा चष्मा "यंत्र किती धीट/ठाम"
ही कळ **तुमच्या हातात** देतो: entropy ची कळ फिरवता येते.
आणि पूर्ण Part 1-2 मिळून यंत्राचं एक पाऊल आता संपूर्ण गणित
आहे: कुठेही जादू उरली नाही.

## स्वतः बघा (5 मिनिटं)

अनेक AI-साधनांत "temperature" किंवा "creativity" ची कळ असते.
असेल तर: तोच प्रश्न दोन T ला विचारा (कमी आणि जास्त). कमी
T: उत्तर दर वेळी जवळपास तेच, सुरक्षित. जास्त T: दर वेळी
वेगळं, कधी छान कधी विचित्र. तुम्ही entropy ची कळ प्रत्यक्ष
फिरवताय: distribution तीव्र-सपाट करताय.

# Chapter 3.1 [SPINE]: Derivative: बदलाचा दर

उतार समजायला आधी एक साधी कल्पना: **derivative** (बदलाचा
दर). आणि ती इतकी रोजची आहे की तुम्ही ती वापरता, फक्त नाव
माहीत नाही.

**Derivative म्हणजे काय.** एका आकड्याला थोडं ढकललं, तर
दुसरा आकडा **किती** बदलतो? गाडीचा वेग म्हणजे derivative:
"वेळ थोडा पुढे गेला, तर अंतर किती वाढलं." थेंबूवर: "weight
थोडं वाढवलं, तर loss किती बदलली?" हाच प्रश्न, आणि त्याचं
उत्तर = derivative. एका ओळीत: **derivative = परिणामाचा दर =
"इथे थोडं हललं तर तिथे किती हलतं."**

**आकड्यांनी बघू (थेंबूचं सोपं रूप).** समजा थेंबूचा loss हा एका
weight w वर असा अवलंबून आहे: loss = (w - 3)². म्हणजे w =
3 ला loss शून्य (सर्वोत्तम), आणि w जसजसा 3 पासून दूर, तसतशी
loss वाढते (एक खोरं, तळाशी w=3). आता derivative विचारतो:
"w = 5 ला उभं राहून थोडं हललं तर loss कुठे जाईल?"

```
w = 5:   loss = (5-3)² = 4
w = 5.1: loss = (5.1-3)² = 2.1² = 4.41   (वाढली!)
w = 4.9: loss = (4.9-3)² = 1.9² = 3.61   (घटली!)
```

म्हणजे w = 5 ला: w **वाढवलं** तर loss वाढते; w **घटवलं**
तर loss घटते. Derivative हा दर आणि दिशा दोन्ही सांगतो:
इथे तो **धन** (positive) आहे ("w वाढला की loss वाढते"),
आणि आकार सांगतो किती वेगात. आणि इथे शिकण्याची गुरुकिल्ली:
**loss कमी करायची तर derivative च्या उलट दिशेला जा.**
derivative धन (w वाढला की loss वाढते) -> म्हणून w **कमी**
करा (उताराच्या खाली, w=3 कडे). हेच "उतार उतरणं."

**डोंगराची उपमा (Book 2 चा धुका).** loss = एक डोंगराळ भूभाग,
उंची = चूक. तुम्ही एका जागी (w = 5) उभे, तळ (कमीत कमी
loss) शोधायचाय, पण धुक्यामुळे पूर्ण नकाशा दिसत नाही. Derivative
म्हणजे: **तुमच्या पायाखालचा उतार**: "इथे जमीन कुठल्या दिशेला
झुकलीये, किती तीव्र." उतार कळला की एक पाऊल **खाली** टाका
(loss कमी होईल त्या दिशेला). पुन्हा उतार बघा, पुन्हा पाऊल.
हळूहळू तळाकडे. Derivative = पायाखालच्या उताराचं मोजमाप:
पूर्ण नकाशा नाही, पण पुढचं एक पाऊल पुरेसं.

## इथे लोक काय चुकीचं समजतात

"Derivative म्हणजे किचकट calculus, सूत्रं." मूळ कल्पना साधी:
"इथे थोडं हललं तर तिथे किती हलतं." तुम्ही ती रोज वापरता
(वेग = अंतराचा derivative, प्रवेग = वेगाचा). AI मध्ये लागणारं
derivative फक्त काही मूठभर नियमांचं (कोणतं फार महत्त्वाचं
नाही; कल्पना महत्त्वाची). आणि दुसरा गैरसमज: "derivative
म्हणजे उत्तर." नाही: derivative म्हणजे **दिशा** (पुढचं पाऊल
कुठे), उत्तर नाही: उत्तर मिळतं अनेक पावलं टाकून (3.4).

## नकाशावर


# Chapter 3.2 [SPINE]: Gradient: धुक्यातला डोंगर उतरणं

थेंबूचा प्रश्न: लाखो weights चे उतार एकत्र कसे? उत्तर Part 1
शी जोडतं: सगळ्या weights चे derivatives मिळून एक **बाण**
(vector) होतो, आणि त्याचं नाव **gradient.** हा विभागाचा
मध्यवर्ती शब्द आहे.

**Gradient म्हणजे काय.** एका weight चा derivative = त्या एका
दिशेतला उतार (3.1). पण अनेक weights म्हणजे अनेक दिशा
(थेंबूला 2: आर्द्रता-अक्ष, ढग-अक्ष). प्रत्येक अक्षाचा वेगळा उतार
काढा, त्यांची यादी बनवा: **तोच gradient बाण.** आणि त्याचा
सुंदर गुणधर्म: **gradient बाण नेहमी सर्वात तीव्र चढाच्या दिशेला
दाखवतो.** म्हणजे "इथून सर्वात वेगात **वर** (loss वाढेल) कुठे?"
मग loss कमी करायला? **gradient च्या बरोबर उलट** जा: सर्वात
तीव्र **उताराची** दिशा. याला **gradient descent** (उतार-उतरण)
म्हणतात: पूर्ण यंत्र-शिक्षणाचं इंजिन.

**धुक्यातल्या डोंगराची पूर्ण उपमा (Book 2, 2.6 आता नेमकी).**
तुम्ही धुक्यात डोंगरावर, तळ शोधायचाय (कमीत कमी loss).
पूर्ण नकाशा दिसत नाही. काय करता? (1) पायाखाली चाचपून
बघता: **कुठली दिशा सर्वात तीव्र खाली** (gradient चं उलट).
(2) त्या दिशेला **एक पाऊल** (छोटं, कारण धुकं). (3) नव्या
जागी पुन्हा चाचपा, पुन्हा पाऊल. हळूहळू तळाकडे. हेच gradient
descent: **उतार बघ -> उलट दिशेला पाऊल -> पुन्हा**, हजारो-
लाखो वेळा. यंत्र "शिकतं" म्हणजे नक्की हेच करतं: loss-डोंगरावर
weights-चेंडू धुक्यात, पावलापावलाने तळाकडे.

**थेंबूवर आकड्यांनी (दोन weights).** थेंबूचा loss दोन weights
w1, w2 वर. एका जागी gradient काढला, म्हणा तो बाण (+4,
-2) निघाला. अर्थ: "w1 वाढवला तर loss जोरात वाढेल (+4);
w2 वाढवला तर loss घटेल (-2)." loss कमी करायला **उलट**
जा: w1 **कमी** करा, w2 **वाढवा**, आणि प्रमाणात (4 चा उतार
मोठा म्हणून w1 जास्त हलवा). एक पाऊल:

```
gradient = (+4, -2)   (सर्वात तीव्र चढाची दिशा)
उलट दिशा = (-4, +2)   (सर्वात तीव्र उताराची: इकडे जा)
w1: 5 -> 5 - (थोडं)x4  (कमी करा, जास्त)
w2: 3 -> 3 + (थोडं)x2  (वाढवा, कमी)
```

नवे weights loss किंचित कमी करतात. पुन्हा gradient, पुन्हा
पाऊल. **हेच शिकणं, फक्त 2 ऐवजी अब्जावधी weights आणि
ट्रिलियन पावलं.**

**आणि इथे GPU का लागतो ते नेमकं दिसतं (Book 2 चा कारखाना):**
अब्जावधी weights चा gradient एका पावलात काढणं म्हणजे अब्जावधी
derivatives, अब्जावधी गुणा-बेरीज (Part 1 चे dot products,
matrices). आणि हे ट्रिलियन पावलं. म्हणून हजारो GPU, महिनोन्महिने
(Book 4, 1.1 चं training-bill: आता कळलं कशाचं). "training"
म्हणजे: प्रचंड gradient descent, धुक्यातल्या अवाढव्य डोंगरावर.

## इथे लोक काय चुकीचं समजतात

"Gradient descent यंत्राला 'सर्वोत्तम उत्तर' शोधून देतो." नाही:
तो फक्त **जवळचा खोलगट भाग** शोधतो (local minimum), जगातला
सर्वात खोल नाही. धुक्यात तुम्ही एका दरीत उतराल, पण शेजारी
अजून खोल दरी असू शकते: तुम्हाला दिसत नाही. आश्चर्य हे की
अब्जावधी-मितींच्या डोंगरावर हे बहुधा **पुरेसं चांगलं** निघतं (का,
ते 3.6 चं गूढ). पण "सर्वोत्तम सापडतं" ही चूक: gradient descent
"चांगलं-पुरेसं" शोधतो, "परिपूर्ण" नाही.

## नकाशावर

```
3.1  derivative = एका दिशेतला उतार
3.2  gradient = सगळ्या weights चे उतार एकत्र (बाण); सर्वात
     तीव्र चढाची दिशा -> उलट जा (gradient descent); धुक्यात
     पावलापावलाने तळाकडे = शिकणं
```

**सूत्रावर:** gradient हा चष्मा "अब्जावधी weights एकत्र कसे
सुधारायचे" या अशक्य वाटणाऱ्या प्रश्नाला एका बाणात आणतो:
सर्वात तीव्र उताराची दिशा. जे मोजता येतं (gradient) त्या दिशेने
सगळे weights एकदम सुधारतात: हेच शिकण्याचं इंजिन.

## स्वतः बघा (5 मिनिटं)

डोळे मिटून, एका उतारावर उभं असल्याची कल्पना करा. पायाखाली
जाणवतं: डावा पाय थोडा खाली, उजवा थोडा वर -> म्हणजे उतार
डावीकडे-खाली. तुम्ही सहज डावीकडे पाऊल टाकाल (तळाकडे).
तुमचा पाय हा gradient-sensor आहे; तुमचं पाऊल gradient
descent. यंत्र हेच करतं, फक्त अब्जावधी "पायांनी" (weights)
एकाच वेळी.

## विचार करा

थेंबूचं यंत्र आता एका थराचं समजलं. पण खरं यंत्र **अनेक थरांचं**
(Part 1, 1.4: साखळी). शेवटच्या थरात loss दिसते; पण **पहिल्या**
थरातल्या weight ने त्या loss वर किती परिणाम केला हे कसं
काढायचं? "पहिला थर -> दुसरा -> ... -> शेवटचा -> loss: इतक्या
लांब साखळीत, सुरुवातीच्या एका weight चा शेवटच्या loss वरचा
उतार कसा मोजायचा?"

> हाच deep learning चा सर्वात हुशार भाग, आणि तो एका
> साध्या गुणाकार-नियमाने सुटतो: चूक थरामागून थर, मागे
> वाटत जाणं. त्याचं नाव chain rule / backpropagation:
> पुढचा chapter, विभागाचा गाभा.

# Chapter 3.3 [SPINE]: Chain Rule: चूक मागे वाटणं

थेंबूचा प्रश्न: लांब साखळीत सुरुवातीच्या weight चा शेवटच्या
loss वरचा उतार कसा? उत्तर deep learning चा सर्वात हुशार,
सर्वात सुंदर भाग आहे: **chain rule** (साखळी-नियम), ज्याला
कृतीत **backpropagation** (चूक मागे-वाटणं) म्हणतात.

**कल्पना: परिणामांची साखळी.** एक साखळी: पाऊस कमी -> धरणात
पाणी कमी -> वीज कमी -> कारखाना बंद -> मजूर बेकार. आता
प्रश्न: "पाऊस 10% कमी झाला तर मजुरीवर किती परिणाम?"
उत्तर: **प्रत्येक दुव्याचा दर गुणा.** पाऊस->पाणी चा दर x पाणी->
वीज चा दर x वीज->कारखाना x कारखाना->मजुरी. दरांचा गुणाकार =
टोकापासून टोकाचा परिणाम. **हाच chain rule: साखळीतल्या
प्रत्येक पायरीचा दर (derivative) गुणा, म्हणजे सुरुवातीचा शेवटावरचा
परिणाम मिळतो.**

**यंत्रात: loss मागे वाटणं.** थेंबूचं यंत्र: पहिला थर -> दुसरा ->
शेवटचा -> loss. पहिल्या थरातल्या weight चा loss वरचा उतार
हवाय. Chain rule: **शेवटापासून सुरुवातीकडे, प्रत्येक थराचा दर
गुणत मागे या.** म्हणून याला "back-propagation": loss ची "जबाबदारी"
शेवटच्या थरापासून मागे, प्रत्येक थराला त्याच्या वाट्याची, वाटत
जाणं. जणू loss म्हणते "ही चूक झाली; प्रत्येक थराचा यात किती
हात?": आणि उत्तर मागे-मागे, गुणाकाराने, प्रत्येक weight पर्यंत
पोहोचतं.

**दोन पावलं (हेच पूर्ण training चं यंत्र):**

```
1. पुढे (forward): माहिती आत -> थर-थर -> अंदाज -> loss.
   (थेंबू: हवा -> गुण -> probability -> चूक)
2. मागे (backward): loss -> chain rule ने प्रत्येक थराचा
   दर गुणत मागे -> प्रत्येक weight चा उतार (gradient).
   मग gradient descent ने सगळे weights एक पाऊल सुधार (3.2).
```

पुढे-मागे, पुढे-मागे: ट्रिलियन वेळा. **हेच "यंत्र शिकतं." Forward
ने अंदाज, backward ने दोष-वाटप, मग सुधारणा.** आणि सौंदर्य:
कितीही खोल यंत्र (शंभर थर) असो, chain rule प्रत्येक weight
पर्यंत नेमका उतार पोहोचवतो: फक्त दर गुणत मागे या. Deep
learning शक्य झालं कारण हा एक साधा गुणाकार-नियम अब्जावधी
weights ना एका पावलात सुधारू देतो.

**एक सूक्ष्म धोका (कळून घ्या, नाव पुरे):** दर गुणत-गुणत मागे
जाताना, जर दर सतत **छोटे** (0.1 x 0.1 x 0.1...) असतील तर
गुणाकार जवळजवळ **शून्य** होतो: सुरुवातीच्या थरांपर्यंत उतार
पोहोचतच नाही (ते शिकतच नाहीत): याला "vanishing gradient"
म्हणतात. उलट दर मोठे तर गुणाकार **स्फोटक** (exploding).
खूप-खोल यंत्रं शिकवायला हे मोठे अडथळे होते; आणि transformer
ची काही रचना (residual connections वगैरे) नेमकी हे टाळायला:
म्हणजे Book 2 चा transformer अंशतः या गणिती अडचणीवरचा
उपाय आहे. (खोलात जायची गरज नाही; एवढं कळलं की papers
मधला हा शब्द ओळखीचा होईल.)

## इथे लोक काय चुकीचं समजतात

"Backpropagation म्हणजे यंत्र 'मागे विचार करतं' किंवा 'आठवतं'."
नाही: हे विचार-आठवण नाही, **शुद्ध गुणाकार.** loss पासून मागे,
प्रत्येक थराचा दर गुणत, प्रत्येक weight चा उतार काढणं: यांत्रिक,
भावनाशून्य अंकगणित. "यंत्र स्वतःच्या चुकांतून शिकतं" ही कविता;
"loss चा gradient chain rule ने प्रत्येक weight ला वाटला जातो
आणि weights एक पाऊल सरकतात" हे गणित. Backprop ला बुद्धी
नाही, फक्त गुणाकार आहे.

## नकाशावर

```
3.1  derivative = उतार   3.2  gradient = उतार-बाण, उलट जा
3.3  chain rule/backprop: प्रत्येक थराचा दर गुणत loss मागे
     वाटणं; forward (अंदाज) + backward (दोष-वाटप) = शिकणं;
     vanishing/exploding = खोलीचा अडथळा
```

**सूत्रावर:** chain rule हा चष्मा "खोल यंत्र कसं शिकतं" या
गूढाला एका गुणाकार-नियमात आणतो: चूक मागे वाटा, प्रत्येक
weight ला त्याचा वाटा. जे मोजता येतं (प्रत्येकाचा दोष) ते
सुधारता येतं (प्रत्येकाला एक पाऊल): deep learning चं संपूर्ण
रहस्य एका गुणाकारात.

## स्वतः बघा (5 मिनिटं)

एक साखळी-हिशेब करा: एका दुकानाचा नफा 10% वाढला, दुकानाचा
मालक कंपनीचा 20% भागधारक, कंपनीचा नफा शहराच्या करात
5% योगदान. "दुकान-नफा वाढ शहराच्या करावर किती?": दर
गुणा (0.10 x 0.20 x 0.05 = 0.001, म्हणजे किरकोळ). तुम्ही
आत्ता chain rule केलात: साखळीतले दर गुणून टोकाचा परिणाम.
यंत्र loss साठी हेच करतं, फक्त लाखो दुव्यांचं.

थेंबूला आता सगळे तुकडे कळले: अंदाज (Part 1), चूक (Part 2),
उतार, gradient, backprop. पण थेंबू म्हणतो: "तुकडे कळले, पण
मला **एकदा, संपूर्ण, आकड्यांनी** करून बघायचंय: माझी खरी हवा
घ्या, अंदाज काढा, चूक मोजा, आणि एक weight प्रत्यक्ष सुधारा:
सुरुवातीपासून शेवटपर्यंत, काहीही न वगळता. तरच 'यंत्र शिकतं'
हे माझ्या हाडात मुरेल."

> हीच पुढच्या chapter ची विनंती, आणि विभागाचा कळस: थेंबूवर
> पूर्ण एक शिकवणी-पाऊल, हाताने, खऱ्या आकड्यांनी, एकही
> पायरी न वगळता. यंत्र-शिक्षण डोळ्यांसमोर घडताना बघू.

# Chapter 3.4 [SPINE]: थेंबूला हाताने शिकवू: पूर्ण एक पाऊल

हा पूर्ण पुस्तकातला सर्वात महत्त्वाचा chapter. इथे आपण थेंबूला
**प्रत्यक्ष, हाताने, एका शिकवणी-पावलातून** नेऊ: एकही पायरी न
वगळता, खऱ्या आकड्यांनी. हे एकदा डोळ्यांनी घडताना बघितलं की
"यंत्र शिकतं" हे वाक्य कायमचं उघडं होईल. कागद-पेन घ्या; सोबत
करा.

**थेंबूची रचना (सर्वात सोपी).** थेंबू एका ओळीचं यंत्र:
```
अंदाज p = w1 x आर्द्रता  +  w2 x ढग  +  b
```
w1, w2 = आर्द्रता आणि ढगांना दिलेली महत्त्वं (weights); b =
एक स्थिर सरकवण (bias). आजची माहिती: आर्द्रता = 0.8, ढग =
0.6. सुरुवातीचे (कच्चे, न-शिकलेले) weights: w1 = 1.0, w2 =
1.0, b = 0. खरं घडलं: **पूर्ण पाऊस, म्हणजे लक्ष्य y = 1.**

**पायरी 1: पुढे (forward): अंदाज काढा.**
```
p = 1.0 x 0.8  +  1.0 x 0.6  +  0
  = 0.8 + 0.6
  = 1.4
```
थेंबूचा अंदाज 1.4. पण खरं लक्ष्य 1. म्हणजे थेंबू **अति-आत्मविश्वासाने**
जास्त बोलला (1 हवं होतं, 1.4 दिलं).

**पायरी 2: चूक (loss) मोजा.** सोप्या loss = (अंदाज - खरं)²:
```
loss = (p - y)²  =  (1.4 - 1)²  =  0.4²  =  0.16
```
चूक 0.16. आता ती कमी करायची.

**पायरी 3: मागे (backward): प्रत्येक weight चा उतार (chain
rule, 3.3).** प्रश्न: प्रत्येक weight थोडा बदलला तर loss किती
बदलेल?

```
आधी loss चा अंदाजावरचा दर:
  dLoss/dp = 2 x (p - y) = 2 x (1.4 - 1) = 2 x 0.4 = 0.8

आता अंदाजाचा प्रत्येक weight वरचा दर (p = w1x0.8 + w2x0.6 + b):
  dp/dw1 = आर्द्रता = 0.8
  dp/dw2 = ढग       = 0.6
  dp/db  = 1

chain rule ने गुणा (दर मागे वाटा):
  w1 चा उतार = 0.8 x 0.8 = 0.64
  w2 चा उतार = 0.8 x 0.6 = 0.48
  b  चा उतार = 0.8 x 1   = 0.80
```

तिन्ही उतार **धन** (positive): अर्थ "हा weight वाढवला तर loss
वाढेल." म्हणून तिन्ही weights **कमी** करायचे (उलट दिशा: 3.2).
आणि लक्षात घ्या: w1 चा उतार (0.64) w2 पेक्षा (0.48) मोठा,
कारण आर्द्रता (0.8) ढगांपेक्षा (0.6) जास्त होती: **जो input
मोठा, त्याचा weight जास्त जबाबदार, म्हणून जास्त सुधारणा.**
गणित आपोआप न्याय करतं.

**पायरी 4: सुधारा (gradient descent).** प्रत्येक weight मधून
"पावलाचा-आकार (learning rate) x उतार" वजा करा. पाऊल-आकार
0.1 घेऊ:
```
w1: 1.0 - 0.1 x 0.64 = 1.0 - 0.064 = 0.936
w2: 1.0 - 0.1 x 0.48 = 1.0 - 0.048 = 0.952
b:  0   - 0.1 x 0.80 = 0   - 0.080 = -0.080
```

**पायरी 5: तपासा: चूक कमी झाली का?** नव्या weights ने पुन्हा
अंदाज:
```
p = 0.936 x 0.8 + 0.952 x 0.6 + (-0.08)
  = 0.7488 + 0.5712 - 0.08
  = 1.24
नवी loss = (1.24 - 1)² = 0.24² = 0.0576
```

**बघा: चूक 0.16 वरून 0.0576 वर घसरली!** एका पावलात.
थेंबू 1.4 वरून 1.24 कडे, म्हणजे खऱ्या 1 च्या **जवळ** आला.
हे पुन्हा-पुन्हा (पायरी 1-5) केलं तर थेंबू हळूहळू 1 वर स्थिरावेल:
**तो शिकला.** आणि हेच, नेमकं हेच, ChatGPT ट्रिलियन वेळा
करतं: फक्त 3 weights ऐवजी अब्जावधी, आणि आर्द्रता-ढग ऐवजी
शब्दांचे बाण. **तुम्ही आत्ता, हाताने, यंत्र-शिक्षण केलंत.**

## इथे लोक काय चुकीचं समजतात

"यंत्र-शिक्षण म्हणजे काहीतरी गूढ, अतिमानवी." तुम्ही ते आत्ता
कागदावर केलंत: गुणा, बेरीज, वजा. पाच पायऱ्या. गूढ काहीच
नाही: फक्त अब्जावधी weights आणि ट्रिलियन पावलं, म्हणून GPU
आणि महिने (Book 4, 1.1). "यंत्र जादूने शिकतं" ही कविता संपली;
"forward-loss-backward-update, पुन्हा" हे अंकगणित उरलं. आणि
हीच सर्वात मोठी मुक्ती: **AI मध्ये कुठेही जादू नाही, फक्त
आकडे: आणि आकडे तुम्हाला समजतात.**

## नकाशावर

```
3.1-3.3  derivative | gradient | chain rule
3.4  थेंबू हाताने: forward (अंदाज 1.4) -> loss (0.16) ->
     backward (उतार गुणा) -> update (weights कमी) -> नवी
     loss 0.0576; हेच ChatGPT, फक्त अब्जावधी पट
```

**सूत्रावर:** हा chapter पूर्ण सूत्राचं मूर्त रूप आहे: चूक **मोजली**
(0.16), उतार **मोजला**, म्हणून **सुधारता आली** (0.0576). जे
मोजता येतं ते सुधारता येतं: यंत्र-शिक्षण म्हणजे या एका वाक्याची
ट्रिलियन-पट पुनरावृत्ती.

## स्वतः बघा (5 मिनिटं)

वेगळ्या सुरुवातीच्या weights ने (उदा w1 = 0.5, w2 = 0.5,
b = 0). पाच पायऱ्या चालवा आणि बघा: loss कमी होते का?
(होईल.) एकदा हाताने केलंत की "training" हा शब्द तुमच्यासाठी
कायमचा अंकगणित होईल, जादू नाही: आणि तीच या पुस्तकाची
सर्वात मोठी कमाई.

## विचार करा

थेंबू शिकला. पण एक गोष्ट खटकली: "मी पाऊल-आकार 0.1 घेतला.
जर 0.01 (खूप छोटं) घेतलं असतं तर? किंवा 2 (खूप मोठं)? हे
'0.1' कुठून आलं, आणि ते चुकीचं निवडलं तर काय होतं? आणि
धुक्यातल्या डोंगरावर मी 'खऱ्या' तळाऐवजी एका छोट्या खड्ड्यात
अडकलो तर?"

> पाऊल-आकार (learning rate) हा यंत्र-शिक्षणातला सर्वात
> नाजूक निर्णय आहे: खूप छोटं = कासवगती; खूप मोठं = तळ
> ओलांडून उडी. आणि खड्ड्यात-अडकणं हे खरं दुखणं. दोन्ही:
> पुढचा chapter.

# Chapter 3.5 [SPINE]: पाऊल-आकार आणि अडकणं

थेंबूचे दोन प्रश्न: पाऊल-आकार 0.1 कुठून, आणि खड्ड्यात अडकलं
तर? हे यंत्र-शिक्षणातले सर्वात व्यावहारिक, सर्वात नाजूक मुद्दे
आहेत.

**पाऊल-आकार (learning rate): सर्वात नाजूक कळ.** gradient
descent मध्ये उतार-दिशा ठरली (3.2); पण **किती मोठं पाऊल**
टाकायचं ते learning rate ठरवते (थेंबूचा 0.1). धुक्यातल्या
डोंगराची उपमा:

```
खूप छोटं (0.001): चिमुकली पावलं; तळ गाठायला अनंत काळ
  (कासवगती). training महिने-वर्षं रेंगाळतं, पैसा जळतो.
खूप मोठं (2.0):   अवाढव्य उड्या; तळ ओलांडून पलीकडच्या
  चढावर, मग परत ओलांडून: उड्या मारत भरकटतं, कधीच
  स्थिरावत नाही (किंवा loss स्फोटक वाढते).
योग्य (0.1 आसपास): नीट उतरत, वाजवी वेगात तळाकडे.
```

आणि गंमत: **योग्य learning rate कामागणिक, यंत्रागणिक वेगळा**;
तो शोधायला प्रयोग लागतात (म्हणून तो "hyperparameter": यंत्र
स्वतः शिकत नाही, माणूस/प्रयोग ठरवतो). आधुनिक पद्धती learning
rate **चालता-चालता बदलतात** (सुरुवातीला मोठा: वेगात उतरा;
शेवटी छोटा: तळाशी नाजूक): याला "schedule" म्हणतात. पण
गाभा तोच: **पाऊल खूप छोटं = वाया वेळ; खूप मोठं = भरकटणं;
मधलं सोनं.** आयुष्यातही तेच: सुधारणा खूप हळू = कंटाळा; खूप
आक्रमक = अस्थिरता.

**अडकणं: खऱ्या तळाऐवजी छोटा खड्डा (local minimum).** धुक्यात
उतरताना तुम्ही एका छोट्या खड्ड्यात याल: सगळीकडे वर दिसतं
(उतार शून्य), म्हणून "तळ आला" वाटतं: पण शेजारी अजून खोल
दरी असते, दिसत नाही. यंत्रही असंच "पुरेसं-चांगल्या" जागी थांबू
शकतं, "सर्वोत्तम" नाही (3.2 चा इशारा). हे टाळायला युक्त्या:
(1) **थोडा गोंधळ (randomness):** प्रत्येक पावलाला पूर्ण data
ऐवजी **तुकडा** वापरणं (mini-batch): यामुळे उतारात थोडा
"थरथराट" येतो, जो छोट्या खड्ड्यातून बाहेर ढकलतो: गंमत अशी
की **थोडा गोंधळ शिकण्याला मदत करतो.** (2) **गती (momentum):**
घरंगळत्या चेंडूला गती असते: तो छोट्या खड्ड्यावरून **पुढे**
जातो (जडत्वाने), खऱ्या खोल दरीत जाऊन थांबतो.

**आणि इथे आश्चर्याची गोष्ट (पुढच्या chapter चं बीज):** अब्जावधी-
मितींच्या डोंगरावर, "छोट्या खड्ड्यात अडकणं" ही अपेक्षेपेक्षा
**खूप कमी** समस्या ठरते: बहुतेक "सपाट" जागा सगळ्या दिशांनी
खड्डे नसतात (काही दिशांनी खाली जाता येतं). का हे नीट कुणालाच
माहीत नाही: पण प्रत्यक्षात gradient descent हे "पुरेसं-चांगलं"
आश्चर्यकारकपणे विश्वासाने शोधतं. हे "का चालतं" हे गूढ पुढच्या
chapter चा विषय.

## इथे लोक काय चुकीचं समजतात

"मोठा learning rate = वेगात शिकेल." उलट अनेकदा: खूप मोठा =
तळ ओलांडून भरकटणं, loss **वाढणं**, training कोसळणं. वेग
learning rate वाढवून येत नाही, **योग्य** learning rate ने येतो.
आणि दुसरा गैरसमज: "randomness म्हणजे चूक/गोंधळ, तो टाळावा."
इथे उलट: थोडा नियंत्रित गोंधळ (mini-batch, momentum) यंत्राला
छोट्या खड्ड्यांतून सोडवतो: **कधीकधी थोडी अनिश्चितता हीच
सुटकेची वाट.** (आयुष्यातही: सगळं-ठरलेलं मार्ग कधी स्थानिक-
खड्ड्यात अडकवतो; थोडा प्रयोग बाहेर काढतो.)

## नकाशावर

```
3.1-3.4  derivative | gradient | chain rule | थेंबू हाताने
3.5  learning rate = पावलाचा आकार (छोटं=कासव, मोठं=भरकटणं,
     मधलं सोनं; hyperparameter); अडकणं (local minimum) ->
     थोडा गोंधळ (mini-batch) + गती (momentum) सोडवतात
```

**सूत्रावर:** learning rate हा चष्मा दाखवतो की सुधारणेचा **वेग**
हाही एक नाजूक सौदा आहे (Book 5 चा आत्मा इथे!): खूप हळू
वाया, खूप वेगात अस्थिर. आणि "मोजून सुधारणं" ला योग्य पाऊल-
आकार लागतो: नाहीतर मोजमाप असूनही सुधारणा फसते.

## स्वतः बघा (5 मिनिटं)

कुठलीही सवय सुधारण्याचा विचार करा (व्यायाम, अभ्यास). खूप
छोटं पाऊल (रोज 1 मिनिट) = प्रगती नगण्य, कंटाळा. खूप मोठं
(रोज 5 तास एकदम) = दुसऱ्या दिवशी सोडून देणं (भरकटणं).
योग्य पाऊल (रोज 30 मिनिटं, वाढवत) = टिकाऊ प्रगती. Learning
rate चं तत्त्व तुमच्या स्वतःच्या सुधारणेलाही लागू: आणि 90-दिवस-
roadmap (The Climb) चा वेगही याच तर्काने ठरवा.

## विचार करा

थेंबूला सगळं यंत्र कळलं: अंदाज, चूक, उतार, पाऊल. पण एक
खोल अस्वस्थता उरली: "हे सगळं **चालतं**, मी हाताने बघितलं.
पण **का** चालतं? अब्जावधी weights, धुक्यातला अवाढव्य डोंगर,
आणि तरी यंत्र काहीतरी उपयोगी शिकतं: नुसतं आकडे जुळवत,
कुणी 'अर्थ' न शिकवता. हे इतकं साधं गणित इतकं गुंतागुंतीचं
वर्तन कसं घडवतं? कुणाला तरी नक्की माहीत असेल ना?"

> प्रामाणिक उत्तर तुम्हाला हादरवेल: **नीट कुणालाच माहीत नाही.**
> जगातले सर्वात मोठे मेंदू अजून "हे का इतकं चांगलं चालतं"
> यावर भांडतात. आणि तेच न-कळणं हा विभागाचा सर्वात प्रामाणिक,
> सर्वात मुक्त करणारा धडा आहे. शेवटचा chapter.

# Chapter 3.6 [DEPTH]: हे का चालतं: प्रामाणिक गूढ [दोन्ही बाजू]

थेंबूचा प्रश्न: हे साधं गणित इतकं गुंतागुंतीचं वर्तन का घडवतं?
आणि उत्तर तुम्हाला हादरवेल आणि मुक्तही करेल: **नीट कुणालाच
माहीत नाही.** हा chapter त्या प्रामाणिक गूढाचा, आणि तो पूर्ण
पुस्तकातला सर्वात मोकळा श्वास आहे. [DEPTH]: थोडं तत्त्वज्ञान,
पण महत्त्वाचं.

**गूढ काय आहे.** आपण शिकलो: gradient descent धुक्यात
पावलापावलाने तळ शोधतं. पण गणिती तर्काने अनेक गोष्टी **चालायला
नकोत:**
- अब्जावधी-मितींचा डोंगर म्हणजे अगणित खड्डे: यंत्र एखाद्या
  वाईट खड्ड्यात अडकायला हवं (3.5). पण अडकत नाही. का?
- यंत्राकडे इतके weights की ते training-data नुसतं **घोकून**
  (पाठ करून) टाकायला हवं, नव्या गोष्टींवर फसायला हवं
  (overfitting). पण अनेकदा ते नव्यावरही चांगलं चालतं
  (generalization). का?
- "मोठं यंत्र = जास्त घोकंपट्टी = वाईट" ही जुनी सांख्यिकी-अपेक्षा;
  प्रत्यक्षात मोठं यंत्र **जास्त चांगलं** चालतं (Book 4 चे scaling
  laws). हे जुन्या सिद्धांताच्या **उलट.**

म्हणजे AI **प्रत्यक्षात चालतं**, पण **का इतकं चांगलं चालतं**
याचा पूर्ण, समाधानकारक सिद्धांत जगाकडे नाही. Deep learning
हे विज्ञानापेक्षा **किमया** (alchemy) जास्त आहे: प्रयोगाने काय
चालतं ते माहीत, पण का ते अर्धवट.

**दोन बाजू (हा जिवंत वाद):**

```
"सिद्धांत मागे आहे" बाजू: आपल्याकडे भक्कम गणिती स्पष्टीकरण
   नाही; बरंचसं "हे करून बघितलं, चाललं" (प्रयोग > सिद्धांत).
   काही संशोधक याला अस्वस्थ होतात: "आपण न-समजलेलं यंत्र
   जगात सोडतोय."
"अंशतः समजतंय" बाजू: काही तुकडे कळलेत (उच्च-मितींत खड्डे
   कमी अडकवणारे; थोडा गोंधळ (3.5) मदत करतो; साधेपणाकडे
   झुकाव). पूर्ण चित्र नाही, पण धुकं विरतंय.
निकाल: AI हे "बांधता येतं पण पूर्ण समजत नाही" या विचित्र
   जागी आहे: आणि तेच त्याला रोमांचक आणि थोडं भीतीदायक
   करतं.
```

**हे तुमच्यासाठी मुक्त करणारं का (सर्वात मोठा धडा):** जर
जगातल्या सर्वात मोठ्या मेंदूंनाही "हे का चालतं" पूर्ण माहीत
नसेल, तर **तुम्हाला "सगळं समजायलाच हवं" हा दबाव नाही.**
या क्षेत्रात कुणीच "पूर्ण जाणकार" नाही; सगळे **शिकत, प्रयोग
करत, आश्चर्य करत** पुढे जातायत. म्हणजे तुम्ही "उशिरा आलात,
सगळं आधीच माहीत आहे" ही भीती खोटी: **सीमारेषेवर सगळेच
नवखे आहेत.** आणि दुसरा धडा (Book 4 शी पूल): जिथे सिद्धांत
अपुरा, तिथे **प्रयोग आणि मोजमाप** (evals!) हेच सत्याचं साधन:
म्हणून जो नीट मोजतो-तपासतो तो, सिद्धांत नसतानाही, पुढे जातो.

**आणि सूत्राचं सर्वात खोल रूप:** आपण "मोजता येतं ते सुधारता
येतं" म्हणालो. Deep learning हे त्याचं टोक आहे: **आपल्याला
"का" पूर्ण कळत नाही, पण "किती चूक" मोजता येते, म्हणून
सुधारता येते.** समजून नाही, **मोजून** प्रगती. हे विचित्र वाटतं,
पण मानवजातीने अनेक गोष्टी आधी **वापरल्या**, मग समजल्या
(आग, औषधं, वीज). AI तिथेच आहे: वापरात पुढे, समजुतीत मागे.
आणि त्या दरीत उभं राहायला भीती नको, **नम्रता** हवी: तीच
खरी वैज्ञानिक वृत्ती.

## इथे लोक काय चुकीचं समजतात

"तज्ज्ञांना AI पूर्ण समजतं, फक्त मला नाही." खोटं, आणि म्हणून
घातक (न्यूनगंड देणारं). प्रत्यक्षात frontier वर सगळे अंधारात
चाचपडतायत: papers "आम्हाला आश्चर्य वाटलं की..." ने भरलेली
असतात. आणि उलट गैरसमज: "समजत नाही म्हणजे सगळं थोतांड."
तेही खोटं: चालतं हे मोजता येतं (benchmarks, प्रत्यक्ष वापर).
खरं मधे: **चालतं (सिद्ध), पण का पूर्ण नाही (प्रामाणिक).** ही
नम्र, अचूक भूमिका: आणि तीच तुम्हाला भुलवणाऱ्या दोन्ही
टोकांपासून (अति-भक्ती, अति-तुच्छता) वाचवते.

## स्वतःची परीक्षा (4 प्रश्न, बोलून; उत्तरं खाली)

**1.** "यंत्र शिकतं" चं पूर्ण गणित पाच पायऱ्यांत?

> forward (अंदाज) -> loss (चूक मोजा) -> backward (chain rule
> ने प्रत्येक weight चा उतार) -> update (उताराच्या उलट, learning
> rate ने) -> पुन्हा. loss घसरते. (3.4)

**2.** Gradient बाण काय दाखवतो, आणि आपण काय करतो?

> सर्वात तीव्र **चढाची** दिशा; loss कमी करायला त्याच्या **उलट**
> पाऊल (gradient descent). (3.2)

**3.** Backpropagation म्हणजे "यंत्र मागे विचार करतं" का?

> नाही: शुद्ध गुणाकार: प्रत्येक थराचा दर गुणत loss मागे, प्रत्येक
> weight ला त्याचा दोष-वाटा. बुद्धी नाही, अंकगणित. (3.3)

**4.** "AI का चालतं" चं प्रामाणिक उत्तर, आणि त्याचा धडा?

> पूर्ण कुणालाच माहीत नाही (किमया > विज्ञान); म्हणून सीमेवर
> सगळे नवखे (मुक्त करणारं), आणि जिथे सिद्धांत अपुरा तिथे
> मोजमाप (evals) हेच सत्य. (3.6)

# Chapter 4.1 [SPINE]: Attention आकड्यांनी: पायरी-पायरी

हा chapter म्हणजे पूर्ण पुस्तकाचा कळस: **attention, आकड्यांनी,
हाताने.** Book 2 ने उपमा दिली (query = मागणी, key = पाटी,
value = माल); आता ती उपमा **आकड्यांत** बघू. कागद-पेन घ्या.

**रचना: तीन शब्द, प्रत्येकाला तीन बाण.** एक छोटं वाक्य: "पाऊस
आज पडेल." attention चं काम: प्रत्येक शब्दाने इतर शब्दांकडे
**किती लक्ष द्यायचं** ठरवून, त्यानुसार माहिती मिसळणं. प्रत्येक
शब्दाला तीन बाण (हे matrices ने बनतात, Part 1; इथे तयार
धरू):

```
शब्द    query (q)    key (k)      value (v)
पाऊस    -            (1, 0)       (2, 0)
आज      -            (0, 1)       (0, 2)
पडेल    (1, 0)       (0.5, 0.5)   (1, 1)
```

query = "मला काय शोधायचंय"; key = "माझ्याकडे काय आहे";
value = "मी काय माहिती देईन." आपण **"पडेल" या शब्दाचं
attention** काढू: तो इतर शब्दांकडे किती लक्ष देतो?

**पायरी 1: जुळणी-गुण (query · प्रत्येक key): dot product (1.2).**
```
पडेल·पाऊस = (1,0)·(1,0)   = 1x1 + 0x0   = 1.0   (जुळतं!)
पडेल·आज   = (1,0)·(0,1)   = 1x0 + 0x1   = 0.0   (जुळत नाही)
पडेल·पडेल = (1,0)·(0.5,0.5)= 1x0.5+0x0.5 = 0.5   (थोडं)
```
"पडेल" ची मागणी (1,0) "पाऊस" च्या पाटीशी (1,0) सर्वात जुळते.
गुण: 1.0, 0.0, 0.5.

**पायरी 2: गुणांचं लक्ष-वाटप (softmax, 2.6).** हे गुण probability
मध्ये (बेरीज 1):
```
स्फोट: e^1=2.72,  e^0=1.0,  e^0.5=1.65
बेरीज: 2.72+1.0+1.65 = 5.37
लक्ष: पाऊस 2.72/5.37=0.51,  आज 1.0/5.37=0.19,  पडेल 1.65/5.37=0.31
```
म्हणजे "पडेल" आपलं **51% लक्ष "पाऊस" कडे**, 19% "आज" कडे,
31% स्वतःकडे देतो. हेच "attention weights": कुणाकडे किती
बघायचं.

**पायरी 3: माहिती मिसळा (लक्ष x value यांची बेरीज).** आता
प्रत्येक शब्दाचा value-बाण त्याच्या लक्ष-वाट्याने घ्या, बेरीज करा:
```
output = 0.51 x (2,0) + 0.19 x (0,2) + 0.31 x (1,1)
       = (1.02, 0)   + (0, 0.38)   + (0.31, 0.31)
       = (1.33, 0.69)
```
झालं. "पडेल" चा नवा बाण = **(1.33, 0.69):** मुख्यतः "पाऊस"
च्या माहितीने (2,0) रंगलेला, कारण तिकडे सर्वात जास्त लक्ष.
**हेच attention:** प्रत्येक शब्दाने इतरांकडे लक्ष-वाटून, त्यांची
माहिती स्वतःत मिसळणं. "पडेल" ला आता "पाऊस" चा संदर्भ
कळला: वाक्याचा अर्थ त्याच्या बाणात उतरला.

**हेच ChatGPT करतं, फक्त:** 3 शब्द ऐवजी हजारो, 2-आकड्यांचे
बाण ऐवजी शेकडो-आकड्यांचे, आणि एका "लक्ष-नजरे" ऐवजी अनेक
समांतर (multi-head: प्रत्येक नजर वेगळं नातं बघते: कोण-कुणाशी
व्याकरण, कोण-कुणाशी अर्थ). पण **कृती तीच जी तुम्ही आत्ता
केलीत:** dot (जुळणी) -> softmax (लक्ष) -> weighted sum
(मिसळण). Book 2 चा "मागणी-पाटी-माल बाजार" आता तीन ओळींचं
अंकगणित आहे. Attention चं गूढ संपलं.

## इथे लोक काय चुकीचं समजतात

"Attention म्हणजे यंत्र 'लक्ष देतं', म्हणजे त्याला जाणीव/समज
आहे." नाही: "लक्ष" हा फक्त softmax-चा वाटप-आकडा आहे
(0.51, 0.19, 0.31). यंत्र "बघत" नाही, "जाणत" नाही; ते dot
products चे गुण softmax मधून probability करतं आणि values
ची भारित बेरीज घेतं. "attention" हे काव्यात्मक नाव आहे,
यांत्रिक कृतीला. जाणीव तिथे नाही, फक्त जुळणी-वाटप-मिसळण
आहे. (हा भेद Book 2 च्या "यंत्राला समज आहे का" वादाचा गाभा.)


सर्वात गूढ यंत्र आता तीन ओळींचं अंकगणित. न दिसणारं (यंत्र
शब्दांचा संदर्भ कसा जोडतं) पूर्ण आकड्यांत दिसलं. जादू कायमची
संपली; समज उरली.

# Chapter 4.2 [DEPTH]: Softmax-Scaling का लागतं

थेंबूचा प्रश्न: attention मध्ये गुण आधी का भागतात? हा छोटा
पण सुंदर मुद्दा आहे, आणि तो "papers मधले विचित्र भागाकार"
समजायला किल्ली आहे. [DEPTH]: बारीक, पण एका खऱ्या नमुन्याचं
स्पष्टीकरण.

**समस्या: मोठे बाण = मोठे गुण = अति-तीव्र softmax.** 4.1 मध्ये
बाण छोटे (2 आकडे) होते, गुण छोटे (1.0, 0.5). पण खऱ्या यंत्रात
बाण शेकडो आकड्यांचे. dot product म्हणजे शेकडो गुणाकारांची
बेरीज (1.2): जितके जास्त आकडे, तितकी बेरीज **मोठी** होते.
गुण 1-2 ऐवजी 20-50 होतात. आणि मोठे गुण softmax मध्ये
घातले तर?

```
छोटे गुण (1, 0, 0.5): softmax -> (0.51, 0.19, 0.31): मऊ वाटप
मोठे गुण (10, 0, 5):  softmax -> (0.99, 0.00, 0.01): अति-तीव्र!
```

मोठे गुण softmax ला **टोकाला** नेतात: जवळजवळ सगळं लक्ष
एकावर, बाकीला शून्य (distribution अति-तीव्र, entropy जवळजवळ
शून्य: 2.4). हे वाईट का? दोन कारणं: (1) यंत्र फक्त एकाच
शब्दाकडे बघतं, बाकीचा संदर्भ गमावतं (मऊ मिसळण हवं). (2)
आणि गंभीर: शिकवणीत **gradient जवळजवळ शून्य** होतो
(vanishing: 3.3): कारण अति-तीव्र softmax चा उतार सपाट,
म्हणून weights हलतच नाहीत, यंत्र शिकत नाही.

**उपाय: गुणांना बाणाच्या-आकाराच्या मुळाने भागा.** transformer
चा नियम: dot-गुणांना **root(d)** ने भागा (d = बाणातल्या
आकड्यांची संख्या). बाण 64 आकड्यांचा तर root(64) = 8 ने भागा;
100 आकड्यांचा तर 10 ने. का हे नेमकं? गणिती कारण: बाण
मोठे झाले की dot-गुण साधारण root(d) पटीने वाढतात; म्हणून
root(d) ने भागलं की गुण पुन्हा "वाजवी" आकारात येतात (1-2
च्या आसपास), softmax मऊ राहतो, शिकणं सुरळीत. एका ओळीत:
**scaling म्हणजे बाण कितीही मोठे असोत, attention चे गुण
वाजवी ठेवणं, म्हणजे softmax मऊ आणि शिकणं जिवंत.**

**हे शिकण्याचा खरा फायदा (papers-वाचन):** transformer च्या
मूळ paper चं नावच "scaled dot-product attention" आहे. आता
तुम्हाला "scaled" का ते नेमकं कळलं: तो root(d) चा भागाकार,
आणि तो का लागतो. papers मध्ये असे शेकडो "छोटे तांत्रिक
तपशील" असतात जे भीतीदायक दिसतात पण **प्रत्येकामागे असंच
एक साधं व्यावहारिक कारण** असतं ("हे न केलं तर हे बिघडतं").
गणिताचा चष्मा तुम्हाला ते कारण शोधायला शिकवतो: आणि मग
paper भीतीदायक न राहता "समस्या-उपाय" ची यादी होतं.

## इथे लोक काय चुकीचं समजतात

"Paper मधली प्रत्येक सूत्र-सजावट म्हणजे खोल, दुर्बोध गणित."
बहुतेकदा उलट: प्रत्येक तपशीलामागे एक साधं, व्यावहारिक "नाहीतर
हे बिघडतं" असतं (इथे: नाहीतर softmax तीव्र, शिकणं मरतं).
papers अवघड **दिसतात** कारण संक्षिप्त भाषा आणि प्रतीकं; पण
आत बहुधा तुम्हाला समजणारी अभियांत्रिकी-कारणं. "हे प्रतीक
का आहे" विचारत गेलं की paper उलगडतं. भीती प्रतीकांची असते,
कल्पनांची नाही.

## नकाशावर

```
4.1  attention आकड्यांनी: dot -> softmax -> weighted sum
4.2  scaling: मोठे बाण -> मोठे गुण -> अति-तीव्र softmax (शिकणं
     मरतं); उपाय root(d) ने भागा -> गुण वाजवी, softmax मऊ;
     papers चे तपशील = "नाहीतर हे बिघडतं"
```

**सूत्रावर:** scaling हा छोटा चष्मा मोठा धडा देतो: AI मधला
प्रत्येक तांत्रिक तपशील एका मोजता-येणाऱ्या समस्येचा उपाय
आहे. जे बिघडतं ते मोजता आलं (तीव्र softmax, मेलेला gradient),
म्हणून उपाय (भागाकार) सापडला: सूत्र papers च्या तळाशीही.

पहिल्याचा softmax मऊ (तिन्हींना थोडं); दुसऱ्याचा जवळजवळ
(1, 0, 0). बघा: गुण मोठे केले की softmax टोकाला जातो. हेच
scaling टाळतं. आकड्यांचा "आकार" softmax च्या मऊपणावर किती
परिणाम करतो, ते डोळ्यांनी दिसेल.

# Chapter 4.3 [SPINE]: एक Transformer-मजला, पूर्ण

थेंबूचा ChatGPT होण्याचा क्षण. एक पूर्ण transformer-मजला, सगळे
तुकडे जोडून, एका बाणावर पायरी-पायरी. Book 2 चा "बाजार +
एकांत-खोली" आता आकड्यांच्या प्रवाहात.

**मजल्याचे चार अवयव (एका शब्द-बाणावर):** एक शब्द-बाण आत
येतो; मजला त्याला चार पायऱ्यांतून नेतो, नवा (जास्त-समजलेला)
बाण बाहेर.

```
पायरी 1: ATTENTION (बाजार): शब्द इतर शब्दांकडे लक्ष-वाटून
   त्यांची माहिती मिसळतो (4.1). "पडेल" -> (1.33, 0.69),
   "पाऊस" चा संदर्भ आत आला. आउटपुट: संदर्भ-रंगलेला बाण.

पायरी 2: जोडणी (residual): मूळ बाण + attention-आउटपुट (बेरीज).
   का? म्हणजे मूळ माहिती हरवत नाही (attention ने फक्त
   "भर" घातली, मूळ पुसलं नाही); आणि हेच खोल यंत्रात gradient
   जिवंत ठेवतं (3.3 चा vanishing टाळतो). "जुनं ठेवून नवं जोडा."

पायरी 3: एकांत-खोली (feed-forward): आता प्रत्येक शब्द एकटा,
   एका छोट्या 2-थरी यंत्रातून (matrix -> वाकडी कृती ReLU ->
   matrix: Part 1, 1.3-1.4). इथे शब्द बाजारात मिळालेली
   माहिती "पचवतो", स्वतःपुरता विचार करतो. + पुन्हा जोडणी.

पायरी 4: ताळमेळ (normalization): बाणातले आकडे खूप मोठे/
   लहान होऊ नयेत म्हणून त्यांना "वाजवी" पट्ट्यात आणणं
   (scaling चा भाऊ, 4.2): पुढच्या मजल्याला स्वच्छ बाण मिळो.
```

आत बाण, बाहेर बाण: **पण बाहेरचा बाण "जास्त समजलेला"**
(संदर्भ मिसळलेला + पचवलेला + नीटनेटका). आणि मग तोच बाण
**पुढच्या मजल्यात**, तिथे पुन्हा चार पायऱ्या, आणि पुढच्या...
GPT मध्ये असे **शेकडो मजले.** प्रत्येक मजला बाणाला थोडं जास्त
अर्थ देतो: पहिले मजले व्याकरण-सारखं उथळ, वरचे मजले खोल
अर्थ-तर्क. शेवटी शेवटच्या बाणातून पुढच्या token ची probability
(softmax, 2.6). **हेच ChatGPT चं एक पाऊल, पूर्ण.**

**थेंबू ते ChatGPT (पूर्ण प्रवास एका दृष्टिक्षेपात):**
```
थेंबू:    2 आकडे -> 3 weights -> 1 अंदाज (एक ओळ)
मजला:    बाण -> attention + जोडणी + एकांत + ताळमेळ -> बाण
ChatGPT: शब्द -> बाण (embedding) -> शेकडो मजले ->
         शेवटचा बाण -> softmax -> पुढचा token -> पुन्हा
```

तुकडे तेच जे थेंबूचे: बाण (Part 1), dot-matrix (Part 1),
softmax-probability (Part 2), आणि हे सगळं शिकलं gradient
descent-backprop ने (Part 3). **कुठेही नवीन जादू नाही; फक्त
थेंबूचे तुकडे, अब्जावधी पट, शेकडो मजले उंच.** जो थेंबू समजला
तो ChatGPT समजला: फरक आकाराचा, तत्त्वाचा नाही. हीच पूर्ण
पुस्तकाची सर्वात मोठी कमाई: **AI ही थेंबूची मोठी आवृत्ती आहे,
वेगळं जग नाही.**

## इथे लोक काय चुकीचं समजतात

"शेकडो मजले म्हणजे यंत्र शेकडो पट 'जास्त हुशार/जागरूक'."
मजले जास्त = जास्त **टप्प्याटप्प्याने अर्थ-शुद्धीकरण**, जागरूकता
नाही. प्रत्येक मजला तेच चार यांत्रिक अवयव चालवतो; "समज"
कुठल्याही एका मजल्यात नाही, ती अनेक साध्या रूपांतरांच्या
साखळीतून **उगवते** (emergence: Book 2, 3.9). "मजला विचार
करतो" ही उपमा; "मजला बाणावर चार गणिती कृती करतो" हे
सत्य. आणि हेच का इतकं चांगलं चालतं: पूर्ण कुणालाच माहीत
नाही (3.6): नम्रता कायम.

## नकाशावर

```
4.3  transformer-मजला: attention (बाजार) + जोडणी (residual) +

     थेंबू ते ChatGPT: तेच तुकडे, अब्जावधी पट
```

**सूत्रावर:** हा chapter पूर्ण चष्मा-प्रवासाचा कळस: ChatGPT चं
हृदय आता थेंबूच्या तुकड्यांचं बनलेलं दिसतं. सर्वात गुंतागुंतीचं
यंत्र सर्वात साध्या कृतींची उंच रचना आहे: आणि ती रचना तुम्ही
आता वाचू शकता.

# Chapter 4.4 [SPINE]: Scaling Laws: सरळ रेषेचं गणित

थेंबूचा प्रश्न: यंत्र मोठं केलं की हुशारी अंदाजपत्रे वाढते: हे
कसं, आणि "सरळ रेषा" कशाची? Scaling laws हे AI मधलं सर्वात
आश्चर्यकारक, आणि व्यावहारिकदृष्ट्या सर्वात महत्त्वाचं गणित आहे
(Book 4 चा अख्खा उद्योग यावर उभा).

**निरीक्षण: आकार वाढवा, चूक अंदाजपत्रे घटते.** संशोधकांना
आढळलं: यंत्र मोठं करा (जास्त weights), data वाढवा, compute
वाढवा: आणि loss (चूक, 2.5) **गुळगुळीत, अंदाजपत्रे** घटते.
इतकी अंदाजपत्रे की छोट्या यंत्रांवरून **मोठ्या यंत्राची चूक आधीच
भाकीत** करता येते (म्हणून labs अब्जावधी खर्चण्याआधी छोट्या
प्रयोगांतून "हे मोठं यंत्र किती चांगलं होईल" ठरवतात). हे विलक्षण:
गुंतागुंतीचं वर्तन, पण त्याची चूक एका साध्या नियमाने पडते.

**"सरळ रेषा" कशाची: log-log आलेख.** साध्या आलेखावर (आकार
विरुद्ध चूक) रेषा वाकडी येते. पण **दोन्ही अक्ष "log" मध्ये**
घेतले (म्हणजे 1, 10, 100, 1000 समान अंतरावर: गुणाकाराचे
टप्पे, बेरजेचे नाही) तर ती वाकडी रेषा **सरळ** होते. याचा अर्थ:
**आकार 10 पट केला की चूक ठराविक टक्क्याने घटते; पुन्हा 10
पट, पुन्हा तेवढीच टक्केवारी.** हा "power law" (घात-नियम):
निसर्गात सर्वत्र (भूकंपांचे आकार, शहरांची लोकसंख्या, संपत्तीचं
वाटप). AI ची चूकही याच कुळात: गुणाकाराच्या टप्प्यांत गुळगुळीत
घट.

**पण इथे कठोर सत्य (आणि आशा):** रेषा सरळ, पण **खाली झुकती**:
प्रत्येक 10-पट सुधारणा **आधीच्याइतकीच टक्केवारी** देते, म्हणजे
**निरपेक्ष सुधारणा घटत जाते** (returns diminish). 100 वरून
1000 (10x) ने जेवढी सुधारणा, 1000 वरून 10000 (पुन्हा 10x,
पण 9000 चा प्रचंड खर्च!) ने तेवढीच टक्केवारी: म्हणजे पुढची
प्रत्येक सुधारणा **प्रचंड महाग.** म्हणूनच Book 4 (2.7) चा
"scaling वळलं": नुसतं मोठं करत राहणं परवडेनासं झालं, म्हणून
खर्च नव्या जागी (post-training, विचार-वेळ) वळला. Scaling
मेलं नाही; **घात-नियमाची किंमत असह्य झाली, म्हणून वाट
बदलली.**

**हे तुमच्यासाठी का महत्त्वाचं:** (1) scaling laws समजले की
"पुढचं यंत्र किती चांगलं" या चर्चा तुम्ही आकड्यांनी वाचता,
hype ने नाही. (2) "AI अनंत वाढेल" (घात-नियम विसरून) आणि
"AI थांबलं" (एका सपाटीकडे बघून) दोन्ही अतिरेक ओळखता:
खरं मधे, घातनियमाच्या झुकत्या रेषेवर. (3) आणि सर्वात खोल:
**एका साध्या रेषेने अब्जावधींचे निर्णय ठरतात** (labs किती
खर्चायचं ठरवतात): गणिताचा चष्मा किती शक्तिशाली, याचं हे
टोक.

## इथे लोक काय चुकीचं समजतात

"Scaling laws म्हणजे यंत्र मोठं केलं की अनंत हुशार होईल."
घात-नियमाची झुकती रेषा हेच नाकारते: सुधारणा **घटत** जाते,
आणि खर्च **स्फोटक** वाढतो. आणि उलट गैरसमज: "एका सुधारणेचा
वेग मंदावला = scaling मेलं." नाही: रेषा अजून सरळ (सुधारणा
सुरू), फक्त निरपेक्ष घट लहान आणि खर्च मोठा. दोन्ही टोकं
(अनंत-आशा, संपूर्ण-निराशा) घातनियम न समजल्याने येतात.
रेषा वाचता आली की दोन्ही भ्रम विरतात.

## नकाशावर

```
4.1-4.3  attention | scaling(softmax) | transformer-मजला
4.4  scaling laws: आकार 10x -> चूक ठराविक % घट (घात-नियम);
     log-log आलेखावर सरळ-झुकती रेषा; सुधारणा घटती, खर्च
     स्फोटक -> "scaling वळलं"; रेषा वाचा, hype नको
```

**सूत्रावर:** scaling laws हा सर्वात भव्य चष्मा: AI च्या भवितव्याचा
अंदाज एका सरळ रेषेत मोजता येतो. जे मोजता येतं (चूकीचा कल)
त्यावर अब्जावधींचे निर्णय ठरतात: गणित इथे भविष्यवाणीचं साधन
होतं.

## स्वतः बघा (5 मिनिटं)

एक घात-नियम रोजचा: तुमच्या अभ्यासात/कौशल्यात पहिले 10
तास मोठी झेप देतात; पुढचे 10 कमी; पुढचे 10 अजून कमी
(diminishing returns). पण थांबत नाही: प्रत्येक "दुप्पट मेहनत"
ठराविक सुधारणा देतच राहते, फक्त लहान. AI ची चूकही असंच
वागते. तुमच्या 90-दिवस-प्रवासालाही (The Climb) हेच लागू:
सुरुवात झपाट्याने, नंतर संथ-पण-सतत.

# Chapter 4.5 [SPINE]: Paper वाचण्याची कला

पूर्ण पुस्तकाची खरी परीक्षा: एक खरा AI-paper उघडून वाचणं.
कारण top 0.00001 ची सीमारेषा नेमकी हीच: papers स्वतः वाचता
येणं. आणि हे chapter सांगतं की ती भीती **रचनेची** आहे, बुद्धीची
नाही: आणि रचना शिकता येते.

**आधी दिलासा: papers तुमच्यासाठीच लिहिलेली नाहीत.** AI-papers
तज्ज्ञांनी तज्ज्ञांसाठी, संक्षिप्त, प्रतीकांनी भरून लिहिलेली असतात:
वाचकाला घाबरवायला नाही, पण **तसाच परिणाम** होतो. म्हणून
पहिला नियम: **paper "समजलं नाही" म्हणजे तुम्ही कमी नाही;
paper दुर्बोध भाषेत आहे.** आणि दुसरा: **पहिल्यांदा 100% समजायचं
नसतंच**; अनुभवी संशोधकही paper 3-4 वेळा, वाढत्या खोलीने
वाचतात.

**वाचनाचा क्रम (छापून ठेवा): बाहेरून आत.** paper पहिल्या
ओळीपासून शेवटपर्यंत वाचू नका (तिथेच लोक बुडतात). ऐवजी
थरांनी:

```
थर 1 (5 मिनिटं): फक्त शीर्षक + सारांश (abstract) + निष्कर्ष
   (conclusion) + आकृत्यांचे कॅप्शन. प्रश्न: "हे कुठलं दुखणं
   सोडवतात, आणि निकाल काय?" (Book 1-4 चं जुनं सूत्र!)
थर 2 (15 मिनिटं): प्रस्तावना (intro) + प्रत्येक विभागाचं
   पहिलं वाक्य. प्रश्न: "त्यांची मुख्य कल्पना काय, आधीच्यापेक्षा
   वेगळं काय?"
थर 3 (खोल, गरज असेल तर): पद्धत (method) + आकडे नीट.
   इथे गणित येतं: आणि आता तुमच्याकडे चष्मा आहे: dot,
   softmax, gradient, attention: बहुतेक प्रतीकं ओळखीची.
```

बहुतेक papers साठी थर 1-2 पुरतात ("हे काय, का, किती चांगलं").
थर 3 फक्त जे तुम्ही खरंच वापरणार/खोदणार त्यासाठी. **90%
मूल्य पहिल्या 20 मिनिटांत**; उरलेलं 10% साठी तास.

**प्रतीकांना घाबरू नका (सर्वात मोठा अडथळा).** paper मधली
भीतीदायक सूत्रं बहुधा तुम्हाला **आता माहीत असलेल्या** गोष्टीच:
"softmax(QK^T / root(d)) V" हे भयंकर दिसतं, पण तुम्ही ते
आत्ता वाचू शकता: Q,K,V = query-key-value बाण (4.1); QK^T =
query-key चे dot products (जुळणी-गुण); /root(d) = scaling
(4.2); softmax = लक्ष-वाटप (2.6); V = values ची भारित बेरीज.
**अख्खं attention एका ओळीत, आणि प्रत्येक तुकडा तुम्हाला माहीत.**
हीच पूर्ण पुस्तकाची कमाई: प्रतीक बघून घाबरण्याऐवजी "हा कुठला
ओळखीचा तुकडा" विचारणं. एक अनोळखी प्रतीक आलं तर थांबा,
शोधा, तो एक तुकडा समजून घ्या: paper तुकड्यांचं बनलेलं आहे,
अभेद्य भिंत नाही.

**आणि सर्वात मोठा गुपित (Book 4 शी पूल): AI आता paper
वाचायला मदत करतं.** अडलेलं प्रतीक/परिच्छेद AI ला विचारा
"हे सोप्या भाषेत समजाव": पण **आंधळेपणाने नाही**: तुमच्या
चष्म्याने त्याचं उत्तर **तपासा** (Book 4 चं evals-भान). AI +
तुमचा गणिती पाया = papers ची भीती कायमची संपते. जो हे
जोडतो (पाया + AI-मदत + तपासणी) तो कुठलंही नवं संशोधन,
आठवड्याच्या आत, वाचू-समजू शकतो: आणि तेच top 0.00001 चं
खरं रहस्य: **नवं ज्ञान स्वतः पचवण्याची यंत्रणा.**

## इथे लोक काय चुकीचं समजतात

"Papers फक्त PhD-वाल्यांसाठी; मी वाचूच शकत नाही." खोटं,
आणि आत्म-पराभवी. papers दुर्बोध **भाषेत** आहेत, दुर्बोध
**कल्पनांचं** नाहीत (बहुतेकदा): आणि भाषेचा अडथळा थर-वाचन +
चष्मा + AI-मदत ने ओलांडता येतो. आणि उलट: "मी एक paper
वाचलं, सगळं समजलं, आता मी तज्ज्ञ." एक paper = एक तुकडा;
खरी समज अनेक papers, प्रयोग, वेळ यांतून. नम्रता दोन्ही
बाजूंनी: "वाचू शकतो" (आत्मविश्वास) आणि "सगळं कळलं नाही"
(प्रामाणिकपणा): दोन्ही एकत्र.

## नकाशावर

```
4.1-4.4  attention | scaling | transformer | scaling laws
4.5  paper वाचन: बाहेरून-आत (abstract->intro->method); 90%
     मूल्य 20 मिनिटांत; प्रतीक = ओळखीचे तुकडे; AI-मदत +
     तपासणी = भीती संपली; हेच top-thinker चं रहस्य
```

**सूत्रावर:** paper-वाचन हा सर्वात व्यावहारिक चष्मा-क्षण: गणित
शिकण्याचा खरा फायदा नवं बांधणं नाही, **जगातलं नवं ज्ञान
स्वतः वाचता येणं.** आणि जे स्वतः वाचता-तपासता येतं, त्यावर
कुणाच्या "सांगण्यावर" विसंबावं लागत नाही: तीच खरी बौद्धिक
स्वातंत्र्य.

## स्वतः बघा (5 मिनिटं)

"Attention Is All You Need" (transformer चा मूळ paper, 2017:
जगातलं सर्वाधिक-cited AI-paper) चा फक्त abstract शोधून वाचा
(एक परिच्छेद). बघा: किती शब्द तुम्हाला आता ओळखीचे (attention,

आता अर्धं वाचता येतं. हीच प्रगती: आणि थर-1 वाचन इतकंच.

पूर्ण पुस्तक संपत आलंय. थेंबू ChatGPT झाला, आणि थेंबूचा

# Chapter 4.6 [SPINE]: अंतिम परीक्षा

नियम आधीसारखेच: पुस्तक न उघडता, **बोलून** उत्तर द्या; गाभा
खाली. हेतू गुण नाही: **गणिताचा चष्मा मुरला का** हे बघणं.

**भाग अ: गणित मुरलं का (5 प्रश्न)**

**1.** "यंत्राला शब्दाचा अर्थ कसा कळतो" चं पूर्ण गणिती उत्तर?

> अर्थ = दिशा; शब्दाला आकड्यांचा बाण (embedding); जवळच्या
> दिशा = जवळचे अर्थ; जवळीक = dot product ने मोजतात. (1.1,
> 1.2, 1.5)

**2.** "यंत्र शिकतं" पाच पायऱ्यांत, आणि "चूक" नक्की काय?

> forward (अंदाज) -> loss (cross-entropy: खऱ्याला दिलेली
> probability) -> backward (chain rule ने प्रत्येक weight चा
> उतार) -> update (उलट उतार, learning rate) -> पुन्हा. (2.5,
> 3.3, 3.4)

**3.** Attention तीन कृतींत?

> dot (query-key जुळणी-गुण) -> softmax (लक्ष-वाटप) ->
> weighted sum (values ची भारित मिसळण). (4.1)

**4.** "AI मोठं केलं की हुशार" चं गणित, आणि दोन्ही टोकांचे भ्रम?

> scaling laws: आकार 10x -> चूक ठराविक % घट (घात-नियम,
> log-log सरळ-झुकती रेषा); सुधारणा घटती + खर्च स्फोटक. भ्रम:
> "अनंत वाढ" आणि "पूर्ण थांबलं" दोन्ही रेषा न वाचल्याने. (4.4)

**5.** "AI का चालतं" चं प्रामाणिक उत्तर?

> पूर्ण कुणालाच माहीत नाही (किमया > विज्ञान); सीमेवर सगळे
> नवखे; समजून नाही, मोजून प्रगती. (3.6)

**भाग ब: थेंबू ते ChatGPT, आणि leverage (5 प्रश्न)**

**6.** softmax मध्ये गुण आधी का भागतात (scaling)?

> मोठे बाण -> मोठे dot-गुण -> अति-तीव्र softmax -> gradient
> मरतो, शिकणं थांबतं; root(d) ने भागून गुण वाजवी, softmax मऊ. (4.2)

**7.** transformer-मजल्याचे चार अवयव?

> attention (बाजार: संदर्भ मिसळणं) + जोडणी (residual: जुनं
> ठेवून नवं) + एकांत (feed-forward: पचवणं) + ताळमेळ (norm).
> शेकडो मजले. (4.3)

**8.** थेंबू आणि ChatGPT यांत तत्त्वाचा फरक आहे का?

> नाही: तेच तुकडे (बाण, dot, matrix, softmax, gradient), फक्त
> 3 weights ऐवजी अब्जावधी, शेकडो मजले उंच. फरक आकाराचा,
> तत्त्वाचा नाही. (4.3)

**9.** भीतीदायक सूत्र (उदा softmax(QK^T/root(d))V) समोर आलं तर?

> तुकड्यांत फोडा: Q,K,V=बाण, QK^T=dot-जुळणी, /root(d)=scaling,
> softmax=लक्ष, V=भारित बेरीज = attention. प्रत्येक तुकडा
> ओळखीचा; प्रतीकाला घाबरू नका, तुकडा शोधा. (4.5)

**10.** गणित शिकण्याचा **खरा** उपयोग काय (नुसतं "समजलं" पलीकडे)?

> papers/दावे **स्वतः वाचता-तपासता येणं**: कुणाच्या सांगण्यावर
> विसंबावं लागत नाही. "समजणाऱ्या" कडून "तपासणाऱ्या" कडे,
> "ऐकणाऱ्या" कडून "वाचणाऱ्या" कडे: तेच leverage (Book 4, 9.2).
> (4.5, 1.6)

---

आणि आता **खरी** अंतिम परीक्षा: वरचे दहा नाही, **खालचा एक**,
ज्याचं उत्तर पुस्तकात नाही, फक्त तुमच्याकडे आहे.

पुस्तकाच्या सुरुवातीला (front matter) एक भीती होती: "गणित
म्हणजे सूत्रं-घोकंपट्टी, माझ्या आवाक्याबाहेर." आता, थेंबूला हाताने
शिकवल्यावर, attention आकड्यांनी काढल्यावर, तो कागद पुन्हा
बघा. भीती कुठे गेली? बहुधा तिची जागा एका शांत आत्मविश्वासाने
घेतली:

> "AI मध्ये कुठेही जादू नाही. फक्त आकडे: बाण, गुणाकार,
> बेरीज, उतार. आणि आकडे मला समजतात. म्हणून AI मला
> समजतं: उपमेने नाही, **गणिताने.** आणि जे मला गणिताने
> समजतं, त्यावर मी कुणाच्या 'सांगण्यावर' विसंबत नाही: मी
> स्वतः तपासतो. हीच माझी उरलेली, न-नकलता-येणारी ताकद."

थेंबूपासून ChatGPT पर्यंतचा प्रवास हेच शिकवतो: **सर्वात
गुंतागुंतीचं यंत्रही सर्वात साध्या कृतींची उंच रचना आहे**, आणि
त्या साध्या कृती तुम्हाला येतात. जादू संपली; चष्मा उरला.

## शेवटचं "स्वतः बघा" (आयुष्यभराचं)

आजपासून, कुठलंही AI-सूत्र, कुठलाही "यंत्र हे करतं" चा दावा,
कुठलाही paper: तीन प्रश्न विचारा: **"याखालचं गणित कुठलं,
आणि ते मला माहीत असलेल्या तुकड्यांचं बनलंय का?"** (Part 1-3),
**"हा दावा किती वेळा, किती स्वच्छ चालतो: मोजलंय का?"** (1.6),
आणि **"हे मी स्वतः वाचून-तपासू शकतो, की फक्त ऐकतोय?"**
(4.5). हे तीन प्रश्न तुम्हाला AI-गर्दीतल्या कवितेतून आणि विक्रीतून
कायमचे वेगळे काढतील: कारण तुमच्याकडे चष्मा आहे, आणि
चष्मा असलेला माणूस भुलत नाही: तो बघतो.

# सूत्र-पत्र: सगळं गणित एका पानावर (भिंतीवर लावा)

(थेंबूचा ChatGPT होण्याचा पूर्ण नकाशा, एका पानात.)

**दिशांचं जग (Part 1):**

```
vector       आकड्यांची यादी = दिशा (बाण); अर्थ = दिशा
dot product  जोडीने गुणा + बेरीज = जवळिकीचं माप
             सारखे->मोठा, लंब->शून्य, उलटे->उणे
matrix       रूपांतर-यंत्र (अनेक dot); बाण आत, फिरवलेला बाण बाहेर
             weights = matrix-आकडे
साखळी+खोली   रूपांतर + वाकडी कृती (ReLU), वारंवार = खोली
उच्च मिती    जागा स्फोटक (अर्थ मावतात); डोळे फसतात, गणित खरं
```

**शक्यतांचं जग (Part 2):**

```
probability  विश्वासाचं माप (0-1); बेरीज=1; खात्री-बरोबर वेगळे
distribution शक्यतांचा आकार; तीव्र=खात्री, सपाट=गोंधळ
Bayes        नवं मत = जुनं मत + पुरावा; दुर्मिळतेचा विसर = चूक
entropy      आश्चर्याचं माप; शिकणं = आश्चर्य कमी करणं
cross-entropy loss = खऱ्याला दिलेल्या खात्रीची शिक्षा
softmax+temp गुण -> probability (स्फोट+भागा); temp = धीटपणा-कळ
```

**उताराचं जग (Part 3):**

```
derivative   बदलाचा दर; पायाखालचा उतार
gradient     सगळ्या weights चे उतार (बाण); उलट जा = शिकणं
chain rule   दर गुणत loss मागे वाटणं (backprop)
थेंबू-पाऊल   forward(अंदाज) -> loss -> backward(उतार) ->
             update(उलट, learning rate) -> पुन्हा
का चालतं     पूर्ण कुणालाच माहीत नाही; मोजून प्रगती
```

**परत AI कडे (Part 4):**

```
attention    dot(जुळणी) -> softmax(लक्ष) -> weighted sum(मिसळण)
scaling      root(d) ने भागा: softmax मऊ, शिकणं जिवंत
transformer  attention + जोडणी + एकांत + ताळमेळ; शेकडो मजले
scaling laws आकार 10x -> चूक % घट (घात-नियम, log-log रेषा)
paper-वाचन   बाहेरून-आत; प्रतीक = ओळखीचे तुकडे; AI-मदत+तपास
```

**थेंबू ते ChatGPT (एका ओळीत):**

```
शब्द -> बाण(embedding) -> [attention+एकांत] x शेकडो मजले
     -> शेवटचा बाण -> softmax -> पुढचा token -> पुन्हा
शिकलं: gradient descent + backprop, ट्रिलियन पावलं.
तेच थेंबूचे तुकडे, अब्जावधी पट. जादू नाही, आकडे.
```

**तीन आयुष्यभराचे प्रश्न:**

```
1. याखालचं गणित कुठलं, माझ्या तुकड्यांचं बनलंय का? (Part 1-3)
2. हा दावा किती वेळा, किती स्वच्छ चालतो: मोजलंय का? (1.6)
3. हे मी स्वतः वाचून-तपासू शकतो, की फक्त ऐकतोय? (4.5)

सूत्र: गणित म्हणजे न दिसणारं दाखवणारा चष्मा.
जे मोजता येतं ते सुधारता येतं; ते तपासताही येतं.
```

---

**पुस्तक संपलं.** थेंबू ChatGPT झाला, आणि तुमच्या हातात
चष्मा आला. आता कुठलंही AI-यंत्र बघाल तेव्हा जादू दिसणार
नाही: बाण, गुणाकार, उतार दिसतील. आणि जादू न दिसणारा
माणूस भुलत नाही: तो बांधतो, तपासतो, आणि पुढे जातो.

चष्मा; हा इथे संपतो. सुरू करा.
