# Chapter 4.2 [SPINE]: टिकवणं: "वापरतच नाही" वरचं औषध

## आधी अंदाज लिहा

```
1. छोटे धंदे software सोडून का देतात: चालत नाही
   म्हणून की आणखी कशाने? ______________________
2. retainer 12 महिने टिकवायचं सर्वात स्वस्त हत्यार
   काय असेल? __________________________________
```

## आधी कटू आकडे

छोट्या धंद्यांना विकलेलं software जगभर याच वेगाने गळतं:
**महिन्याला 3-7% गिऱ्हाईकं सोडतात** [पक्कं: SaaS-क्षेत्राचे
प्रसिद्ध benchmark]: म्हणजे वर्षाला 30-50%+. कारणांची
यादी बोलकी आहे:

```
1. धंदाच बंद पडतो (छोट्या धंद्यांची वर्ष-मृत्यूदर मोठी:
   तुमचा दोष नाही, पण तुमचा retainer जातो)
2. मालक स्वतःच्या खिशातून देतो: प्रत्येक महिन्याला
   "हे चालू ठेवू का?" चा प्रश्न नव्याने
3. आणि सर्वात मोठं: वापर आटतो. यंत्र चालू असतं:
   पण यादी कुणी वाचत नाही, data कुणी भरत नाही:
   मग "कशाला देतोय पैसे?" -> बंद.
```

तिसरं कारण नीट बघा: **यंत्र चुकलं म्हणून नाही; माणूस
विसरला म्हणून.** म्हणजे औषधही तंत्राचं नाही, सवयीचं आहे.

## औषध: तीन सवय-खिळे

```
खिळा 1: रोजचा एक आकडा, आपोआप, WhatsApp वर.
   रोज सकाळी 9 ला मालकाला यंत्राकडून एकच ओळ:
   "काल: 4 आठवणी गेल्या, ₹12,000 वसूल, 2 नव्या
   चौकश्या." एक ओळ: यादी नाही, dashboard नाही
   (dashboard कुणी उघडत नाही; WhatsApp सगळे
   वाचतात: 1.5). हा खिळा यंत्रालाच बांधून द्या: मालकाच्या
   सवयीचं काम यंत्राने करणं हीच खरी automation.
   (हे Book 11, 4.4 चा आकडे-फलक: मालकाच्या मापात.)
खिळा 2: महिन्याची 15-मिनिटांची भेट (retainer-चा भाग
   म्हणूनच सांगितलेली): पुरावा-पान (4.1) + "पुढच्या
   महिन्यात एक छोटी सुधारणा" ठरवणं. या भेटीची तीन
   कामं: वापर जिवंत, नातं जिवंत, आणि वाढ-विक्रीचं
   दार ("हे पण होईल का?" इथेच जन्मतं: 2.2 च्या
   खिशातल्या गळत्या इथेच विकल्या जातात).
खिळा 3: staff ला मालक बनवा. यंत्र वापरणारी खरी
   व्यक्ती बहुधा staff असते (receptionist, पोरगा, munshi).
   तिला 30-मिनिटांची शिकवणी + तिचं नाव यंत्राच्या
   यादीत ("रमेश-दादांसाठी रोजची यादी") + तिची अडचण
   पहिल्यांदा सोडवणं. staff यंत्राचा शत्रू झाला ("हे
   माझ्या जागेवर आलंय") तर यंत्र मरतं; मित्र झाला
   ("माझं काम सोपं झालं") तर तुमचा वकीलच झाला.
```

## Retainer वाढवायचा जिना (टिकला की चढायचं)

```
महिना 1-3: विकलेलं एक काम रुजवणं (भाव ₹4K समजा)
महिना 4: पहिली वाढ-विक्री: खिशातली दुसरी गळती
   ("उत्तर-bot पण लावू? +₹2K"): नवा करार-कागद!
महिना 7+: तिसरं काम / मोठी जोडणी: retainer ₹8-10K
वर्षाला: भाव-फेरी: "काम वाढलंय, पुढच्या वर्षापासून
   ₹__ होईल" (नव्या गिऱ्हाईकांना आधीच जास्त भाव:
   जुन्यांना सौम्य वाढ: नांगर आठवा 2.6)
```

एक गिऱ्हाईक असं वाढवत नेलं की वर्ष-2 त तोच ₹10K/
महिना = एकट्याचा ₹1.2L/वर्ष: **नवं दार शोधण्यापेक्षा
जुनं दार खोल करणं स्वस्त** (Book 11 चं LTV-सत्य
गल्लीत).

## इथे लोक चुकतात

**"Churn झाला की नवं गिऱ्हाईक शोधून भरून काढू."**

गणित करा: महिन्याला 1 नवं विकता आणि 12 पैकी 1
गळतं, तर वर्षभर धावून जागेवरच (गळकी बादली: Book 11,
3.3). आणि गळण्याची किंमत फक्त retainer नाही: **वस्तीतली
खबरही आहे** ("त्याने लावलं होतं, काढून टाकलं"). म्हणून
नियम: **नवी विक्री आठवड्याला एक दार; पण चालू गिऱ्हाईकाचा
प्रश्न आला तर तो आधी.** क्रम कायम: टिकवणं > वाढवणं >
नवं. (आणि गळालाच कुणी, तर 15-मिनिटांचा निरोप-फोन:
"काय चुकलं?" चं उत्तर = फुकट course: 2.7 चं post-
mortem इथेही.)

## नकाशा

```
4.1  delivery: 30 दिवस
4.2  टिकवणं: churn 3-7%/महिना हे जग-सत्य; मृत्यू-कारण
     #1 = वापर आटणं (माणूस, तंत्र नाही); तीन खिळे:
     रोजची एक-ओळ, महिन्याची 15-मि भेट, staff-मैत्री;
     retainer-जिना 4K -> 8-10K; क्रम: टिकवणं > वाढवणं
     > नवं
```

**सूत्राशी:** इथेही सूत्रच: मालकाला रोज **दिसणारा** निकाल
(एक-ओळ संदेश) = टिकणारा retainer. न दिसणारं काम
न झालेल्या कामासारखंच असतं.

## स्वतः करून बघा (field-काम 22)

तुमच्या master-demo त "रोजची एक-ओळ" आत्ताच बांधा:
यंत्राने रोज सकाळी पाठवायचा संदेश-साचा लिहा (कालचे
3 आकडे). हा demo-भेटीतही दाखवायचा: "आणि रोज
सकाळी तुम्हाला हे येईल" हे वाक्य विक्रीतही जादू करतं
(मालकाला "माझं नियंत्रण राहील" वाटतं).
