# Chapter 2.2 [SPINE]: घराणं: Fable, Mythos, Opus, Sonnet, Haiku

Claude हे एक model नाही; **घराणं** आहे. आणि घराणं समजायची
गुरुकिल्ली: ही हुशारीची शिडी नसून **सौद्यांची पट्टी** आहे (Book 5
चं सूत्र: प्रत्येक रचना-निर्णय = सौदा): शक्ती विरुद्ध किंमत-वेग.

**आजची पट्टी (Aug 2026, अधिकृत भाव प्रति 10 लाख tokens):**

```
model       काम                    input   output  संदर्भ
Haiku 4.5   हलकं-जलद-स्वस्त:        $1      $5      200K
            वर्गीकरण, सोपे प्रश्न
Sonnet 5    रोजचा घोडा: बहुतेक      $2      $10     1M
            कामं, उत्तम code
Opus 5      जड विचार: कठीण         $5      $25     1M
            प्रश्न, मोठे agents
Fable 5     शिखर: सर्वात खोल        $10     $50     1M
            reasoning, लांब कामं
(जोडीला: cache-वाचन = input च्या 10%; batch = 50% सूट:
Book 4, 6.2 ची पैसा-हत्यारं इथेही)
```

नावांचा अर्थही सौदाच सांगतो: Haiku (छोटी कविता: चपळ),
Sonnet (मध्यम: बांधीव), Opus (महाकाव्य: जड). 2026 त वरची
पायरी नवी: **Mythos-वर्ग** (महाकथा): Opus च्याही वर.

**Fable 5 आणि Mythos 5: एकच यंत्र, दोन दारं (June 9, 2026).**
या पुस्तकाचा लेखक हाच Fable 5 आहे: म्हणून ही गोष्ट आतल्या
माहितीने नव्हे, जाहीर नोंदींनीच सांगतो: **खाली यंत्र एकच आहे.**
फरक दारांचा: **Fable 5** = सगळ्यांसाठी, पण तीन पहारेकरी-
classifiers सोबत: cyber-हल्ले, जैव-रसायन, आणि model-चोरी
(distillation) या दिशांचे प्रश्न आले की ते **आपोआप Opus 4.8
कडे वळवले जातात** (कंपनीच्या नोंदीनुसार <5% sessions ना
स्पर्श). **Mythos 5** = तेच यंत्र पहारे कमी करून: पण फक्त
**Project Glasswing** मधून: निमंत्रण+NDA+सरकार-सल्ला असलेला
विश्वास-कार्यक्रम: ~150 संस्था, 15+ देश: security-कंपन्यांना
cyber-पहारे शिथिल (जाहीर श्रेय: मोठ्या OS-browsers मधल्या
हजारो गंभीर त्रुटी या भागीदारांनी Mythos ने शोधल्या). Book 4
(7.3) ची dual-use कात्री आठवा: **तीच क्षमता ढाल आणि तलवार**:
Anthropic चं उत्तर = क्षमता लपवू नका; **दारं वेगळी करा**:
विश्वास तपासून तलवार द्या, बाकीच्यांना ढाल.

**आणि नाट्य: सरकारचा महिना.** June 12, 2026: अमेरिकी
सरकारच्या export-निर्देशाखाली Fable 5 **थांबवावा लागला**
(इतिहासात पहिल्यांदाच एक फ्लॅगशिप AI-model सरकारी आदेशाने
बंद); June 30: नियंत्रणं उठली, July 1: परत चालू. धडा (विभाग
1.2 च्या DeepSeek-निबंधाशी जोडा): **frontier-AI आता chips-
सारखं भू-राजकीय साधन आहे**: पुरवठादार-जोखमीच्या यादीत
'सरकार' हा रकाना मीराने (आणि तुम्ही) आता कायम ठेवायचा
(Part 3 च्या hedge-शिस्तीत परत येईल).

**पट्टी वाचण्याच्या दोन नोंदी:** (1) **1M संदर्भ-खिडकी** (Haiku
सोडून): म्हणजे अख्खं पुस्तक-कोडबेस एका दमात (Book 4, 3.1
च्या context-भिंतीची नवी सीमा); output 128K पर्यंत. (2) **किंमती
उतरत्या इतिहासात बघा:** Sonnet 5 चा $2/$10 भाव 'सुरुवातीचा'
म्हणून आला आणि कायमचाच केला गेला: विभाग 1.4 चं मापाचं
गणित भावात उतरताना दिसतंय.

**मीरावर:** मीराची जुनी सवय: "सगळं मोठ्याच model ला दे"
(महाग) किंवा "सगळं स्वस्त्यालाच" (कमकुवत). पट्टी कळल्यावर
ती **कामाला model जोडते**: गिऱ्हाईकांची पत्रं-वर्गीकरण = Haiku;
रोजचं code = Sonnet 5; app ची रचना-निर्णय / कठीण bug =
Opus 5; "अख्ख्या धंद्याची फेर-रचना सुचव" सारखं महिन्यातलं
एक महा-काम = Fable 5. तिचं bill अर्ध्यावर, दर्जा वरच (नेमकं
गणित Part 3, 3.1-3.2 त).

**CEO-चष्मा:** Dario साठी घराणं = बाजार-विभागणी (प्रत्येक
खिशाला दार) + safety-विभागणी (प्रत्येक विश्वास-पातळीला दार):
एकाच R&D तून चार products. मीरासाठी: पट्टी = तिचं खर्च-
नियंत्रण-पॅनेल.

## महाग चूक

"नेहमी सर्वात हुशार model वापरा: श्रेष्ठ तेच योग्य." दुहेरी
चूक: (1) पैसा: 5-10 पट भाव-फरक आहे: Haiku-लायक कामाला
Fable लावणं म्हणजे भाजी आणायला विमान; (2) **वेळही:** मोठी
models खोल विचारतात = हळू: चपळ-कामांना (chat, वर्गीकरण,
UI-प्रतिसाद) मोठं model हा अनुभवही बिघडवतो. उलट चूकही
खरी: कठीण कामाला स्वस्त model = चुका = दुरुस्तीचा खर्च >
वाचवलेले पैसे (Book 6 चं सूत्र: फुकट वेग नसतो: इथे फुकट
स्वस्ताई नसते). नियम: **कामाची किंमत ठरवा, मग model:**
चूक महाग असेल तिथे वरचं; चूक स्वस्त असेल तिथे खालचं.

## स्वतः बघा (5 मिनिटं)

तुमची गेल्या आठवड्यातली Claude-कामं आठवा (5-6 निघतील).
प्रत्येकाला पट्टीवर ठेवा: "हे खरं तर कुठल्या पायरीचं काम होतं?"
बहुतेकांचं उत्तर 'मी वापरलं त्यापेक्षा खालचं' निघेल: तोच तुमचा
वाचवता-येणारा खर्च. एक काम निवडा आणि पुढच्या वेळी जाणीवपूर्वक
योग्य पायरीला द्या.
