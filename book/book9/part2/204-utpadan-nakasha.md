# Chapter 2.4 [SPINE]: उत्पादन-नकाशा: कुठलं दार कुणासाठी

Claude चं जग आता एक इमारत आहे: अनेक दारं, प्रत्येक वेगळ्या
पाहुण्यासाठी. पूर्ण नकाशा एकदाच नीट (भाव Aug 2026 चे;
भारतासाठी स्थानिक किंमती येत आहेत: 1.7):

```
दार 1: claude.ai (गप्पांचं मुख्य दार)
   Free: चव घेण्यापुरतं | Pro $20/महिना: रोजचा वापर |
   Max $100/$200: जड वापर (5x/20x मर्यादा) |
   Team $30/माणूस | Enterprise: करार-भाव
दार 2: Claude Code (builders चं दार: 1.5 चा तारा)
   रूपं: terminal (मूळ), desktop, web (claude.ai/code),
   VS Code/JetBrains extensions, mobile. किंमत: Pro/Max
   मध्येच सामील, किंवा API-मीटरने
दार 3: API / console (धंद्याचं दार)
   तुमच्या app मधून थेट यंत्राला: 2.2 ची भाव-पट्टी इथली;
   मीराच्या products चं इंजिन इथून चालतं
दार 4: जोडलेली दारं (Claude तुमच्या जगात येतो)
   Chrome-extension (browser मध्ये), Excel (पत्रकांत:
   finance-जगासाठी), mobile apps, desktop app
दार 5: घाऊक दारं (इतरांच्या मार्गांनी)
   Amazon Bedrock, Google Vertex, Microsoft Foundry:
   मोठ्या कंपन्या आपल्या cloud-करारातूनच Claude घेतात
   (1.4 ची दोन-पाठी चाल इथे विक्रीत दिसते)
```

**आणि दालनं (दारांच्या आतल्या सोयी):** **Projects/Artifacts**
(Jun 2024): काम विषयवार + घडवलेल्या वस्तू; **Memory** (Oct
2025 पासून Pro/Max): आठवण-वह्या: पण नीट समजा: **यंत्र
'शिकत' नाही; नोंदी ठेवतो** (retraining नाही, टिपणं: Book 4,
3.4 चं बाहेरचं-स्मरण); **Skills** (Oct 16, 2025): कौशल्य-पुड्या:
"आमच्या पद्धतीने invoice तपास" सारखी शिकवण file-रूपात:
Dec 2025 त **open standard** केली (MCP-चालीची पुनरावृत्ती:
पुढचा chapter); **Agent SDK** (Sep 2025): Claude Code चा
harness च library म्हणून: स्वतःचे agents बांधणाऱ्यांसाठी.

**नकाशा वाचण्याची CEO-रीत:** दारं वेगळी दिसतात, पण **व्यूह
एक** आहे: (1) **शिडी:** Free (चव) -> Pro (सवय) -> Max/Code
(व्यसन) -> API (धंदा) -> Enterprise (करार): प्रत्येक पायरी
पुढच्या पायरीची विक्री करते; (2) **सवयीचं जाळं:** Chrome-Excel-
mobile म्हणजे "तुम्ही जिथे काम करता तिथे Claude": प्रत्येक
जोडणी = switching-cost चा नवा धागा (Book 8, 2.1); (3)
**builders आधी:** नवं काही आधी builders ना (Code, SDK,
Skills): कारण builders products बांधतात, products वापरकर्ते
आणतात: platform-क्रम (Book 8, 2.2: product आधी, मैदान मग).

**मीरावर:** मीराची निवड आता स्वच्छ: (अ) स्वतःच्या रोजच्या
कामाला **Max + Claude Code** (मर्यादा-गणित Part 3 त);
(ब) गिऱ्हाईकांच्या apps ना **API** (Sonnet 5 मुख्य, 2.2 ची
पट्टी); (क) गिऱ्हाईकाला शिकवायला **claude.ai Free/Pro** (सोपं
दार आधी: तिच्या सेवेची चव तिथूनच). एक व्यक्ती, तीन दारं,
तीन कामं: नकाशा असला की गोंधळ संपतो.

**CEO-चष्मा:** Dario साठी प्रत्येक दार म्हणजे वेगळ्या जातीच्या
विश्वासाची चाचणी: consumer चा रोजचा, builder चा तांत्रिक,
enterprise चा करारबद्ध. मीरासाठी: दारांची शिडी हीच तिच्या
**स्वतःच्या** product ची शिकवणी: तिच्या app लाही Free-चव ->
सवय -> करार ही शिडी बांधता येते: नकल करण्याजोगा नमुना.

## महाग चूक

"सगळं एकाच दारातून करीन" (फक्त chat, किंवा फक्त API).
फक्त-chat वाला builder-हत्यारं (Code, Skills, SDK) न वापरता
हाताने ढकलत राहतो: निम्मा वेग; फक्त-API वाला प्रत्येक छोट्या
प्रश्नाला मीटर लावतो: महाग आणि माणसाळलेली दालनं (Projects,
Memory) मुकतो. दारं **कामानुसार** निवडायची, निष्ठेनुसार नाही.
आणि खोल चूक: नकाशा न बघताच "Claude म्हणजे chatbot"
समजणं: 2026 चा Claude ही **इमारत** आहे: chatbot हे फक्त
तिचं सर्वात जुनं दार.
