# Chapter 3.1 [SPINE]: कुठलं model कधी: 5 सेकंदांचं गणित

2.2 ची पट्टी ज्ञान होतं; आता ती **निर्णय-यंत्र** करू. कुठल्याही
कामाआधी तीन प्रश्न (5 सेकंद पुरतात):

```
प्रश्न 1: चूक झाली तर किंमत काय?
   क्षुल्लक (परत विचारीन) | मध्यम (वेळ जाईल) | महाग
   (गिऱ्हाईक/पैसा/इभ्रत जाईल)
प्रश्न 2: कामाला खोल विचार लागतो का?
   नाही (शोधणं/वर्गीकरण/साधं रूपांतर) | थोडा (रोजचं
   code/लेखन) | खूप (रचना-निर्णय, कठीण bug, व्यूह)
प्रश्न 3: किती वेळा होणार?
   एकदाच | रोज-शेकडो वेळा (इथे प्रत्येक पैसा गुणिला जातो)
```

**उत्तरांची जुळणी (मीराचा तक्ता):**

```
काम                          चूक     विचार   model
गिऱ्हाईक-पत्रांचं वर्गीकरण    क्षुल्लक  नाही    Haiku 4.5
   (रोज x 500: स्वस्ती गुणिली जाते)
रोजचं code, drafts, उत्तरं    मध्यम   थोडा    Sonnet 5
   (घोडा-काम: 80% इथेच)
कठीण bug, DB-रचना, करार-     महाग    खूप     Opus 5
   मसुदा तपास
'अख्ख्या product ची फेर-      महाग    खूप+    Fable 5
   आखणी', महिन्याची व्यूह-     लांब
   बैठक (महिन्यातून 1-2 वेळा)
```

**तीन बारकावे (इथेच खरे पैसे):** (1) **शिडीने चढा, उडी नको:**
संशय असेल तर आधी Sonnet 5 ला द्या; अडला-चुकला **तरच**
वर (उलटा क्रम: आधी महागाला देणं = 80% कामांवर 2.5x जादा
भाव विनाकारण); (2) **effort चं बटण विसरू नका:** मोठ्या
models ना "किती खोल विचार कर" सांगता येतं (API त effort:
low/medium/high...): "Opus हवा पण घाईचं आहे" अशा कामाला
Opus + कमी-effort हा मधला सौदा अस्तित्वात आहे: model-निवड
ही एकच कळ नाही; (3) **मिश्र-यंत्रणा (agents साठी सोनं):**
एका कामात दोन्ही: स्वस्त model ने 100 files **वाचून** टिपणं
काढावी (वाचन-मजुरी), महागड्याने त्या टिपणांवर **निर्णय** घ्यावा
(विचार-मजुरी): Book 4 (5.6) चे subagents हेच: मीराचा code-
review असाच चालतो: Haiku-वाचक + Opus-न्यायाधीश: खर्च
1/3, दर्जा तोच.

**मीरावर (आठवड्याचा हिशेब):** जुनी सवय: सगळं Opus: महिना
संपेपर्यंत मीटर चढलेला. नवी यंत्रणा: वर्गीकरण-यादी-शोध Haiku
(दिवसाची शेकडो कामं जवळजवळ फुकट), घोडा-काम Sonnet 5,
आठवड्याला 4-5 खरी Opus-कामं, महिन्याला 1-2 Fable-बैठका.
**bill 60% खाली, आणि गंमत: दर्जा वर**: कारण महागड्या models
ना आता फक्त त्यांच्या लायकीची कामं जातात: लक्ष विखुरत नाही.

**CEO-चष्मा:** Anthropic घराणं याचसाठी बांधते: प्रत्येक कामाला
योग्य किंमत-बिंदू मिळाला की **एकूण वापर वाढतो** (स्वस्त दारं
नवी कामं आणतात). मीरासाठी: model-निवड ही तिच्या margin ची
रोजची चौकी: सवय झाली की विचारही करावा लागत नाही.

# Chapter 3.2 [SPINE]: खर्चाचं गणित: वर्गणी, मीटर, आणि चार बचत-बटणं

**पहिला निर्णय: वर्गणी की मीटर?** नियम सोपा आहे:

```
तुम्ही स्वतः काम करता (chat, Claude Code रोज)
   -> वर्गणी (Pro $20 / Max $100-200): 'खा-तितकं-हवं'
   थाळी: जड वापराला मीटरपेक्षा खूप स्वस्त पडते
तुमचं SOFTWARE काम करतं (गिऱ्हाईकांचं app, स्वयंचलित
   यंत्रणा)
   -> API-मीटर: प्रत्येक token मोजून: कारण इथे खर्च
   गिऱ्हाईक-संख्येने वाढतो आणि तो product च्या भावात
   बांधायचा असतो (Book 4, 6.3: unit economics)
दोन्ही करता (मीरासारखे बहुतेक builders)
   -> दोन्ही: स्वतःला Max, products ना API: खिसे वेगळे
   ठेवा: नाहीतर कुठलं काम काय खातंय कळत नाही
```

(वर्गणीच्या मर्यादा आठवा: 2.6 चा limits-राग: Max = 'अमर्याद'
नव्हे: जड आठवड्यात भिंत लागू शकते: व्यवसाय-critical यंत्रणा
वर्गणीवर नका टांगू: ती API वर.)

**मीटरचं मूळ समीकरण (Book 4, 6.1 ची उजळणी एका ओळीत):**
खर्च = (आत जाणारे + बाहेर येणारे tokens) x भाव. आणि बाहेरचे
input च्या 5 पट महाग: **म्हणून यंत्राला लांबलचक उत्तरं मागणं
हीच पहिली गळती.**

**चार बचत-बटणं (API-जगात):**

```
बटण 1: cache (10%): संवादाची सुरुवात (system-सूचना, कागदपत्रं)
   न बदलता ठेवली तर परत-परत पाठवताना ती input च्या
   फक्त 10% भावात: लांब गप्पा/agents मध्ये हा फरक 3-5x
   पर्यंत. शिस्त एकच: स्थिर भाग आधी, बदलता शेवटी.
बटण 2: batch (50%): 'आत्ता नको, सवडीने चालेल' अशी कामं
   (रात्रीचे reports, घाऊक वर्गीकरण) batch-रांगेत: सरळ
   अर्धा भाव. प्रश्न विचारायची सवय: 'हे खरंच आत्ताच हवंय?'
बटण 3: model-निवड (3.1): सर्वात मोठं बटण: 5-10x चा पल्ला.
बटण 4: effort/लांबी: खोल विचार फक्त गरजेला; उत्तराची
   लांबी मागणीतच आखा ('3 मुद्द्यांत सांग').
```

**आणि पाचवं, अदृश्य बटण: context-शिस्त.** Book 4 (3.3) चं
सत्य रुपयांत: संवाद जितका लांब, तितका **प्रत्येक** पुढचा प्रश्न
महाग (सगळी जुनी पानं परत-परत यंत्रासमोर जातात: cache
असूनही वाढ राहतेच). सवयी: नवं काम = नवा संवाद; लांबलेल्या
कामाचा **सारांश काढून** ताज्या संवादात पुढे; एका संवादात दहा
विषय नकोत. **स्वच्छ संवाद = स्वच्छ bill** (आणि वर दर्जाही:
गोंधळलेला context यंत्रालाही गोंधळवतो).

**मीराचा महिना (नमुना-हिशेब, गोल आकडे):** स्वतःची Max-वर्गणी
$100 (रोजचं Claude Code: थाळी वसूल); products चं API-मीटर:
गिऱ्हाईक-app चं वर्गीकरण Haiku-batch (हजारो कामं, डॉलर-दोन
डॉलर), उत्तर-मसुदे Sonnet 5 + cache (system-सूचना स्थिर
ठेवल्याने 60% input स्वस्तात), आठवडी-report रात्री batch.
एकूण: **खर्च आता भावनेने नाही, रचनेने ठरतो**: आणि प्रत्येक
गिऱ्हाईकामागचा AI-खर्च तिला माहीत असल्याने भाव ठरवणं
(margin राखणं) शक्य: हीच खरी कमाई.

**CEO-चष्मा:** Anthropic bचत-बटणं **मुद्दाम** देते (cache-batch-
घराणं): स्वस्त वापर = जास्त वापर = मोठं जाळं (1.4 चं मापाचं
गणित त्यांच्या बाजूने). मीरासाठी: बटणं दाबणारा आणि न दाबणारा
यांच्या margin मध्ये 2-4x फरक: **स्पर्धकाशी लढाई इथेच अर्धी
ठरते.**

## महाग चूक

"AI-खर्च म्हणजे 'येईल तसा': धंद्याचा natural खर्च." नाही:
**रचना-निर्णय आहे** (Book 5 चं सूत्र!). दोन builders, एकच
product, एकच गिऱ्हाईक-संख्या: एकाचा AI-खर्च दुसऱ्याच्या
चौपट: फरक फक्त बटणांचा (चुकीचं model + cache नाही +
सगळं तात्काळ + लांबलेले संवाद). आणि उलटी चूक: बचतीच्या
नादात critical कामं स्वस्त्या model ला देऊन गिऱ्हाईक गमावणं:
बचत **मार्जिनमध्ये** शोधायची, **दर्जात** नाही: बटणं क्रमाने:
आधी cache-batch-context (दर्जाला धक्का शून्य), मग model-
निवड (गणिताने), दर्जा-कपात कधीच नाही.

## नकाशावर

```
3.1  निवड: 3 प्रश्न + शिडी + मिश्र-यंत्रणा
3.2  खर्च: वर्गणी(स्वतः)/मीटर(software)/दोन्ही(builders);
     बटणं: cache 10% | batch 50% | model 5-10x | effort-
     लांबी | context-शिस्त; बचत margin त, दर्जात नाही
```

**सूत्रावर:** खर्चाची शिस्त हीसुद्धा विश्वासाचीच बाजू: गिऱ्हाईकाला
टिकाऊ भाव देता येणं (margin शाबूत म्हणून) हाही विश्वासच.
पुरवठादाराकडून स्वस्त घ्या, गिऱ्हाईकाला स्थिर द्या: मधली शिस्त
तुमची.

# Chapter 3.3 [SPINE]: Claude Code पूर्ण: मीराची रोजची यंत्रणा

Claude Code 'वापरणारे' हजारो; **पिळून काढणारे** थोडे. फरक
model चा नाही: **यंत्रणेचा** (Vend-धडा, 2.3: harness हाच फरक:
इथे तुमचा स्वतःचा harness). मीराची पूर्ण यंत्रणा, नक्कल-योग्य:

# Chapter 3.4 [SPINE]: Claude वर धंदा: solo-builder चा संधी-नकाशा

आता तीन पुस्तकांचे चष्मे एकत्र लावू: Book 4 (AI-धंद्याचे 6
थर), Book 8 (खंदक-गुपित-वाटप), आणि या पुस्तकाची कंपनी-नजर.
निकाल: **2026 च्या भारतातल्या solo-builder साठी पाच जागा**:

```
जागा 1: शेवटच्या मैलाची सेवा (सुरुवात इथून)
   काय: ठरावीक धंद्याचं ठरावीक दुखणं Claude-यंत्रणेने सोडवणं
   (class-मालकांचा हिशेब; दुकानदारांची GST-कागदं; वकिलांचे
   मसुदे). का-आत्ता: यंत्र तयार, गावात कुणी नाही (1.7).
   खंदक: गिऱ्हाईक-नाती + धंद्याची आतली समज (यंत्राची नाही!).
जागा 2: विद्येची पुडी (productized service)
   काय: जागा-1 ची सेवा साच्यात बांधून (तुमच्या skills-पुड्या
   हेच बीज: 3.3) ठरल्या भावात, ठरल्या साच्यात विकणं:
   'तासांची' सेवा 'नगांची' होते. खंदक: साचा+brand.
जागा 3: चिमुकलं SaaS (Book 4, 6.3 चा थर-5)
   काय: एका दुखण्याचं app, API-इंजिनावर (2.4 चं दार-3),
   वर्गणी-भावात. का-आत्ता: बांधणी-खर्च कोसळलाय (एकटीने
   app = आता खरं). धोका: नुसतं 'GPT-wrapper' असणं:
   खंदक हवाच: तुमचा data/नाती/धंदा-विशिष्ट खोली.
जागा 4: agent-कारागिरी (उगवती, थोड्यांचीच)
   काय: कंपन्यांच्या यंत्रणांत agents बसवून देणं (harness
   engineering ची सेवा-आवृत्ती): Book 4 Part 2 ची विद्या
   विकणं. का-आत्ता: मागणी स्फोटक, कारागीर दुर्मिळ.
जागा 5: शिकवण-सामग्री (मराठी/स्थानिक!)
   काय: तुमच्या भाषेत AI-विद्या शिकवणं (हे कपाटच त्याचा
   पुरावा: असं दुसऱ्यांसाठी). खंदक: भाषा+विश्वास+समुदाय.
```

**नकाशा वाचायचे तीन नियम:** (1) **क्रम:** 1 -> 2 -> 3 ही
शिडी आहे: सेवेने गिऱ्हाईक-समज कमवा, साच्याने margin, app
ने झोपेतली कमाई: उडी थेट 3 वर मारणारे बहुधा 'दुखणंच न
कळलेलं app' बांधतात (Book 8, 2.3: Thiel चा छोटा-बाजार-राजा
क्रम हाच); (2) **खंदक-प्रश्न प्रत्येक जागेला** (Book 8, 2.1):
"Claude तर सगळ्यांकडे आहे: माझ्याकडे असं काय जे स्पर्धकाला
नक्कल-कठीण?" उत्तर नेहमी यंत्राबाहेर: नाती, धंदा-समज, data,
भाषा, brand; (3) **वाटप आधी ठरवा** (Book 8, 2.5): पहिली
100 गिऱ्हाईकं नावानिशी कुठून: याचं उत्तर नसेल तर जागा कितीही
सुंदर असो: पैज उलटी-असमान.

**मीरावर (पूर्ण वर्तुळ):** मीरा या नकाशावर स्वतःला शोधते:
ती जागा-1 त उभी आहे (दुकानदार-हिशेब सेवा), जागा-2 कडे
सरकतेय (साचे बांधले: 3.3 च्या पुड्या), आणि तिच्या वहीत

**आता विमा: पाच कलमं (खर्च जवळजवळ शून्य, शिस्त तेवढी):**

**कलम 1: विद्या यंत्रणेत, यंत्रात नाही.** 3.3 चं बीज आता
पूर्ण: तुमची CLAUDE.md, skills, साचे, शिस्त: हे **कागद**
आहेत, model नाही: model बदलला तरी 90% यंत्रणा जगते.
जो 'एका model च्या लकबी' शिकतो तो बदलात बुडतो; जो
**पद्धत** बांधतो तो पोहतो.

**कलम 2: standard-वाटांनी बांधा.** जोडण्या MCP ने (2.5:
सामाईक भाषा: पुरवठादार-निरपेक्ष), कौशल्यं skills-रूपात (open
standard): म्हणजे तुमच्या इमारतीचे दरवाजे-खिडक्या बाजारी
मापाचे: पुरवठादार बदलला तरी चौकटी बसतात.

**कलम 3: अदलाबदल-चाचणी, वर्षातून दोनदा.** तुमच्या product
चा गाभा-प्रवाह (सर्वात महत्त्वाची 3-4 कामं) दुसऱ्या पुरवठादाराच्या
model वर **चालवून बघा** (एक दुपार पुरते: API-थर नीट बांधला
असेल तर model-नाव ही एक ओळ असते: Book 5, 2.5 ची
करार-शिस्त!). निकाल वहीत: "आज स्थलांतराला किती दिवस
लागतील?" उत्तर 'महिने' आलं तर वीण घट्ट-जास्त झालीये:
सैल करा. **विमा म्हणजे पळून जाणं नव्हे: पळता येण्याची
खात्री** (आणि गंमत: ती खात्री असली की राहण्याचा निर्णयही
शांत डोक्याने होतो).

**कलम 4: उंबरठे आधी लिहा (Book 8, 1.7 ची निर्णय-वही).**
"भाव 2x झाले तर मी काय करीन; आठवडाभर सेवा बंद तर
काय; माझ्या जागेत Anthropic स्वतः उतरली तर काय": उत्तरं
**आज**, शांतपणे: संकटात ठरवलेले निर्णय वाईट असतात (Book 8,
1.2 चा pre-mortem: इथे पुरवठादा-जोखमीवर). मीराचा कागद:
तीन उंबरठे, तीन तयार-चाली: झोप शांत.

**कलम 5: गिऱ्हाईक-नातं स्वतःकडे.** सर्वात खोल विमा: तुमच्या
गिऱ्हाईकाचा करार-विश्वास-data-संवाद **तुमच्याशी** असावा,
यंत्राशी नाही (Book 8, 2.1: नाती-खंदक). यंत्र बदललं तरी
गिऱ्हाईक विचारतो "मीरा, आता काय?": हे विचारलं जाणं हाच
धंदा. wrapper आणि धंदा यांतला अंतिम फरक इथेच: wrapper
यंत्र विकतो (यंत्र गेलं की तो गेला); धंदा **नातं + निकाल**
विकतो (यंत्र हे आतलं इंजिन: बदलण्याजोगं).

**मीरावर (कलमं जागी):** MCP-जोडण्या आधीच (2.5); गाभा-
प्रवाहाची अदलाबदल-चाचणी दिवाळी-होळीला (वहीत तारखा!);
उंबरठा-कागद लिहिलेला; आणि 400 गिऱ्हाईकांचं नातं तिच्या
नावावर. निष्कर्ष ती एका ओळीत सांगते: **"मी Claude वर
'अवलंबून' नाही; Claude ला 'वापरून' आहे: फरक विम्याचा."**

**CEO-चष्मा:** गंमत अशी: Anthropic लाही hedge-करणारे
गिऱ्हाईक **आवडतात**: कारण अडकवून ठेवलेल्यांपेक्षा राहून-
निवडलेले गिऱ्हाईक स्थिर असतात (विश्वास-धंद्याचं तर्कशास्त्र:
सूत्र!): MCP-Skills open केले त्यामागे हेही आहे (2.5). मीरासाठी:
hedge ही अविश्वासाची नव्हे, **प्रौढ भागीदारीची** खूण.
