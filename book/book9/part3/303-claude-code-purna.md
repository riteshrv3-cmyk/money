# Chapter 3.3 [SPINE]: Claude Code पूर्ण: मीराची रोजची यंत्रणा

Claude Code 'वापरणारे' हजारो; **पिळून काढणारे** थोडे. फरक
model चा नाही: **यंत्रणेचा** (Vend-धडा, 2.3: harness हाच फरक:
इथे तुमचा स्वतःचा harness). मीराची पूर्ण यंत्रणा, नक्कल-योग्य:

**खांब 1: CLAUDE.md: तुमची छोटी घटना.** प्रकल्प-folder मधली
एक file जी Claude Code प्रत्येक वेळी आपोआप वाचतो: **तुमचे
नियम** तिथे लिहा: "आमची भाषा-शैली ही; DB ला थेट हात
नाही; test आधी चालवायच्या; गिऱ्हाईक-data बाहेर नाही." ओळखा:
**हीच constitutional-AI ची युक्ती तुमच्या मापात** (2.1!): नियम
दर संवादात परत सांगण्याऐवजी एकदा लिहून यंत्रणेत: आणि यंत्र
चुकलं की नियम **तिथे** सुधारायचा (संवादात नाही): चूक एकदाच
होते. मीराची सवय: प्रत्येक फसलेल्या कामानंतर प्रश्न: "CLAUDE.md
त कुठली ओळ असती तर हे टळलं असतं?"

**खांब 2: आधी योजना, मग हात (plan-आधी-काम).** मोठ्या
कामाला थेट "कर" नको: आधी **"योजना मांड, अजून काही बदलू
नको"** (plan-mode): योजना वाचा, दुरुस्त करा, **मगच** राबवायला
सांगा. का: यंत्राचा वेग प्रचंड आहे: चुकीच्या दिशेला वेग =
चुकीचा डोंगर (Book 8, 1.3: हे एकतर्फी-दाराकडे झुकणारं काम:
हळू-खोल). छोट्या-दुतर्फी कामांना थेट: वर्गवारी तुमची (Book 8
ची दारं इथे रोज लागतात!).

**खांब 3: skills: पुड्या बांधून ठेवा.** परत-परत लागणारी विद्या
(invoice-तपासणीची तुमची रीत, report चा साचा, deploy ची
चौकट) **skill-file** मध्ये एकदा लिहा (2.4): मग "ते skill वापर"
इतकीच आज्ञा. मीराकडे 6 पुड्या: नव्या गिऱ्हाईकाचं on-boarding,
आठवडी-report, bug-तपास-शिस्त, भाव-पत्रक, backup-तपास,
'client-ला-सोपं-भाषांतर'. **तिची विद्या आता फक्त डोक्यात नाही:
यंत्रणेत आहे**: म्हणजे विकता येते, वाढवता येते (Book 4, 5.3:
process ची किंमत).

**खांब 4: समांतर हात (subagents).** मोठं काम = तुकडे =
समांतर agents: "या 40 files तपासा" हे चार agents ना वाटून:
वेळ 1/4 (Book 6 चा parallel-धडा हातात). आणि 3.1 ची मिश्र-
यंत्रणा: वाचक-agents स्वस्त, निर्णय-agent महाग.

**खांब 5: आरसा-सवय (रोज 2 मिनिटं).** दिवसाच्या शेवटी एक
प्रश्न खुद्द Claude ला: **"आज मी तुला वापरण्यात काय चुकवलं:
उद्या काय वेगळं करू?"** उत्तरं अनेकदा साधी-धारदार निघतात
("तू context मध्ये जुनं debugging ठेवून नवं काम मागितलंस";
"त्या कामाला plan-mode योग्य होता"). **यंत्राकडूनच यंत्र-वापर
शिकणं**: फुकट गुरु, घरचाच.

**या पाचांचं एकत्र फळ (मीराचा अनुभव):** एकटी असून ती
4-जणांच्या टीमचं काम काढते: पण नेमकं सांगायचं तर **ती
'काम करत' नाही; काम करणारी यंत्रणा चालवते**: नियम (खांब 1),
निर्णय-वर्गवारी (2), साठवलेली विद्या (3), समांतर हात (4),
रोजची सुधारणा (5). Book 4 च्या भाषेत: ती आता operator
नाही, **harness engineer** आहे: आणि 1.5 ची आठवण: हीच
जगातली सर्वात वेगाने वाढणारी नोकरी-विद्या आहे.

**CEO-चष्मा:** Anthropic आतून हेच जगते (70-90% code:
2.3): Claude Code ही त्यांच्या स्वतःच्या यंत्रणेची विक्री-आवृत्ती
आहे: dogfooding. मीरासाठी: तिची यंत्रणा जितकी लिखित-पक्की,
तितकी ती **model-बदलातही टिकते** (नवं model आलं तरी
CLAUDE.md, skills, शिस्त तीच राहते: विद्या यंत्रणेत असल्याने
अमर: पुढच्या chapter च्या hedge चं बीज इथेच).

## महाग चूक

"Claude Code = जादूची कांडी: सांगा आणि विसरा." दोन आठवड्यांत
भ्रमनिरास ठरलेला: यंत्र चुकतं, भरकटतं, जुनं विसरतं: आणि
'कांडी'वाले मग उलट टोकाला जातात ("निरुपयोगी आहे!").
दोन्ही चूक: हे **साधन-सहकारी** आहे: शिकवावं लागतं (खांब 1),
आखावं लागतं (2), तपासावं लागतं (5). गुंतवणुकीशिवाय फळ
नाही: पण गुंतवणूक एकदाच, फळ चक्रवाढ (यंत्रणा साचते: Book 8,
2.1 ची साचणारी विद्या: तुमचा स्वतःचा खंदक).

## स्वतः बघा (5 मिनिटं)

आज एकच खांब उभारा: तुमच्या मुख्य प्रकल्पात CLAUDE.md
(नसेल तर) उघडा आणि **पाच ओळी** लिहा: तुमचे दोन कडक
नियम, एक शैली-सूचना, एक 'कधीच करू नको', एक 'नेहमी
आधी विचार'. उद्या काम करताना फरक बघा. एका आठवड्यात
file दहा ओळींची होईल: ती वाढ = तुमची साचणारी विद्या.
